การสร้างโมเดลอย่างรอบคอบเป็นเรื่องของวินัยมากกว่าปุ่มต่าง ๆ ชิ้นส่วนที่เขียนเป็นข้อความสามารถอ่าน ตรวจทาน เปรียบเทียบทีละบรรทัด และสร้างใหม่ด้วยสคริปต์ได้ PartCraft ทำได้ทั้งสองทาง: ชิ้นส่วนใดก็เขียนเป็นสคริปต์ได้ และสคริปต์สร้างชิ้นส่วนได้

## ในแอป

ในแท็บ {{ui:พารามิเตอร์}} ภายใต้ **สคริปต์**:

- {{ui:บันทึกเป็นสคริปต์}} ดาวน์โหลดชิ้นส่วนที่เปิดอยู่เป็น `<name>.pcscript`
- {{ui:เปิดสคริปต์}} สร้างชิ้นส่วนจากไฟล์ `.pcscript` หากมีข้อผิดพลาด จะแจ้งเลขบรรทัด และจะไม่มีการแทนที่อะไร

## รูปแบบของสคริปต์

```
pcscript 1
part "Bracket"
  resolution 64

param width = 120
  note Plate width
param thick = 8
param bolt = 8.5
param margin = bolt * 1.5

sketch Plate
  on top
  point a 0, 0
  point b 120, 0
  point c 120, 60
  point d 0, 60
  line bottom a b
  line right b c
  line top c d
  line left d a
  coincident a O
  horizontal bottom
  horizontal top
  vertical left
  vertical right
  distance bottom = width
  distance left 60

extrude Base
  sketch Plate
  depth = thick

sketch HoleCentres
  on face Base end
  point h1 12, 12
  hdistance O h1 = margin
  vdistance O h1 = margin

hole Bolts
  sketch HoleCentres
  d = bolt
  through
```

กฎ:

- บรรทัดที่ชิดขอบซ้ายจะเริ่มคำสั่ง: `pcscript`, `part`, `param`, ชนิดฟีเจอร์ (`sketch`, `extrude`, `revolve`, `hole`, `lpattern`, `cpattern`, `mirror`, `fillet`, `chamfer`, `shell`, `import` และชนิดที่ใหม่กว่า) ตามด้วยชื่อ หรือ `rollback <feature>`
- บรรทัดที่เยื้องคือการตั้งค่าของคำสั่งด้านบน การตั้งค่าที่อยู่ลำพัง (`through`, `reverse`, `suppressed`) หมายถึง ใช่
- การตั้งค่าตัวเลขคือตัวเลข หรือ `=` ตามด้วยนิพจน์ ซึ่งทำให้เป็นสมการ: `depth = thick`
- ในสเกตช์: `on` ระบุระนาบ (`front`, `top`, `right`, `face Base end`, `face Revolve1 side l3`); รูปทรงเป็น `point <name> x, y`, `line <name> <point> <point>`, `circle <name> <centre> <radius>`, `arc <name> <centre> <start> <end>` (ทวนเข็มนาฬิกา) หรือ `spline <name> fit|control <points>`; ความสัมพันธ์คือชนิดและชื่อที่มันเชื่อมกัน (`O` คือจุดกำเนิด); ไดเมนชันจบด้วยค่าหรือ `= นิพจน์`
- การตั้งค่าเสริมของบรรทัดรูปทรงหรือความสัมพันธ์ใส่ไว้ในวงเล็บเหลี่ยมท้ายบรรทัด คั่นด้วย `;`: `[construction]`, `[side -1; label 5, 3]`
- `#` เริ่มคอมเมนต์ (ที่ต้นบรรทัดหรือหลังช่องว่าง) ชื่อที่มีช่องว่างให้ใส่ใน "เครื่องหมายคำพูดคู่"
- รหัสฟีเจอร์นับจาก f1 ตามลำดับที่เขียน การอ้างอิงขอบและหน้าใช้รหัสนี้ เช่น `edge f2.side:l3 f2.end [at 50, 0, 10]`
- การตั้งค่าที่รูปแบบไม่มีคำเรียกจะเขียนเป็น `json` และค่า ระบบจะอ่านกลับตามที่เขียนไว้

เมื่อบันทึกจากแอป สคริปต์จะมีการตั้งค่าทุกอย่าง จึงเปิดเป็นชิ้นส่วนเดิม โซลิด STEP ที่นำเข้าจะถูกเขียนไว้ในสคริปต์เมื่อบันทึกจากแอป และเป็นไฟล์ `.step` แยกต่างหากที่ตั้งชื่อด้วย `step-file` เมื่อใช้จากบรรทัดคำสั่ง

## เครื่องมือบรรทัดคำสั่ง

เครื่องมือนี้ทำงานบนคอมพิวเตอร์ที่มี Node.js 24 จากสำเนาซอร์ส CadCraft: `node tools/partcraft-cli/partcraft.mjs <command>` เป็นเครื่องมือสำหรับนักพัฒนา และใช้โมดูลเดียวกับแอป ชิ้นส่วนคือไฟล์ `.partcraft.json` หรือสคริปต์ `.pcscript`

| คำสั่ง | ทำอะไร |
|---|---|
| `info <part>` | ฟีเจอร์ พารามิเตอร์ แถบย้อนกลับ และปริมาตรกับขนาดของโซลิดที่สร้างแล้ว |
| `params <part>` | พารามิเตอร์และสมการทุกตัวพร้อมค่า |
| `set <part> width=150 Base.depth==thick` | ไปข้างหน้า: เปลี่ยนพารามิเตอร์ เชื่อมตัวเลข (`==` หรือนิพจน์) ตั้งค่าตัวเลขธรรมดา |
| `drive <part> Base.depth=12` | ย้อนกลับ: แก้พารามิเตอร์ที่อยู่เบื้องหลังตัวเลขที่ถูกขับเคลื่อน (`--prefer width` เลือกตัวใดตัวหนึ่ง) |
| `build <part> --out x.step` | เขียน `.step`, `.stl`, `.3mf`, `.json`, `.pcscript` หรือมาโคร (`.swb`) |
| `build <part> --table sizes.csv --out-dir sizes` | หนึ่งไฟล์ต่อหนึ่งแถวของตารางการออกแบบ |
| `variants <part> --out-dir d` หรือ `--zip f.zip` | ทุกการกำหนดค่าเป็น STEP, IFC, DWG และภาพตัวอย่าง พร้อมตารางรุ่นย่อยและรายการในไลบรารี (`--only "A,B"`, `--formats step,ifc,dwg,preview`, `--no-item`); ดู [สร้างชุดรุ่นย่อย](topic:variant-pack) |
| `script <in.pcscript> -o part.json` | สคริปต์เป็นชิ้นส่วน |
| `to-script <part> -o part.pcscript` | ชิ้นส่วนเป็นสคริปต์ |
| `rollback <part> [<feature>]`, `forward <part> [--end]` | ย้ายแถบย้อนกลับในไฟล์ |
| `check <part> [--strict]` | การตรวจสอบวินัย (ด้านล่าง) |

`build` ยังรับ `--set name=value` (ใช้เฉพาะการสร้างครั้งนี้) และ `--upto <feature>` ทุกคำสั่งรับ `--json` รหัสออก: 0 ปกติ, 1 พบปัญหา, 2 พิมพ์คำสั่งผิด สคริปต์จะไม่ถูกเขียนทับในตำแหน่งเดิม ให้ใช้ `-o` เพื่อบันทึกสำเนาที่เปลี่ยนแล้ว

## การตรวจสอบ

`check` รายงานสิ่งที่ทำให้ชิ้นส่วนแก้ไขยากในภายหลัง:

| สิ่งที่พบ | นับเป็น |
|---|---|
| สเกตช์ที่กำหนดเกิน (ความสัมพันธ์ขัดแย้งหรือซ้ำ) | ข้อผิดพลาด |
| ฟีเจอร์ที่สร้างไม่ได้ | ข้อผิดพลาด |
| พารามิเตอร์หรือสมการที่มีข้อผิดพลาด หรือพารามิเตอร์ที่อ้างอิงกันเอง | ข้อผิดพลาด |
| สเกตช์ที่กำหนดไม่ครบ พร้อมองศาอิสระ | คำเตือน |
| ตัวเลขที่พิมพ์ลงในฟีเจอร์และไดเมนชันโดยตรงซึ่งไม่มีพารามิเตอร์ควบคุม | คำเตือน |
| พารามิเตอร์ที่ไม่มีอะไรใช้ | คำเตือน |
| ฟีเจอร์ที่ถูกระงับ; แถบย้อนกลับไม่อยู่ที่ท้ายสุด | คำเตือน |

`--strict` ทำให้คำเตือนทุกรายการเป็นข้อผิดพลาด ดังนั้นสคริปต์สร้างจะปฏิเสธชิ้นส่วนที่ไม่ถูกควบคุมครบ

:::note
เอาต์พุตมาโคร `.swb` มีไว้สำหรับผู้ทำโมเดลชิ้นส่วนที่โรงงานส่วนใหญ่ใช้: เมื่อรันในโปรแกรมนั้น จะสร้างชิ้นส่วนที่นั่น ยังไม่เคยรันในโปรแกรมนั้นที่นี่ (ไม่มีบนเซิร์ฟเวอร์ของเรา) จึงถือว่ายังไม่ได้ทดสอบ
:::
