同じ工具経路でも、制御装置ごとに書き方が異なります。行番号の有無、`M6` か一時停止か、`G28` か `G53` か、`M30` か `M2` か、といった違いです。**ポスト**は、その書き方を示す短いテキストです。PartCraft の内蔵の3種のポスト（Fanuc風、GRBL、LinuxCNC）は、この形式で書かれているため、自分のポストは、そのどれかをコピーして始めることができます。

切削の前に、お使いの機械自身のシミュレーターで出力を確認し、まず素材の上の空中で実行してください。内蔵のポストは、この形式が作られる前に書いていたものとまったく同じ出力を書きます（テストでは、数百のプログラムについて出力をバイト単位で比較しています）。ただし、ここに記載の内容は、お使いの機械で検証されたものではありません。変更したポストの検証は、お客様ご自身で行う必要があります。

## 作成する

加工の**ポスト**の下で:

- 内蔵の制御装置にある{{ui:ポストを編集…}}は、**お客様自身のコピー**を開きます。お客様自身のポストにある場合は、そのポストを開きます。
- {{ui:新規ポスト…}}は、すべてのイベントを含む小さな空のポストから始まります。
- {{ui:ポストファイルをインポート…}}は、`.cpost` テキストファイルを読み込みます（エディターの**ファイルとして保存…**で得られるファイルです）。

エディターには、テキスト、読み込めるかどうかを示す行（誤りがある場合はその行）、および入力中に書き出される Gコードが表示されます。**プレビュー**では、すべてのイベントを実行する小さなサンプルプログラム、またはこのパーツ自身のプログラムを選べます。{{ui:保存}}は、ポストをパーツのファイルに保存し（最大 20 件）、それを制御装置として選択します。ポストはパーツとともに移動します。別のパーツで使うには、ファイルとして保存して、そのパーツでインポートしてください。

## ポストの例

```
post mymill
name My mill (.nc)
extension nc
line-numbers off
decimal-point no
canned-cycles no
modal motion G0 G1 G2 G3

on start
  comment Program {program}: {name}
  emit G21 G90 G17
end

on tool-change
  emit T{tool.number} M6
end

on rapid
  if moved
    emit G0~ X{x}~ Y{y}~ Z{z}~
  end
end
```

`//` で始まる行と空行は無視されます。先頭には設定が並び、その後に `on <event>` ブロックがイベントごとに1つずつあり、`end` で閉じます。省略したイベントは何も書き出しません。

| 設定 | 意味 |
|---|---|
| `post <id>` | ポストの ID: 文字、数字、`-`、`_` |
| `name <text>` | 制御装置リストに表示される名前 |
| `extension <ext>` | ファイルの拡張子: nc、ngc、tap など |
| `line-numbers 10` / `off` | すべての `emit` 行に `N10`、`N20` などを付けるか、付けないか |
| `decimal-point yes` / `no` | `10` の代わりに `10.` と書くか（コメントには小数点は付きません） |
| `canned-cycles yes` / `no` | `no` の場合、穴は、それが表す G0/G1 の移動として書き出されます |
| `modal <group> <words>` | グループの語（`modal motion G0 G1 G2 G3`）のうち、変わったときだけ書き出される語 |

## イベント

プログラムでは、次の順に実行されます: `start`。続いて各工程ごとに、`operation`、`tool-change`（工具が変わるとき）、`spindle`（速度が変わるとき）、`approach`（最初の点までの移動。最初の早送りの前）、`coolant-on`、そしてその移動が `rapid`、`feed`、`arc` として続き、各固定サイクルは `cycle-start`、穴ごとの `cycle-hole`、`cycle-end` の順に実行されます。最後に `end` です。

3軸を超える動作のためのイベントは次のとおりです（このイベントがないポストは、そのようなプログラムを拒否し、不足しているイベントの名前を表示します）:

| イベント | 実行されるタイミング | その変数 |
|---|---|---|
| `index` | 工具の向きが前の工程と異なる工程の前、および回転軸のある機械での最初の工程の前 | `rot.a`、`rot.b`、`rot.c`（移動先の位置。機械にない軸は空）、`first.x`、`first.y`、`first.z` |
| `rapid-rotary`、`feed-rotary` | 切削中に回転軸が動く工程の移動 | `x`、`y`、`z`、`rot.a`、`rot.b`、`rot.c`、`f`、`rot.moved`、`inverse`（送りを逆時間にする必要がある場合は yes）、`invf`（1/分） |
| `rotary-end` | そのような工程の後 | |
| `probe-move` | プローブが触れた時点で停止する移動 | `x`、`y`、`z`、`f`、`probe.n`（1〜4）、`probe.axis`（x、y、z）、`probe.k`（1、2、3） |
| `probe-set` | 1回のプロービングサイクルの接触の後 | `probe.kind`（`"z"`、`"x"`、`"y"`、`centre`）、`probe.action`（`set` または `measure`）、`probe.expect`、`probe.cx`、`probe.cy` |
| `thread` | 旋盤でのねじ切りの移動 | `x`、`z`、`thread.lead` |

すべてのイベントで共通: `kin`（none、a、b、ac、bc）、`rotary` と `tcp`（セットアップの機械から、yes または no）、`pivot.x`、`pivot.y`、`pivot.z`、工程の `op.tilt` と `op.turn`、旋盤では `spin.mode`（css または rpm）、`spin.css`、`spin.max`、`tool.nose`。値が空の文字の語（A 軸のない機械での `A{rot.a}` など）は、その行から省かれます。x、y、z を引用符付きの文字列として比較してください（`if probe.kind == "z"`）。引用符なしでは、移動の座標になります。

ポストの先頭に2行を追加すると、旋盤用のポストになります: `machine lathe`（X と Z のみを書き出し、フライス用のポストがねじ切りのパスを拒否するように、フライス用のパスを拒否します）、および `lathe-x diameter` または `lathe-x radius`。

各イベントは、その種類の移動の変数を、`{name}` の形式で使用できます。プログラム（`name`、`program`、`setup.axis`、`setup.origin`、`setup.coolant`）、素材（`stock.kind`、`stock.d`、`stock.sx`、`stock.sy`、`stock.sz`、`stock.minx` から `stock.maxz`）、工具（`tool.number`、`tool.desc`、`tool.kind`、`tool.d`、`tool.flutes`、`tool.fluteLen`）、工程（`op.name`、`op.type`）、`rpm`、移動の点（`x`、`y`、`z`、`f`、および軸が変わった場合に真となる `moved`）、円弧（`arc.g` は 2 または 3、`arc.i`、`arc.j`、`arc.cx`、`arc.cy`）、穴（`hole.x`、`hole.y`、`hole.z`、`hole.r`、`hole.q`、`hole.return`、`hole.first`、`cycle.kind`、`cycle.init`、`feed`）。エディターの**イベントと変数**の一覧で、どのイベントがどの変数を扱えるかを確認できます。読み取りと設定が可能な状態: `cool`、`offset`、および `at.x`、`at.y`、`at.z`、`at.f`（最後に書き出された値）。

## 文

| 文 | 動作 |
|---|---|
| `raw TEXT` | 入力どおりの行（行番号なし） |
| `comment TEXT` | `(TEXT)`。非 ASCII と括弧は取り除かれます |
| `emit WORD WORD …` | 語からなる行。空になった語は省かれ、語がなければ行は出ません |
| `word WORD …` | 作成中の行に語を追加します。素の `emit` で行を終えます |
| `if EXPR` … `else` … `end` | 条件: `a == b`、`a != b`、`not a`、`a and b`、`a or b`、`a??b`（a、そうでなければ b） |
| `for tool in tools` … `end` | プログラムが使う工具ごとに1回ずつ |
| `set NAME EXPR` | 値を記憶します（`set offset tool.number`） |
| `reset NAME …` | モーダルの語を忘れます（グループ、`Z` のようなアドレス文字、または `at.z`） |
| `do rapid X Y Z` | 点に対して `rapid` イベントを実行します |

語は、入力された文字に `{variable|filter}` の穴が付いたものです。フィルターは `upper`、`lower`、`pad:N`（ゼロ埋め）、`cut:N`（先頭の N 文字）、`safe`（コメントに安全な ASCII）、`int` です。`~` で終わる語は**モーダル**で、最後に書き出した値と異なる場合のみ書き出されます（`G1~`、`X{x}~`）。`~!` で終わる語は毎回書き出され、かつ記憶されます。変数ではない名前は、そのままの文字として扱われます（`G81`、`mist`）。数値は 0.001 mm に丸められ、末尾のゼロは書かれません。

## ポストにできないこと

ポストは、移動をどう書くかを決めるだけで、それ以上のことはできません。工具経路を変更したり、工程の順序を変えたり、円弧を分割したり、軸を追加したり、機械の移動範囲や運動学を把握したり、座標の計算（`+` はありません）をしたりすることはできません。回転軸の位置そのものは、セットアップで指定した機械から得られるもので、ポストからではありません。ポストは、その符号や文字を変えられますが、運動学は変えられません。工具寿命とサブプログラムのサイクルは作成されていません。ほかのプログラムの `.cps` 形式のポストファイルは読み込めません。これは別の、より単純な形式です。
