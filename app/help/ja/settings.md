アプリバーの歯車アイコン、または{{key:Mod+,}}で{{ui:設定}}を開きます。最初のタブである{{ui:PartCraft}}には、このアプリ固有の設定が含まれています。{{ui:全般}}には、すべてのCadCraftアプリで共有される設定（テーマ、ツールバー、パネル）が含まれています。PartCraftの設定はこのアプリにのみ存在します。ここで変更すると、このブラウザーが設定を記憶します。{{ui:PartCraftの設定をリセット}}を選ぶと、すべての設定が初期状態に戻ります。

## ビューの回転

- **左ボタン**（初期設定）：左ボタンでドラッグすると部品を回転します。右ボタンまたは中ボタンでドラッグすると、パンします。
- **中ボタン**：ホイールを押したままドラッグすると部品を回転します。中ボタンを押しながら{{key:Shift}}（または{{key:Ctrl}}、または⌘）を押すか、右ボタンでドラッグすると、パンします。左ボタンは面、エッジ、平面を選択するだけなので、少しだけ動いたクリックで部品が回転することはありません。多くのCADプログラムはこの方式で動作します。

どちらの設定でも、ホイールはポインターの位置を基準にズームします。スケッチでは、右ボタンと中ボタンは従来どおりパンします。

## スクロール：マウスホイールまたはトラックパッド

- **自動判別**（初期設定）：PartCraftはスクロールの動きを判別します。トラックパッドが送るような横方向や細かいスクロールは部品を回転させ、ホイールの1段ずつのスクロールはズームします。
- **マウスホイール**：スクロールは常にポインターに向かってズームします。
- **トラックパッド**：2本指でスワイプすると部品を回転します。{{key:Shift}}を押しながらスワイプするとパンします。ピンチでズームします。スケッチでは、2本指のスワイプでスケッチをパンします。

ピンチ操作は、どの設定でもズームします。「自動判別」がお使いのマウスやトラックパッドで正しく判別されない場合は、お使いの機器に合う方を選んでください。詳しくは[トラックパッド、タッチ、小さな画面](topic:trackpad-and-touch)を参照してください。

## スケッチ：描きながら拘束を追加

**描きながら拘束を追加**（初期設定ではオン）：点にスナップするクリックは、新しい点をその点に一致させます。曲線上でクリックすると、点はその曲線上に置かれます。ほぼ水平または垂直に描いた線は、水平または垂直になります。[拘束と寸法](topic:relations-dimensions)を参照してください。

他の形状の近くに、それと結び付けずに形状を配置したいときは、オフにしてください。ポインターは引き続き点や曲線にスナップしますが、何も結合されません。連続して描いた線は端点を共有しないため、ドラッグすると引き離されることがあります。必要な拘束は、右側のパネルから自分で追加してください。閉じたプロファイルは、端点が合えば引き続き押し出せます。

:::note
この設定が変更するのは、新しく描く際に追加される内容だけです。スケッチ内にすでにある拘束はそのまま残り、フィレットツールは引き続き接線の円弧と半径を作成します。
:::

## スケッチ：描きながら寸法を入力

**描きながら寸法を入力**（初期設定ではオン）：線、長方形、円、円弧を描いている間に数値を入力すると、ポインターの横にあるサイズ入力欄に値が入ります（{{key:Tab}}で次の入力欄に移動します）。{{key:Enter}}を押すと、入力したサイズで形状が描かれ、入力したサイズごとに駆動寸法が付きます。オフの場合、描いている間に数値を入力しても何も起こらず、形状はクリックだけで描かれます。[描きながらサイズを入力する](topic:sketch-basics#type-the-size-as-you-draw)を参照してください。

## コーナーインジケーター

3Dビューの角に表示される内容：**ViewCube**（初期設定。右上。面、エッジ、または頂点をクリックするとその方向から見られます。ドラッグすると軌道回転し、コンパスリングをドラッグするとモデルを回転します）、**軸アイコン**（左下にある小さな X、Y、Z のマーカーで、ビューに合わせて回転します。X は赤、Y は緑、Z は青）、または**なし**。スケッチ中や図面シートでは、どちらも表示されません。[ViewCube](topic:view-cube)を参照してください。

## ソルバースレッド

シミュレーションソルバーが使用できるスレッド数です。**自動**（初期設定）は、コンピューターの論理プロセッサー数より1少ない数を使用します（最大16）。そのため、スタディの計算中もページの応答性が保たれます。数値を選ぶこともできます。大規模なボクセルスタディ、座屈、時間経過に伴う応力、流れの計算は、複数のスレッドを使うと速く解けます（当社の計測では、80,000 個の立方体を4スレッドで計算すると約2倍速くなり、アイドル状態のコンピューターではさらに速くなります）。約 20,000 未知数未満のモデルは、1スレッドのままです。スレッドの開始にかかるコストが、短縮される時間より大きいためです。スレッド化した計算は、1スレッドの場合と同じ答えになります（丸め誤差の範囲内。合計の加算順序が異なるため）。各スタディの結果には、**ソルバー**の下に、**Nスレッド**または**1スレッド**と、その理由が表示されます。

スレッドを使用するには、ページが**クロスオリジン分離**されている必要があります（ブラウザーは、その場合にのみワーカー間でメモリーを共有できます）。ラボのページは該当します。そうでない場合、設定にその旨が表示され（「このページはクロスオリジン分離されていないため、ここで選んだ設定にかかわらず、ソルバーは1スレッドで動作します。」）、すべての計算は1スレッドで行われます。それ以外の動作は同じで、答えも同じです。

層流の流れスタディも、スレッドを使用します（54,000 個の流体セルを4スレッドで計算すると約2.5倍速く、答えは最後の桁まで同じです）。2次四面体ソルバーと熱伝達は1スレッドで動作します。テストに使用したコンピューターでは、スレッド化するとかえって遅くなったためです（これらのソルバーは、メモリーの速度と、分割できない処理ステップによって制限されます）。

### 独自のWebサーバー

独自のサーバーからPartCraftを実行する場合も、そのまま動作します。ソルバースレッドを使用するには、サーバーがPartCraftのページに2つのヘッダーを送信するように設定します：

```
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
```

Apache の場合は、フォルダーの `.htaccess` に設定します（mod_headers が必要です）：

```
Header set Cross-Origin-Opener-Policy "same-origin"
Header set Cross-Origin-Embedder-Policy "require-corp"
```

nginx の場合は、PartCraft を配信する `location` に設定します：

```
add_header Cross-Origin-Opener-Policy "same-origin" always;
add_header Cross-Origin-Embedder-Policy "require-corp" always;
```

ページを再読み込みすると、設定 › ソルバースレッドに、お使いのコンピューターのスレッド数を含む**自動**が表示されます。2つ目のヘッダーにより、ブラウザーは、ページが許可されていない別サイトから読み込むものをすべて拒否します。PartCraft単体ではこれで問題ありません（すべてのファイルを独自のフォルダーから読み込むためです）。
