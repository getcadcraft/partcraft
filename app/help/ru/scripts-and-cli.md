Аккуратное моделирование зависит больше от дисциплины, чем от кнопок. Деталь, записанную как текст, можно прочитать, проверить, сравнить построчно и перестроить скриптом. PartCraft работает в обе стороны: любую деталь можно записать как скрипт, и скрипт строит деталь.

## В приложении

На вкладке {{ui:Параметры}}, в разделе **Скрипт**:

- {{ui:Сохранить как скрипт}} скачивает открытую деталь как `<name>.pcscript`.
- {{ui:Открыть скрипт}} строит деталь из файла `.pcscript`. Ошибка сообщается с номером строки, и ничего не заменяется.

## Формат скрипта

```
pcscript 1
part "Bracket"
  resolution 64

param width = 120
  note Plate width
param thick = 8
param bolt = 8.5
param margin = bolt * 1.5

sketch Plate
  on top
  point a 0, 0
  point b 120, 0
  point c 120, 60
  point d 0, 60
  line bottom a b
  line right b c
  line top c d
  line left d a
  coincident a O
  horizontal bottom
  horizontal top
  vertical left
  vertical right
  distance bottom = width
  distance left 60

extrude Base
  sketch Plate
  depth = thick

sketch HoleCentres
  on face Base end
  point h1 12, 12
  hdistance O h1 = margin
  vdistance O h1 = margin

hole Bolts
  sketch HoleCentres
  d = bolt
  through
```

Правила:

- Строка у левого края начинает оператор: `pcscript`, `part`, `param`, тип операции (`sketch`, `extrude`, `revolve`, `hole`, `lpattern`, `cpattern`, `mirror`, `fillet`, `chamfer`, `shell`, `import` и более новые типы), за которым следует ее имя, или `rollback <feature>`.
- Строки с отступом — это настройки оператора выше. Настройка без значения (`through`, `reverse`, `suppressed`) означает «да».
- Числовая настройка — это число или `=` и выражение, которое задает уравнение: `depth = thick`.
- В эскизе `on` задает плоскость (`front`, `top`, `right`, `face Base end`, `face Revolve1 side l3`); геометрия задается как `point <name> x, y`, `line <name> <point> <point>`, `circle <name> <centre> <radius>`, `arc <name> <centre> <start> <end>` (против часовой стрелки) или `spline <name> fit|control <points>`; связи задаются своим типом и именами, которые они соединяют (`O` — начало координат); размер заканчивается значением или `= выражение`.
- Необязательные настройки строки геометрии или связи пишутся в квадратных скобках в конце, через `;`: `[construction]`, `[side -1; label 5, 3]`.
- `#` начинает комментарий (в начале строки или после пробела). Имена с пробелами пишутся в "двойных кавычках".
- Операции нумеруются с f1 в порядке записи. Ссылки на ребра и грани используют эти номера, например `edge f2.side:l3 f2.end [at 50, 0, 10]`.
- Настройки, для которых у формата нет слов, пишутся как `json` и значение; при чтении они возвращаются как есть.

Скрипт, сохраненный из приложения, содержит все настройки, поэтому открывается той же деталью. Импортированное тело STEP записывается внутрь скрипта из приложения, а из командной строки — как отдельный файл `.step`, имя которого задано в `step-file`.

## Инструмент командной строки

Инструмент работает на компьютере с Node.js 24, из копии исходного кода CadCraft: `node tools/partcraft-cli/partcraft.mjs <command>`. Это инструмент для разработчиков, он использует те же модули, что и приложение. Детали — это файлы `.partcraft.json` или скрипты `.pcscript`.

| Команда | Что делает |
|---|---|
| `info <part>` | Операции, параметры, линия отката, объем и размеры построенного тела |
| `params <part>` | Каждый параметр и уравнение с его значением |
| `set <part> width=150 Base.depth==thick` | Прямой ход: меняет параметры, связывает числа (`==` или выражение), задает обычные числа |
| `drive <part> Base.depth=12` | Обратный ход: находит параметр, стоящий за управляемым числом (`--prefer width` выбирает один) |
| `build <part> --out x.step` | Записывает `.step`, `.stl`, `.3mf`, `.json`, `.pcscript` или макрос (`.swb`) |
| `build <part> --table sizes.csv --out-dir sizes` | Один файл на каждую строку таблицы проектирования |
| `variants <part> --out-dir d` или `--zip f.zip` | Каждая конфигурация как STEP, IFC, DWG и превью, таблица вариантов и элемент библиотеки (`--only "A,B"`, `--formats step,ifc,dwg,preview`, `--no-item`); см. [Создание пакета вариантов](topic:variant-pack) |
| `script <in.pcscript> -o part.json` | Скрипт в деталь |
| `to-script <part> -o part.pcscript` | Деталь в скрипт |
| `rollback <part> [<feature>]`, `forward <part> [--end]` | Перемещают линию отката в файле |
| `check <part> [--strict]` | Проверка дисциплины (ниже) |

`build` также принимает `--set name=value` (только для этой сборки) и `--upto <feature>`. Каждая команда принимает `--json`. Коды выхода: 0 — все в порядке, 1 — найдена проблема, 2 — команда набрана неверно. Скрипт никогда не переписывается на месте: укажите `-o`, чтобы сохранить измененную копию.

## Проверка

`check` сообщает, что затрудняет дальнейшее изменение детали:

| Результат | Считается |
|---|---|
| Эскиз переопределен (противоречивые или повторяющиеся связи) | ошибка |
| Операция не строится | ошибка |
| Параметр или уравнение с ошибкой либо параметры, которые используют друг друга | ошибка |
| Эскиз недоопределен, с указанием его степеней свободы | предупреждение |
| Числа, введенные прямо в операции и размеры, которые не задаются никаким параметром | предупреждение |
| Параметр, который никто не использует | предупреждение |
| Подавленная операция; линия отката не в конце | предупреждение |

`--strict` превращает каждое предупреждение в ошибку, поэтому скрипт сборки может отказаться от детали, которая не полностью управляется параметрами.

:::note
Вывод макроса `.swb` предназначен для программы моделирования деталей, которую используют большинство мастерских: запущенный в ней, он строит деталь там. Здесь его не запускали в этой программе (она недоступна на наших серверах), поэтому считайте его непроверенным.
:::
