Одна и та же траектория инструмента должна записываться по-разному для разных систем управления: с номерами строк или без, `M6` или пауза, `G28` или `G53`, `M30` или `M2`. **Пост** — короткий текст, который описывает это. Три встроенных поста PartCraft (в стиле Fanuc, GRBL и LinuxCNC) записаны в этом формате, поэтому собственный пост может начинаться как копия одного из них.

Проверьте результат в симуляторе вашего станка перед резкой и сначала прогоните программу в воздухе над заготовкой. Встроенные посты записывают ровно то, что записывали до появления этого формата (тесты сравнивают их вывод побайтно на сотнях программ), но ничего здесь не проверено на вашем станке, а измененный вами пост нужно проверить самостоятельно.

## Создание поста

В Производстве, в разделе **Пост**:

- {{ui:Изменить пост…}} у встроенной системы управления открывает **вашу собственную копию** этого поста. У вашего поста он открывает сам этот пост.
- {{ui:Новый пост…}} начинает с небольшого пустого поста, в котором есть все события.
- {{ui:Импортировать файл поста…}} читает текстовый файл `.cpost` (файл, который вы получаете через **Сохранить как файл…** в редакторе).

Редактор показывает текст, строку, которая сообщает, читается ли он (и какая строка неверна), и G-code, который пост записывает по мере ввода. **Предпросмотр с** выбирает небольшую тестовую программу, которая запускает каждое событие, или программу этой детали. {{ui:Сохранить}} хранит пост в файле детали (до 20 постов) и выбирает его как систему управления. Посты переносятся вместе с деталью; чтобы использовать пост в другой детали, сохраните его как файл и импортируйте там.

## Как выглядит пост

```
post mymill
name My mill (.nc)
extension nc
line-numbers off
decimal-point no
canned-cycles no
modal motion G0 G1 G2 G3

on start
  comment Program {program}: {name}
  emit G21 G90 G17
end

on tool-change
  emit T{tool.number} M6
end

on rapid
  if moved
    emit G0~ X{x}~ Y{y}~ Z{z}~
  end
end
```

Строки, начинающиеся с `//`, и пустые строки игнорируются. Сначала идут настройки; затем по одному блоку `on <событие>` на каждое событие, закрытому `end`. Событие, которое вы не указали, ничего не записывает.

| Настройка | Значение |
|---|---|
| `post <id>` | Идентификатор поста: буквы, цифры, `-` и `_` |
| `name <text>` | Что показывает список систем управления |
| `extension <ext>` | Расширение файла: nc, ngc, tap … |
| `line-numbers 10` / `off` | `N10`, `N20` … в каждой строке `emit` или ни одного номера |
| `decimal-point yes` / `no` | `10.` вместо `10` (в комментариях точка никогда не ставится) |
| `canned-cycles yes` / `no` | `no`: отверстия записываются как перемещения G0/G1, которые они представляют |
| `modal <group> <words>` | Слова группы (`modal motion G0 G1 G2 G3`), которые записываются только при изменении |

## События

Для программы они выполняются в таком порядке: `start`; затем для каждой операции `operation`, `tool-change` (когда меняется инструмент), `spindle` (когда меняется скорость), `approach` (перемещение к первой точке, до первого быстрого хода), `coolant-on`, затем её перемещения как `rapid`, `feed` и `arc`, а каждый постоянный цикл как `cycle-start`, один `cycle-hole` на каждое отверстие и `cycle-end`; в конце `end`.

Каждое событие может использовать переменные своего вида перемещения, которые записываются как `{name}`: программа (`name`, `program`, `setup.axis`, `setup.origin`, `setup.coolant`), заготовка (`stock.kind`, `stock.d`, `stock.sx`, `stock.sy`, `stock.sz`, `stock.minx` … `stock.maxz`), инструмент (`tool.number`, `tool.desc`, `tool.kind`, `tool.d`, `tool.flutes`, `tool.fluteLen`), операция (`op.name`, `op.type`), `rpm`, точка перемещения (`x`, `y`, `z`, `f` и `moved`: true, если какая-либо ось изменилась), дуги (`arc.g` 2 или 3, `arc.i`, `arc.j`, `arc.cx`, `arc.cy`) и отверстия (`hole.x`, `hole.y`, `hole.z`, `hole.r`, `hole.q`, `hole.return`, `hole.first`, `cycle.kind`, `cycle.init`, `feed`). Список **События и переменные** в редакторе показывает, какое событие что видит. Состояние, которое можно читать и задавать: `cool`, `offset`, а также `at.x`, `at.y`, `at.z`, `at.f` (последние записанные значения).

## Операторы

| Оператор | Что делает |
|---|---|
| `raw TEXT` | Строка точно как введена (без номера строки) |
| `comment TEXT` | `(TEXT)` с удаленными символами не из ASCII и скобками |
| `emit WORD WORD …` | Строка слов; слова, которые получились пустыми, пропускаются; нет слов — нет строки |
| `word WORD …` | Добавляет слова к строке, которая строится; голый `emit` её завершает |
| `if EXPR` … `else` … `end` | Условия: `a == b`, `a != b`, `not a`, `a and b`, `a or b`, `a??b` (a, иначе b) |
| `for tool in tools` … `end` | По одному разу для каждого инструмента, который использует программа |
| `set NAME EXPR` | Запоминает значение (`set offset tool.number`) |
| `reset NAME …` | Забывает модальные слова (группу, букву адреса вроде `Z` или `at.z`) |
| `do rapid X Y Z` | Выполняет событие `rapid` для точки |

Слово — это введенный текст с «дырами» `{variable|filter}`. Фильтры: `upper`, `lower`, `pad:N` (дополнение нулями), `cut:N` (первые N символов), `safe` (ASCII, безопасный для комментария) и `int`. Слово, которое оканчивается на `~`, — **модальное**: оно записывается, только если отличается от того, что было записано последним (`G1~`, `X{x}~`). Слово, которое оканчивается на `~!`, записывается каждый раз и всё равно запоминается. Имя, которое не является переменной, — обычный текст (`G81`, `mist`). Числа округляются до 0.001 mm и записываются без завершающих нулей.

## Чего пост не может

Он решает только то, как записываются перемещения, и ничего больше. Он не может изменить траекторию инструмента, поменять порядок операций, разделить дугу, добавить ось, знать ход и кинематику вашего станка или выполнять арифметику с координатами (нет `+`). Зондирование, циклы ресурса инструмента и подпрограмм, вывод для 4-й и 5-й осей и коды токарных станков не реализованы. Файл поста `.cps` из другой программы загрузить нельзя: это другой, более простой формат.
