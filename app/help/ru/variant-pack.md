## Что вы сделаете

Передайте **все размеры детали сразу**: один файл STEP, IFC и DWG и изображение для каждой конфигурации, таблицу, которая показывает, что собой представляет каждая из них, и элемент библиотеки, который помещает все варианты на одну страницу.

Сначала нужна деталь с **конфигурациями** (см. [Конфигурации и таблицы проектирования](topic:design-tables)). Конфигурация, которая отключает операцию, например пластину с отверстиями и без них, становится отдельным вариантом.

## Шаги

1. Откройте деталь. На вкладке {{ui:Параметры}} найдите **Конфигурации**.
2. Нажмите {{ui:Набор вариантов…}}.
3. Отметьте конфигурации для сборки (все отмечены) и файлы для записи: STEP, IFC, DWG, предпросмотр и элемент библиотеки.
4. Нажмите {{ui:Создать набор}}. Строка состояния считает варианты по мере их сборки; ваша деталь не меняется.
5. Скачивается один zip-архив: `<part> variants.zip`.

## Что в архиве

| Файл | Что это |
|---|---|
| `<name>.step` | Конфигурация как твердое тело STEP. |
| `<name>.ifc` | IFC4, один элемент с построенным телом и параметрами детали как свойствами; значение — собственное для этой конфигурации. |
| `<name>.dwg` | Виды спереди, сверху, справа и изометрия как лист чертежа в натуральную величину. |
| `<name>.svg` | Изометрический линейный рисунок. |
| `variants.csv`, `variants.json` | Таблица параметров: id, имя и значение каждого параметра для каждого варианта, операции, которые он отключает, его файлы, объем и размер. |
| `<part>.item.json` | Деталь как один элемент библиотеки с вариантами (см. ниже). |
| `README.txt` | Что создано, примечания ниже и всё, что не было построено. |

Файлы называются по конфигурации. Конфигурация, которую не удалось построить (операция, которую нельзя создать с этими значениями), исключается из файлов и таблицы, перечисляется в README и в сообщении после сохранения архива; остальные все равно записываются.

## Полезно знать

- **STEP** точный, если в вашей сборке включено точное ядро. Без него STEP граненый (плоские треугольники), и README это сообщает.
- **DWG** — это лист чертежа, а не 3D-модель. Его линии берутся из сетки, поэтому криволинейное ребро состоит из множества коротких отрезков.
- **Элемент библиотеки** содержит одно тело и один контур на каждый вариант в собственных осях библиотеки: ось Z вверх, перед направлен в сторону −Y, точка вставки — в середине задней стороны внизу. План — это габаритный прямоугольник каждого варианта. Элемент ограничен 8 MB, поэтому очень тяжелый вариант становится коробкой своего размера, и README сообщает, сколько их.
- Активная конфигурация детали становится вариантом по умолчанию для элемента.
- Порты (точки подключения для труб и воздуховодов) из PartCraft не задаются.

## Разместите варианты на странице библиотеки

Загрузите `<part>.item.json` в разделе **Библиотека › Загрузка** на сайте. Выберите категорию, лицензию и строку с указанием вашего авторства, и он станет элементом библиотеки с вариантами. В BimCraft при размещении спрашивается, какой вариант, а «Замена» предлагает остальные. Страница, где посетители выбирают опции, смотрят 3D и скачивают вариант, пока что **закрытый предпросмотр для сотрудников**: она пока не открыта для публики.

## Из командной строки

```
node tools/partcraft-cli/partcraft.mjs variants plate.partcraft.json --out-dir plate-variants
node tools/partcraft-cli/partcraft.mjs variants plate.partcraft.json --only "Small,Large" --formats step,preview --zip plate.zip
```

`--only` задает конфигурации, `--formats` принимает любые из `step`, `ifc`, `dwg`, `preview`, `--no-item` исключает элемент библиотеки. Команда записывает папку, zip-архив или оба варианта и завершается с кодом 1, если какой-либо вариант не удалось построить. См. [Скрипты и командная строка](topic:scripts-and-cli).
