Генератор — это обычный скрипт ([CraftScript](topic:craftscript), Lua или Python) с несколькими строками-комментариями в начале. PartCraft читает комментарии и создает форму; ваш скрипт читает входы как уже заданные переменные.

## Заголовок

Поместите эти строки в комментарии (`%` в CraftScript, `--` в Lua, `#` в Python):

```
% @generator Теплообменник
% @input mdot: kg/s = 0.2 [0.01 .. 10] "Массовый расход"
% @input kind: = gyroid {gyroid, schwarzp, diamond} "Поверхность"
% @input solid: = true
% @input note: = "text"
```

Вход записывается как `name: unit = default`, затем при необходимости диапазон `[min .. max]` (числа лежат внутри него), список вариантов `{a, b, c}` и подпись в кавычках. Единица измерения нужна только как подпись в форме: **значение приходит в этой единице**, поэтому скрипт, которому нужна СИ, должен его пересчитать. Вызов `to_si(value, 'kg/s', 'kg/s')` также проверяет, что единица означает то, что вы думаете. Имя состоит из букв, цифр и знака подчеркивания; `body`, `sheet` и `problems` уже заняты.

## Что оставляет скрипт

| Переменная | Что |
|---|---|
| `body` | **Обязательно.** Поверхностная сетка, обычно из `[body, info] = to_body(field, h)`. Она исправляется и проверяется по окончании запуска. |
| `sheet` | Необязательно. Структура: каждое поле — число или текст, либо структура с полями `value`, `unit`, `ref` и `note`. Она становится таблицей данных. |
| `problems` | Необязательно. Массив ячеек `problems` из `mfg_check(field, 'sls', struct(), h)` или ваши собственные записи. Они передаются в проверки и в список проблем. |

## Полный небольшой пример

```
% Полый куб со стенкой.
% @generator Полый куб
% @input side: mm = 12 [4 .. 40] "Сторона"
% @input wall: mm = 1.5 [0.5 .. 5] "Стенка"
% @input h: mm = 0.5 [0.25 .. 2] "Размер вокселя"
f = field_subtract(field_box([0 0 0], [side/2 side/2 side/2]), ...
                   field_box([0 0 0], [side/2-wall side/2-wall side/2-wall]));
fb = field_bake(f, h);
[body, info] = to_body(fb, h);
chk = mfg_check(fb, 'sls', struct(), h);
problems = chk.problems;
sheet = struct();
sheet.volume = struct('value', info.volume, 'unit', 'mm3', 'ref', 'по сетке');
```

Получается закрытый куб, и проверка сообщает о его замкнутой внутренней полости как об ошибке для порошкового процесса. Задайте размер вокселя `h` не больше трети самой тонкой стенки, которую вы хотите получить: при толщине менее примерно трех вокселей стенка не будет надежной.

## Поля

`field_sphere`, `field_box`, `field_capsule`, `field_cylinder`, `field_torus`, `field_revolve` (тело вращения по профилю), `tpms` (поверхности гироида, Шварца P и алмаза, с размером ячейки и толщиной стенки, которые могут меняться по всей детали), `lattice` и `lattice_beams`, `along` (круглый канал вдоль траектории), булевы операции `field_union`, `field_intersect`, `field_subtract`, гладкое объединение `field_blend`, а также `field_offset`, `field_shell`, `field_move`, `field_rotate`, `field_scale`. `sample(f, points)` возвращает знаковое расстояние до точек (отрицательное внутри), `field_voxel` дает воксели для решателей. [Поля](topic:fields) объясняет, что это такое.

Полезно знать ограничения: стенка sheet-поверхности толще примерно четверти ячейки закрывает каналы; элемент тоньше примерно трех вокселей может сжиматься; `along` соединяет круглые конусы, поэтому быстро меняющийся радиус оставляет выпуклость (для профиля используйте `field_revolve`).

## Откройте скрипт как генератор

В рабочей области {{ui:Engineer}} нажмите {{ui:Open}} и выберите файл. Скрипт без строки `@generator` или `@input` не принимается: настраивать было бы нечего. Генератор хранится в этом браузере (не более 20), и кнопка {{ui:Remove}} удаляет его. Тело, созданное из него, содержит копию скрипта, поэтому деталь от него не зависит.

Файл может также содержать несколько генераторов: пакет JSON `{"format": "cadcraft-generators", "version": 1, "generators": [{"title": "…", "text": "…"}]}`.
