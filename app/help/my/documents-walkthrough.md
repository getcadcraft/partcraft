## ဘာတွေ လုပ်ရမလဲ

သင်သည် Ana ဖြစ်ပြီး colleague ဖြစ်သူ Ben နှင့်အတူ Riverside Clinic တွင် အလုပ်လုပ်နေသည်။ ပရောဂျက်၏ အစိတ်အပိုင်းများနှင့် assembly များသည် သင်နှစ်ယောက်စလုံး ဝင်ရောက်နိုင်သော ဖိုင်တွဲတစ်ခုတွင် ရှိသည် (shared drive၊ sync ထားသော ဖိုင်တွဲ သို့မဟုတ် cloud ဖိုင်တွဲ)။ အဆုံးတွင် ဖိုင်တစ်ခုသည် ပထမ မိတ္တူမှ revision **A** အဖြစ် ထုတ်ပြန်ပြီးသွားမည်၊ **B.1** အဖြစ် ထပ်ပြောင်းလဲမည်၊ ဘယ်သူက ဘာလုပ်သလဲ သင် မြင်ရမည်၊ နှင့် ဖိုင်ကို သင်ကိုင်ထားစဉ် Ben ဘာမြင်သလဲ သင် သိရမည်။

အရာအားလုံးကို သင့်ဖိုင်များ၏ ဘေးတွင် ရှိသော ဖျောက်ထားသည့် `.ccvault` ဖိုင်တွဲတွင် သိမ်းထားသည်- ဆာဗာ မရှိ၊ ဘာမျှ upload မလုပ်ပါ (cloud ဖိုင်တွဲသည် ခြွင်းချက်ဖြစ်ပြီး နောက်ဆုံးအဆင့်ကို ကြည့်ပါ)။ ခလုတ်နှင့် စည်းမျဉ်းအားလုံးကို တစ်နေရာတည်းတွင် ကြည့်ရန် သင့်အက်ပ်တွင် ရှိလျှင် *Documents: check out, revisions and release* အကြောင်းအရာကို ကြည့်ပါ။

## 1. ပရောဂျက် ဖိုင်တွဲ ပြင်ဆင်ခြင်း

1. ကိရိယာဘားရှိ **File** အုပ်စုတွင် {{ui:Documents…}} ကို ရွေးပါ။
2. {{ui:Choose the project folder}} ကို ရွေးပြီး ပရောဂျက်၏ အစိတ်အပိုင်းနှင့် assembly များရှိသော ဖိုင်တွဲကို ရွေးပါ။ (ပရောဂျက် ဖိုင်တွဲများသည် Studio နှင့် ဖိုင်တွဲဖွင့်နိုင်သော browser များ၊ ဥပမာ Chrome နှင့် Edge တွင် အလုပ်လုပ်သည်။ အခြား browser များတွင် panel က ထိုသို့ ပြောပါမည်။)
3. **သင်:** ဘေးရှိ {{ui:Change}} ကို ရွေးပြီး သင့်နာမည် `Ana` ကို ရိုက်ပါ (မေးလျှင် ဤကွန်ပျူတာ၏ နာမည်ကိုပါ ရိုက်ပါ)။ Panel တွင် *You: Ana on* နှင့် သင့်ကွန်ပျူတာ ပေါ်လာမည်။ သင့်နာမည်သည် သင်လုပ်သမျှ အရာတိုင်းတွင် ပါဝင်သည်။
4. {{ui:Start a vault in this folder}} ကို ရွေးပြီး ပရောဂျက်အမည် `Riverside clinic` ကို ရိုက်ပါ။ Panel တွင် *Vault started for Riverside clinic.* ဟု ပေါ်မည်။

## 2. ဖိုင်တစ်ခုကို ထိန်းချုပ်ခြင်း

1. **vault ထဲတွင် မရှိသော ဖိုင်များ** ကို ဖွင့်ပြီး `plates/Bracket.partcraft.json` ဘေးရှိ {{ui:Add}} ကို ရွေးပါ။
2. ၎င်းသည် **vault ထဲရှိ ဖိုင်များ** အောက်တွင် revision **A.1**၊ state **Work in progress** ဖြင့် ပေါ်လာမည်။ A.1 သည် ပထမ မိတ္တူဖြစ်ပြီး vault သည် revision တိုင်း၏ မိတ္တူကို သိမ်းထားသည်။

## 3. Checkout၊ ပြောင်းလဲခြင်း၊ check in

1. `plates/Bracket.partcraft.json` ဘေးရှိ {{ui:Open}} ကို ရွေးပါ။ အစိတ်အပိုင်းသည် PartCraft တွင် ဖွင့်မည်ဖြစ်ပြီး panel ပိတ်သွားသဖြင့် သင်မြင်နိုင်မည်။ Panel ကို {{ui:Documents…}} မှ ထပ်ဖွင့်ပါ။
2. Panel ကို ထပ်ဖွင့်ပြီး {{ui:Check out}} ကို ရွေးပါ။ အတန်းတွင် **Checked out to you** ဟု ပြောင်းသွားမည်။ `.ccvault/locks` တွင် lock ဖိုင်တစ်ခု ဖန်တီးခဲ့ပြီး သင် check in မလုပ်မချင်း အခြားသူက ဤဖိုင်ကို checkout လုပ်၍ မရပါ။
3. အစိတ်အပိုင်းကို ပြောင်းပါ- dimension တစ်ခုကို တည်းဖြတ်ပါ၊ အပေါက်တစ်ခု ထည့်ပါ။ ဖိုင်သည် သင့်အား checkout ပြုလုပ်ထားခြင်း မရှိလျှင် Save ကို ငြင်းပယ်ပြီး အကြောင်းကို ပြမည်ဖြစ်သည်။ Save As ကတော့ သင့်ကိုယ်ပိုင် မိတ္တူအတွက် အမြဲအလုပ်လုပ်သည်။
4. Panel ကိုဖွင့်ပြီး {{ui:Check in}} ကို ရွေးကာ ပြောင်းလဲမှုကို ရိုက်ပါ (ဥပမာ `Moved the door`)။ Panel က *checked in as A.2* ဟု ပြမည်။ ပရောဂျက် ဖိုင်တွဲရှိ ဖိုင်သည် ယခု သင်ဖွင့်ထားသော အစိတ်အပိုင်း ဖြစ်လာပြီး lock ပျောက်သွားမည်။ ပြောင်းလဲမှု မရှိဘဲ check in လုပ်ပါက revision မပြောင်းပါ။

အတွေးပြောင်းသွားလျှင် {{ui:Undo check-out}} သည် revision အသစ်မရှိဘဲ ဖိုင်ကို ပြန်ပေးသည်။

## 4. သုံးသပ်ခြင်းနှင့် ထုတ်ပြန်ခြင်း

1. {{ui:Send for review}} ကို ရွေးပါ။ State သည် **For review** ဖြစ်လာပြီး ဖိုင်သည် ဖတ်ရုံသာ ဖြစ်သွားမည်။
2. အတည်မပြုမီ {{ui:Project settings}} ကို ရွေးပြီး ဘယ်သူ အတည်ပြုနိုင်သလဲ စာရင်းပြုစုပါ (တစ်ကြောင်းလျှင် နာမည်တစ်ခု၊ ဥပမာ `Ben` နှင့် `Carla`)၊ နှင့် အတည်ပြုသူသည် ရေးသားသူမဟုတ်ရမည်ဟူသော စည်းမျဉ်းကို အမှန်ခြစ်ပါ။ {{ui:Save settings}} ကို ရွေးပါ။ ယခုမှစ၍ vault ကိုယ်တိုင်က အခြားသူများကို ငြင်းပယ်မည်။
3. Ben (သို့မဟုတ် Carla) က {{ui:Approve}} ကို ရွေးပြီး အတည်ပြုသူ၏ နာမည်ကို ရိုက်ပါ။ State သည် **Released** ဖြစ်ပြီး revision သည် **A** ဖြစ်လာမည်၊ *approved by* နှင့် နာမည်ပါလာမည်။ ထုတ်ပြန်ပြီးသော ဖိုင်သည် ဖတ်ရုံသာ ဖြစ်သည်။ {{ui:Send back}} ဖြင့် အကြောင်းပြချက်နှင့်အတူ Work in progress သို့ ပြန်ပို့နိုင်သည်။

အတည်ပြုသူ၏ နာမည်သည် panel တွင် ရိုက်ထည့်သော နာမည်ဖြစ်ပြီး ဘယ်သူ လက်မှတ်ထိုးသလဲ မှတ်တမ်းသာ ဖြစ်သည်၊ အထောက်အထား မဟုတ်ပါ။

## 5. Revision အသစ်

1. ထုတ်ပြန်ပြီးသော ဖိုင်ပေါ်တွင် {{ui:New revision}} ကို ရွေးပါ။ နောက်အက္ခရာအတွက် သင် ကိုင်ထားလိုက်သည်။
2. ပြောင်းပြီး {{ui:Check in}} ကို ရွေးပါ။ Revision သည် **B.1**၊ work in progress ဖြစ်မည်။ အလားတူ ထုတ်ပြန်လျှင် **B** ဖြစ်လာမည်။ ပထမ check in မတိုင်မီ {{ui:Undo check-out}} ကို ရွေးလျှင် **A** တွင်ပင် ကျန်နေမည်။

Revision အက္ခရာများသည် A၊ B … Z၊ AA၊ AB ဖြင့် ဆက်သွားသည်။ သင့်စံနှုန်းက အက္ခရာအချို့ကို ကျော်ထားလျှင် ပရောဂျက် ဆက်တင် *Use the ASME Y14.35 sequence* ကို ဖွင့်ပါက နောက်ဆက်တွဲ revision များတွင် I၊ O၊ Q၊ S၊ X နှင့် Z ကို ကျော်မည်။

## 6. ဘာတွေ ဖြစ်ခဲ့သလဲ ကြည့်ခြင်း

ဖိုင်၏ နာမည်ကို ရွေးပြီး အသေးစိတ်ကို ဖွင့်ပါ-

- **{{ui:History}}**: ဖြစ်ရပ်အားလုံး၊ အသစ်ဆုံးကို အပေါ်ဆုံးတွင်ပြပြီး ဘယ်သူ၊ ဘယ်ကွန်ပျူတာနှင့် ဘယ်အချိန် ဆိုသည်ကိုပါ ပြသည်- Ana မှ *Checked in A.2*၊ Ben မှ *Released* စသည်ဖြင့်။
- **{{ui:Revisions}}**: revision ဇယား- သိမ်းထားသော revision အားလုံး၊ ရက်စွဲ၊ check in လုပ်သူ၊ မှတ်ချက်နှင့် အတည်ပြုသူ။ Vault သည် မိတ္တူတစ်ခုစီကို `.ccvault/revs` တွင် သိမ်းထားသည်။
- **{{ui:Uses}}**: assembly ၏ အစိတ်အပိုင်းများ။
- **{{ui:Used by}}**: ဤအစိတ်အပိုင်းကို ပါဝင်သော vault ထဲရှိ assembly အားလုံးကို စာရင်းပြသည်- bracket ကို ပြောင်းလျှင် မည်သည့် assembly များကို စစ်ရမည်ကို သိရမည်။

## Assembly များ- ၎င်းတို့ အသုံးပြုသည်များနှင့် ပစ္စည်းစာရင်း

Assembly (`.partcraft.json`၊ Assembly mode မှ သိမ်းထားသည်) ကို ဖိုင်တွဲတွင် ထည့်ပြီး ၎င်းကို ထည့်ပါ။ ၎င်း၏ အမည်ကို ရွေးပါ- **Uses** သည် ၎င်းပါဝင်သော အစိတ်အပိုင်းများကို၊ revision နှင့် state တို့နှင့်အတူ စာရင်းပြသည်; အစိတ်အပိုင်းပေါ်ရှိ **Used by** သည် ၎င်းကို ပါဝင်သော assembly အားလုံးကို စာရင်းပြသည်။ {{ui:Bill of materials (CSV)}} သည် အဆင့်အလိုက် အစိတ်အပိုင်းစာရင်း အပြည့်အစုံကို ပမာဏ၊ revision နှင့် state တို့ဖြင့် spreadsheet အတွက် သိမ်းသည်။ Bracket ကို ပြောင်းလျှင် **Used by** က မည်သည့် assembly များကို ကြည့်ရမည်ကို ပြောပြမည်။

## 7. သင်ဖိုင်ကိုင်ထားစဉ် Ben ဘာမြင်သလဲ

ယခု ဖိုင်ကို ထပ်မံ checkout လုပ်ပါ၊ နှင့် Ben ကို သူ့ကွန်ပျူတာတွင် တူညီသော ပရောဂျက် ဖိုင်တွဲကို ဖွင့်ပြီး panel ကို ကြည့်ရန် မေးပါ။ ဖိုင်အတန်းပေါ်တွင် သူသည် **Checked out by Ana on** သင့်ကွန်ပျူတာ **since** အချိန်ကို မြင်မည်ဖြစ်ပြီး {{ui:Check out}} ခလုတ် မရှိပါ။ သူ ကြိုးစားလျှင် vault က ငြင်းပယ်မည်- lock သည် စနစ်က နှစ်ကြိမ် မဖန်တီးနိုင်သော ဖိုင်ဖြစ်သောကြောင့် Studio တွင် ဖိုင်တွဲကို disk ပေါ်တွင် ရှိသည့်အခါ လူနှစ်ယောက်စလုံး တစ်စက္ကန့်တည်းတွင်ပင် ဖိုင်ကို ကိုင်၍ မရပါ။ (browser တွင် ဖိုင်တွဲက အကောင်းဆုံး ကြိုးစားမှုသာ ခွင့်ပြုပြီး panel က **Folder** အောက်တွင် ထိုသို့ ပြောမည်။)

Ana မရှိသဖြင့် Ben ဖိုင်ကို လိုအပ်လျှင် {{ui:Break check-out}} သည် ဖိုင်ကို လွတ်ပေးမည်။ သူသည် အကြောင်းပြချက် ရိုက်ရမည်; ၎င်းသည် မည်သူ၏ checkout ဖြစ်သည်ဆိုသည်နှင့်အတူ မှတ်တမ်းထဲ ဝင်မည်။ ပရောဂျက်တွင် admin များစာရင်း ရှိလျှင် admin များသာ ဖောက်နိုင်သည်။ Stale limit (မူလ 14 ရက်) ထက် ဟောင်းသော checkout ကို *a long time* ဟု အမှတ်အသားပြုမည်။ ဖောက်ပြီးနောက် Ana ၏ နောက်ကျသော check in ကို ငြင်းပယ်မည်- ထို့ကြောင့် သင်နှစ်ယောက် တစ်ယောက်ကို တစ်ယောက် အစားထိုး၍ မရေးနိုင်ပါ။

## 8. Cloud ဖိုင်တွဲများ

Cloud ဖိုင်တွဲသည် သင်၏ အဖွဲ့၏ cloud storage တွင် သိမ်းထားသော ပရောဂျက် ဖိုင်တွဲဖြစ်ပြီး အဖွဲ့အတွက် shared drive မလိုအပ်ပါ။ CadCraft အကောင့်ဖြင့် ဝင်ထားသော Studio တွင် panel က {{ui:Choose the project folder}} ဘေးတွင် {{ui:Open a cloud folder}} ကို ပြမည်။ ၎င်းကို ရွေးပြီး ဖိုင်တွဲကို ရွေးပါ၊ workspace / folder အဖြစ် စာရင်းပြထားသည်။ Workspace ပိုင်ရှင်က ဖိုင်တွဲကို အရင်ဖန်တီးရမည်၊ နှင့် အဖွဲ့၏ cloud storage သည် အသက်ဝင်နေရမည်။ အထက်ပါ အရာအားလုံး အလားတူ အလုပ်လုပ်သည်; ဆာဗာက lock ကို ဖန်တီးပြီး လူများကြား တင်းကျပ်သည်။ ဝင်မထားလျှင် panel က ဝင်ရန် ပြောမည်။ ပုံမှန် browser tab တွင် cloud ခလုတ် မပေးပါ; Studio ကို သုံးပါ။

## စမ်းကြည့်ရန်

အထက်ပါ အဆင့် ရှစ်ခုကို အစစ်အမှန်ဖိုင်၏ မိတ္တူဖြင့် လုပ်ကြည့်ပါ။ လူနှစ်ယောက်ပါဝင်သော အဆင့်များအတွက် အခြားလူတစ်ယောက် သို့မဟုတ် နာမည်နှစ်ခုဖြင့် window နှစ်ခု လိုအပ်သည်။ အစစ်အမှန် မျှဝေ ဖိုင်တွဲဖြင့် စမ်းလျှင် Community testing စာမျက်နှာတွင် ဤမေးခွန်းကို တိတိကျကျ မေးသော စစ်ဆေးမှု ရှိပြီး ရလဒ်များကို လက်ခံသည်။
