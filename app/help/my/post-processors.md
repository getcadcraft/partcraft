တူညီသော toolpath ကို ထိန်းချုပ်ကိရိယာ မတူညီသည်များအတွက် မတူညီစွာ ရေးရသည်: လိုင်းနံပါတ်ရှိ သို့မဟုတ် မရှိ၊ `M6` သို့မဟုတ် ရပ်ခြင်း၊ `G28` သို့မဟုတ် `G53`၊ `M30` သို့မဟုတ် `M2`။ **Post** ဆိုသည်မှာ ထိုအရာကို ပြောသော စာသား တိုတောင်းတစ်ခု ဖြစ်သည်။ PartCraft ၏ built-in post သုံးခု (Fanuc-style၊ GRBL နှင့် LinuxCNC) သည် ဤ format ဖြင့် ရေးထားသောကြောင့် သင့်ကိုယ်ပိုင် post ကို ၎င်းတို့ထဲမှ တစ်ခု၏ မိတ္တူမှ စနိုင်သည်။

ဖြတ်ခင် စက်၏ ကိုယ်ပိုင် simulator တွင် output ကို စစ်ဆေးပြီး ပထမဦးဆုံး ကုန်ကြမ်းအထက် လေထဲတွင် ရွေ့ကြည့်ပါ။ Built-in post များသည် ဤ format မရှိမီ ရေးခဲ့သည့်အတိုင်း ရေးသည် (စမ်းသပ်မှုများက ပရိုဂရမ် ရာချီပေါ်တွင် byte အလိုက် နှိုင်းယှဉ်သည်)၊ သို့သော် ဤအရာတွင် သင့်စက်ပေါ်တွင် သက်သေမပြထားပါ၊ ပြောင်းလဲထားသော post သည် သင့်အတွက် သက်သေပြရမည့်အရာ ဖြစ်သည်။

## တစ်ခု ပြုလုပ်ခြင်း

Manufacture တွင် **Post** အောက်:

- Built-in ထိန်းချုပ်ကိရိယာတစ်ခုပေါ်ရှိ {{ui:post ပြင်ရန်…}} က **သင့်ကိုယ်ပိုင် မိတ္တူ** ကို ဖွင့်သည်။ သင့်ကိုယ်ပိုင် post တစ်ခုပေါ်တွင် ၎င်းကို ဖွင့်သည်။
- {{ui:post အသစ်…}} က every event ပါသော အလွတ် post အသေးတစ်ခုမှ စတင်သည်။
- {{ui:post ဖိုင် သွင်းရန်…}} က `.cpost` စာသားဖိုင် (editor ရှိ **Save as a file…** မှ ရရှိသော ဖိုင်) ကို ဖတ်သည်။

Editor က စာသားကို ပြသည်၊ ဖတ်နိုင်သည်၊ မဖတ်နိုင်သည် (နှင့် မှားသော လိုင်း) ကို ပြောသော လိုင်းတစ်ကြောင်း၊ သင်ရိုက်နေစဉ် post ရေးသော G-code ကို ပြသည်။ **Preview with** က every event ကို run သော နမူနာ ပရိုဂရမ်ငယ် သို့မဟုတ် ဤ part ၏ ကိုယ်ပိုင် ပရိုဂရမ်ကို ရွေးသည်။ {{ui:သိမ်းရန်}} က post ကို part ၏ ဖိုင်တွင် သိမ်းသည် (post 20 အထိ) နှင့် ထိန်းချုပ်ကိရိယာအဖြစ် ရွေးသည်။ Post များသည် part နှင့်အတူ ပါလာသည်; အခြား part တွင် သုံးရန် ဖိုင်အဖြစ် သိမ်းပြီး ထိုနေရာတွင် သွင်းပါ။

## Post ၏ ပုံသဏ္ဍာန်

```
post mymill
name My mill (.nc)
extension nc
line-numbers off
decimal-point no
canned-cycles no
modal motion G0 G1 G2 G3

on start
  comment Program {program}: {name}
  emit G21 G90 G17
end

on tool-change
  emit T{tool.number} M6
end

on rapid
  if moved
    emit G0~ X{x}~ Y{y}~ Z{z}~
  end
end
```

`//` ဖြင့် စသော လိုင်းများနှင့် အလွတ်လိုင်းများကို လျစ်လျူရှုသည်။ အပေါ်ဆုံးတွင် ဆက်တင်များ ရှိသည်; ထို့နောက် event တစ်ခုစီအတွက် `on <event>` block တစ်ခုစီ၊ `end` ဖြင့် ပိတ်သည်။ သင်ချန်ထားသော event သည် ဘာမျှ မရေးပါ။

| ဆက်တင် | အဓိပ္ပာယ် |
|---|---|
| `post <id>` | Post ၏ id: အက္ခရာများ၊ ဂဏန်းများ၊ `-` နှင့် `_` |
| `name <text>` | Control စာရင်းတွင် ပြသသော အမည် |
| `extension <ext>` | ဖိုင်တိုးချဲ့မှု: nc၊ ngc၊ tap … |
| `line-numbers 10` / `off` | `emit` လိုင်းတိုင်းတွင် `N10`၊ `N20` … သို့မဟုတ် မရှိ |
| `decimal-point yes` / `no` | `10` အစား `10.` (မှတ်ချက်များတွင် အစက်မပါပါ) |
| `canned-cycles yes` / `no` | `no`: အပေါက်များကို ၎င်းတို့ကိုယ်စားပြုသော G0/G1 ရွေ့လျားမှုများအဖြစ် ရေးသည် |
| `modal <group> <words>` | Group ၏ စကားလုံးများ (`modal motion G0 G1 G2 G3`) ပြောင်းသည့်အခါမှသာ ရေးသည် |

## Events

ပရိုဂရမ်တစ်ခုအတွက် ၎င်းတို့ ဤအစီအစဉ်ဖြင့် run သည်: `start`; ထို့နောက် လုပ်ဆောင်ချက်တစ်ခုစီအတွက် `operation`၊ `tool-change` (ကိရိယာ ပြောင်းသောအခါ)၊ `spindle` (အမြန်နှုန်း ပြောင်းသောအခါ)၊ `approach` (ပထမအမှတ်သို့ တက်သော ရွေ့လျားမှု၊ ပထမ rapid မတိုင်မီ)၊ `coolant-on`၊ ထို့နောက် ၎င်း၏ ရွေ့လျားမှုများကို `rapid`၊ `feed` နှင့် `arc` အဖြစ်၊ canned cycle တစ်ခုစီကို `cycle-start`၊ အပေါက်တစ်ခုလျှင် `cycle-hole` တစ်ကြိမ်နှင့် `cycle-end`; နောက်ဆုံးတွင် `end`။

Axis သုံးခုထက် ကျော်သော အရာများအတွက် ပိုသော events (event မရှိသော post သည် ထိုပရိုဂရမ်ကို ငြင်းပယ်ပြီး ပျောက်နေသော event ကို အမည်ပေးသည်):

| Event | ဘယ်အချိန် | ၎င်း၏ variables |
|---|---|---|
| `index` | ကိရိယာဦးတည်ချက် နောက်ဆုံးတစ်ခုနှင့် မတူသော လုပ်ဆောင်ချက်မတိုင်မီ၊ rotary axes ရှိ စက်တွင် ပထမ လုပ်ဆောင်ချက်မတိုင်မီ | `rot.a`၊ `rot.b`၊ `rot.c` (သွားရမည့် နေရာများ; စက်တွင် မရှိသော axis အတွက် ဗလာ)၊ `first.x`၊ `first.y`၊ `first.z` |
| `rapid-rotary`၊ `feed-rotary` | ဖြတ်နေစဉ် rotary axes ရွေ့သော လုပ်ဆောင်ချက်၏ ရွေ့လျားမှုများ | `x`၊ `y`၊ `z`၊ `rot.a`၊ `rot.b`၊ `rot.c`၊ `f`၊ `rot.moved`၊ `inverse` (feed သည် inverse time ဖြစ်ရမည်ဆိုလျှင် yes)၊ `invf` (1/မိနစ်) |
| `rotary-end` | ထိုလုပ်ဆောင်ချက်ပြီးနောက် | |
| `probe-move` | Probe ထိလျှင် ရပ်သော ရွေ့လျားမှု | `x`၊ `y`၊ `z`၊ `f`၊ `probe.n` (1 မှ 4)၊ `probe.axis` (x၊ y သို့မဟုတ် z)၊ `probe.k` (1၊ 2 သို့မဟုတ် 3) |
| `probe-set` | Probing cycle တစ်ခု၏ ထိတွေ့မှုများပြီးနောက် | `probe.kind` (`"z"`၊ `"x"`၊ `"y"` သို့မဟုတ် `centre`)၊ `probe.action` (`set` သို့မဟုတ် `measure`)၊ `probe.expect`၊ `probe.cx`၊ `probe.cy` |
| `thread` | Lathe ပေါ်ရှိ threading ရွေ့လျားမှု | `x`၊ `z`၊ `thread.lead` |

Event တိုင်းအတွက်လည်း: `kin` (none၊ a၊ b၊ ac၊ bc)၊ `rotary` နှင့် `tcp` (yes သို့မဟုတ် no၊ Setup ရှိ စက်မှ)၊ `pivot.x`၊ `pivot.y`၊ `pivot.z`၊ လုပ်ဆောင်ချက်၏ `op.tilt` နှင့် `op.turn`၊ lathe ပေါ်တွင် `spin.mode` (css သို့မဟုတ် rpm)၊ `spin.css`၊ `spin.max` နှင့် `tool.nose`။ တန်ဖိုးဗလာဖြစ်သော စကားလုံး၊ ဥပမာ A axis မရှိသော စက်ပေါ်ရှိ `A{rot.a}` ကို လိုင်းမှ ဖယ်သည်။ x၊ y နှင့် z ကို စာသားအဖြစ် ကိုးကားပါ (`if probe.kind == "z"`): ကိုယ်ပိုင်အနေဖြင့် ၎င်းတို့သည် ရွေ့လျားမှု၏ သြဒိနိတ်များ ဖြစ်သည်။

Post ၏ထိပ်တွင် လိုင်းနှစ်ကြောင်းထပ်ထည့်လျှင် ၎င်းသည် lathe post ဖြစ်လာသည်: `machine lathe` (ထိုအခါ X နှင့် Z သာ ရေးပြီး milling လမ်းကြောင်းများကို milling post ငြင်းသကဲ့သို့ ငြင်းသည်) နှင့် `lathe-x diameter` သို့မဟုတ် `lathe-x radius`။

Event တစ်ခုစီသည် ၎င်း၏ ကိုယ်ပိုင် အမျိုးအစား ရွေ့လျားမှု၏ variables များကို `{name}` ပုံစံဖြင့် သုံးနိုင်သည်: ပရိုဂရမ် (`name`၊ `program`၊ `setup.axis`၊ `setup.origin`၊ `setup.coolant`)၊ ကုန်ကြမ်း (`stock.kind`၊ `stock.d`၊ `stock.sx`၊ `stock.sy`၊ `stock.sz`၊ `stock.minx` … `stock.maxz`)၊ ကိရိယာ (`tool.number`၊ `tool.desc`၊ `tool.kind`၊ `tool.d`၊ `tool.flutes`၊ `tool.fluteLen`)၊ လုပ်ဆောင်ချက် (`op.name`၊ `op.type`)၊ `rpm`၊ ရွေ့လျားမှု၏ အမှတ် (`x`၊ `y`၊ `z`၊ `f`၊ နှင့် `moved`: axis တစ်ခု ပြောင်းလျှင် true)၊ arcs (`arc.g` 2 သို့မဟုတ် 3၊ `arc.i`၊ `arc.j`၊ `arc.cx`၊ `arc.cy`) နှင့် အပေါက်များ (`hole.x`၊ `hole.y`၊ `hole.z`၊ `hole.r`၊ `hole.q`၊ `hole.return`၊ `hole.first`၊ `cycle.kind`၊ `cycle.init`၊ `feed`)။ Editor ၏ **Events and variables** စာရင်းက event တစ်ခုစီ မြင်သည့်အရာကို ပြသည်။ ဖတ်နိုင်ပြီး သတ်မှတ်နိုင်သော state: `cool`၊ `offset`၊ နှင့် `at.x`၊ `at.y`၊ `at.z`၊ `at.f` (နောက်ဆုံး ရေးထားသော တန်ဖိုးများ)။

## Statements

| Statement | ဘာလုပ်သလဲ |
|---|---|
| `raw TEXT` | ရိုက်ထားသည့်အတိုင်း လိုင်းတစ်ကြောင် (လိုင်းနံပါတ် မပါ) |
| `comment TEXT` | `(TEXT)` ဖြစ်ပြီး ASCII မဟုတ်သော စာလုံးများနှင့် ကွင်းများကို ဖယ်ထုတ်ထား |
| `emit WORD WORD …` | စကားလုံးများ၏ လိုင်းတစ်ကြောင်း; ဗလာဖြစ်သော စကားလုံးများကို ဖယ်သည်; စကားလုံး မရှိလျှင် လိုင်း မရှိ |
| `word WORD …` | ဆောက်နေသော လိုင်းသို့ စကားလုံးများ ထည့်; `emit` ချည်းပဲ ရိုက်လျှင် ၎င်းကို အဆုံးသတ်သည် |
| `if EXPR` … `else` … `end` | အခြေအနေများ: `a == b`၊ `a != b`၊ `not a`၊ `a and b`၊ `a or b`၊ `a??b` (a၊ မဟုတ်လျှင် b) |
| `for tool in tools` … `end` | ပရိုဂရမ်က သုံးသော ကိရိယာတစ်ခုစီအတွက် တစ်ကြိမ် |
| `set NAME EXPR` | တန်ဖိုးကို မှတ်ထား (`set offset tool.number`) |
| `reset NAME …` | Modal စကားလုံးများကို မေ့ (group၊ `Z` ကဲ့သို့ address letter၊ သို့မဟုတ် `at.z`) |
| `do rapid X Y Z` | အမှတ်တစ်ခုအတွက် `rapid` event ကို run |

စကားလုံး ဆိုသည်မှာ `{variable|filter}` အပေါက်များပါသော ရိုက်ထားသော စာသား ဖြစ်သည်။ Filters များမှာ `upper`၊ `lower`၊ `pad:N` (သုည ဖြည့်)၊ `cut:N` (ပထမ N လုံး)၊ `safe` (မှတ်ချက်အတွက် ဘေးကင်းသော ASCII) နှင့် `int`။ `~` ဖြင့် အဆုံးသတ်သော စကားလုံးသည် **modal** ဖြစ်သည်: နောက်ဆုံးရေးခဲ့သည်နှင့် ကွဲပြားမှသာ ရေးသည် (`G1~`၊ `X{x}~`)။ `~!` ဖြင့် အဆုံးသတ်သော စကားလုံးကို အမြဲရေးပြီး ဆက်မှတ်ထားသည်။ Variable မဟုတ်သော အမည်သည် ရိုးရိုး စာသား ဖြစ်သည် (`G81`၊ `mist`)။ ဂဏန်းများကို 0.001 mm အထိ ပြည့်စုံစွာ ဖြတ်ပြီး နောက်ဆုံး သုည မပါဘဲ ရေးသည်။

## Post မလုပ်နိုင်သည့်အရာများ

ဤအရာသည် ရွေ့လျားမှုများကို ဘယ်လိုရေးမည်ကို ဆုံးဖြတ်ခြင်းသာ ဖြစ်ပြီး ထိုထက်ပိုမလုပ်ပါ။ လမ်းကြောင်းကို ပြောင်းလဲခြင်း၊ လုပ်ဆောင်ချက်များကို စီခြင်း၊ arc ကို ခွဲခြင်း၊ axis ထည့်ခြင်း၊ သင့်စက်၏ travel သို့မဟုတ် kinematics ကို သိခြင်း၊ သို့မဟုတ် သြဒိနိတ်များပေါ်တွင် သင်္ချာ လုပ်ခြင်း (`+` မရှိ) ကို မလုပ်နိုင်ပါ။ Rotary အနေအထားများသည် post မှ မဟုတ်ဘဲ Setup ရှိ စက်မှ လာသည်: post က ၎င်းတို့၏ လက္ခဏာ သို့မဟုတ် အက္ခရာများကို ပြောင်းနိုင်သည်၊ kinematics ကို မပြောင်းနိုင်ပါ။ Tool-life နှင့် subprogram cycles ကို မတည်ဆောက်ရသေးပါ။ အခြား program မှ `.cps`-ပုံစံ post ဖိုင်ကို မတင်နိုင်ပါ: ဤသည်မှာ ကွဲပြားပြီး ရိုးရှင်းသော format ဖြစ်သည်။
