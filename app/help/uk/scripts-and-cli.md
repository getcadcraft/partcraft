Акуратне моделювання — це радше дисципліна, ніж кнопки. Деталь, записану як текст, можна прочитати, перевірити, порівняти рядок за рядком і відновити за допомогою скрипта. PartCraft працює в обидва боки: будь-яку деталь можна записати як скрипт, а скрипт будує деталь.

## У застосунку

На вкладці {{ui:Параметри}}, у розділі **Скрипт**:

- {{ui:Зберегти як скрипт}} завантажує відкриту деталь як `<name>.pcscript`.
- {{ui:Відкрити скрипт}} будує деталь із файлу `.pcscript`. Помилка повідомляється з номером її рядка, і нічого не замінюється.

## Формат скрипта

```
pcscript 1
part "Bracket"
  resolution 64

param width = 120
  note Plate width
param thick = 8
param bolt = 8.5
param margin = bolt * 1.5

sketch Plate
  on top
  point a 0, 0
  point b 120, 0
  point c 120, 60
  point d 0, 60
  line bottom a b
  line right b c
  line top c d
  line left d a
  coincident a O
  horizontal bottom
  horizontal top
  vertical left
  vertical right
  distance bottom = width
  distance left 60

extrude Base
  sketch Plate
  depth = thick

sketch HoleCentres
  on face Base end
  point h1 12, 12
  hdistance O h1 = margin
  vdistance O h1 = margin

hole Bolts
  sketch HoleCentres
  d = bolt
  through
```

Правила:

- Рядок біля лівого краю починає оператор: `pcscript`, `part`, `param`, тип елемента (`sketch`, `extrude`, `revolve`, `hole`, `lpattern`, `cpattern`, `mirror`, `fillet`, `chamfer`, `shell`, `import` та новіші типи), за яким іде його назва, або `rollback <feature>`.
- Рядки з відступом — це налаштування оператора вище. Налаштування без значення (`through`, `reverse`, `suppressed`) означає «так».
- Числове налаштування — це число або `=` і вираз, що утворює рівняння: `depth = thick`.
- В ескізі: `on` називає площину (`front`, `top`, `right`, `face Base end`, `face Revolve1 side l3`); геометрія — це `point <name> x, y`, `line <name> <point> <point>`, `circle <name> <centre> <radius>`, `arc <name> <centre> <start> <end>` (проти годинникової стрілки) або `spline <name> fit|control <points>`; зв'язки — це їхній тип і назви, які вони з'єднують (`O` — початок координат); розмір завершується своїм значенням або `= expression`.
- Необов'язкові налаштування рядка геометрії чи зв'язку пишуться у квадратних дужках наприкінці, розділені `;`: `[construction]`, `[side -1; label 5, 3]`.
- `#` починає коментар (на початку рядка або після пробілу). Назви з пробілами пишуться у "подвійних лапках".
- Ідентифікатори елементів нумеруються з f1 у порядку запису. На них посилаються посилання на ребра і грані, наприклад `edge f2.side:l3 f2.end [at 50, 0, 10]`.
- Налаштування, для яких формат не має слів, записуються як `json` і значення; вони зчитуються назад без змін.

Збережений із застосунку скрипт містить кожне налаштування, тож він відкривається як та сама деталь. Імпортоване тіло STEP записується всередині скрипта із застосунку, а з командного рядка — як окремий файл `.step`, названий через `step-file`.

## Інструмент командного рядка

Інструмент працює на комп'ютері з Node.js 24, з копії вихідного коду CadCraft: `node tools/partcraft-cli/partcraft.mjs <command>`. Це інструмент для розробників, і він використовує ті самі модулі, що й застосунок. Деталі — це файли `.partcraft.json` або скрипти `.pcscript`.

| Команда | Що робить |
|---|---|
| `info <part>` | Елементи, параметри, панель відкату, об'єм і розмір побудованого тіла |
| `params <part>` | Кожен параметр і рівняння з його значенням |
| `set <part> width=150 Base.depth==thick` | Уперед: змінює параметри, пов'язує числа (`==` або вираз), задає звичайні числа |
| `drive <part> Base.depth=12` | Назад: розв'язує параметр, що стоїть за керованим числом (`--prefer width` вибирає один) |
| `build <part> --out x.step` | Записує `.step`, `.stl`, `.3mf`, `.json`, `.pcscript` або макрос (`.swb`) |
| `build <part> --table sizes.csv --out-dir sizes` | Один файл на кожен рядок таблиці розмірів |
| `variants <part> --out-dir d` або `--zip f.zip` | Кожна конфігурація як STEP, IFC, DWG і попередній перегляд, таблиця варіантів та елемент бібліотеки (`--only "A,B"`, `--formats step,ifc,dwg,preview`, `--no-item`); див. [Створити пакет варіантів](topic:variant-pack) |
| `script <in.pcscript> -o part.json` | Скрипт у деталь |
| `to-script <part> -o part.pcscript` | Деталь у скрипт |
| `rollback <part> [<feature>]`, `forward <part> [--end]` | Переміщує панель відкату у файлі |
| `check <part> [--strict]` | Перевірка дисципліни (нижче) |

`build` також приймає `--set name=value` (лише для цієї побудови) та `--upto <feature>`. Кожна команда приймає `--json`. Коди виходу: 0 — усе добре, 1 — знайдено проблему, 2 — команду введено з помилкою. Скрипт ніколи не переписується на місці: вкажіть `-o`, щоб зберегти змінену копію.

## Перевірка

`check` повідомляє, що ускладнює подальші зміни деталі:

| Знахідка | Вважається |
|---|---|
| Ескіз, що надмірно визначений (суперечливі або повторювані зв'язки) | помилка |
| Елемент, який не будується | помилка |
| Параметр або рівняння з помилкою, або параметри, що посилаються один на одного | помилка |
| Ескіз, що недовизначений, з його ступенями свободи | попередження |
| Числа, введені безпосередньо в елементи та розміри, якими не керує жоден параметр | попередження |
| Параметр, який ніде не використовується | попередження |
| Пригнічений елемент; панель відкату не в кінці | попередження |

`--strict` робить кожне попередження помилкою, тож скрипт побудови може відхилити деталь, яка не повністю керується.

:::note
Вивід макроса `.swb` призначено для програми моделювання деталей, яку використовує більшість майстерень: запущений у цій програмі, він будує деталь там. Тут його в цій програмі не запускали (її немає на наших серверах), тож ставтеся до нього як до неперевіреного.
:::
