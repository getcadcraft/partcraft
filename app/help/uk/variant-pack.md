## Що ви зробите

Передайте **кожен розмір деталі одразу**: один файл STEP, IFC і DWG та зображення для кожної конфігурації, таблицю, яка показує, що є що, і елемент бібліотеки, який розміщує їх усі на одній сторінці.

Спершу потрібна деталь з **конфігураціями** (див. [Конфігурації та таблиці проєктування](topic:design-tables)). Конфігурація, яка вимикає елемент, наприклад пластину з отворами і без них, стає окремим варіантом.

## Кроки

1. Відкрийте деталь. На вкладці {{ui:Параметри}} знайдіть **Конфігурації**.
2. Натисніть {{ui:Пакет варіантів…}}.
3. Позначте конфігурації для побудови (усі позначено) і файли для запису: STEP, IFC, DWG, попередній перегляд і елемент бібліотеки.
4. Натисніть {{ui:Створити пакет}}. Рядок стану рахує варіанти, коли їх будують; ваша деталь не змінюється.
5. Завантажиться один zip-архів: `<part> variants.zip`.

## Що в zip-архіві

| Файл | Що це |
|---|---|
| `<name>.step` | Конфігурація як тверде тіло STEP. |
| `<name>.ifc` | IFC4, один елемент з побудованим тілом і параметрами деталі як властивостями; значення — власне для цієї конфігурації. |
| `<name>.dwg` | Види спереду, зверху, справа та ізометрія як аркуш креслення в повному розмірі. |
| `<name>.svg` | Ізометричне лінійне зображення. |
| `variants.csv`, `variants.json` | Таблиця параметрів: id, назва і значення кожного параметра для кожного варіанта, елементи, які він вимикає, його файли, обʼєм і розмір. |
| `<part>.item.json` | Деталь як один елемент бібліотеки з її варіантами (див. нижче). |
| `README.txt` | Що створено, примітки нижче і все, що ще не зроблено. |

Файли називаються за конфігурацією. Конфігурація, яку не вдалося побудувати (елемент, який не можна створити з цими значеннями), виключається з файлів і таблиці, перелічується в README і в повідомленні після збереження zip-архіву; інші все одно записуються.

## Корисно знати

- **STEP** точний, якщо точне ядро увімкнено у вашій збірці. Без нього STEP гранований (плоскі трикутники), і README про це повідомляє.
- **DWG** — це аркуш креслення, а не 3D-модель. Його лінії беруться з сітки, тож криволінійний край — це багато коротких ліній.
- **Елемент бібліотеки** містить одне тіло і один відбиток на кожен варіант у осях бібліотеки: вісь Z вгору, перед — до −Y, а точка вставки — посередині задньої сторони внизу. План — це прямокутник обмеження кожного варіанта. Елемент обмежено 8 MB, тож дуже важкий варіант стає коробкою свого розміру, а README вказує, скільки їх.
- Активна конфігурація деталі стає типовим варіантом елемента.
- Порти (точки з’єднання для труб і каналів) з PartCraft не задаються.

## Розмістіть варіанти на сторінці бібліотеки

Завантажте `<part>.item.json` у **Бібліотека › Вивантажити** на сайті. Оберіть його категорію, ліцензію і ваш рядок атрибуції, і він стане елементом бібліотеки з варіантами. У BimCraft під час розміщення запитується варіант, а Swap пропонує інші. Сторінка, де відвідувачі вибирають опції, бачать 3D і завантажують варіант, наразі є **попереднім переглядом для персоналу**: вона ще не відкрита для загалу.

## З командного рядка

```
node tools/partcraft-cli/partcraft.mjs variants plate.partcraft.json --out-dir plate-variants
node tools/partcraft-cli/partcraft.mjs variants plate.partcraft.json --only "Small,Large" --formats step,preview --zip plate.zip
```

`--only` називає конфігурації, `--formats` — будь-які з `step`, `ifc`, `dwg`, `preview`; `--no-item` виключає елемент бібліотеки. Записує папку, zip або обидва і завершується з кодом 1, коли варіант не вдалося побудувати. Див. [Скрипти і командний рядок](topic:scripts-and-cli).
