Одну й ту саму траєкторію інструмента треба записувати по-різному для різних систем керування: з номерами рядків або без них, `M6` або пауза, `G28` або `G53`, `M30` або `M2`. **Пост** — це короткий текст, який визначає, як саме. Три вбудовані пости PartCraft (у стилі Fanuc, GRBL та LinuxCNC) записано в цьому форматі, тож власний пост можна почати з копії одного з них.

Перевірте результат у симуляторі вашого верстата перед обробкою і спершу проженіть програму в повітрі над заготовкою. Вбудовані пости записують саме те, що записували до появи цього формату (тести порівнюють їхній вивід байт за байтом на сотнях програм), але нічого тут не перевірено на вашому верстаті, а змінений вами пост треба довести самостійно.

## Створення поста

У Виробництві, в розділі **Пост**:

- {{ui:Редагувати пост…}} для вбудованої системи керування відкриває **вашу власну копію** цього поста. Для власного поста відкривається сам цей пост.
- {{ui:Новий пост…}} починає з невеликого порожнього поста з усіма подіями.
- {{ui:Імпортувати файл поста…}} читає текстовий файл `.cpost` (файл, який ви отримуєте через **Зберегти як файл…** у редакторі).

Редактор показує текст, рядок, що повідомляє, чи його вдалося прочитати (і який рядок невірний), а також G-код, який записує пост, поки ви друкуєте. **Попередній перегляд з** вибирає невелику тестову програму, що запускає кожну подію, або власну програму цієї деталі. {{ui:Зберегти}} зберігає пост у файлі деталі (до 20 постів) і вибирає його як систему керування. Пости переміщуються разом із деталлю; щоб використати його в іншій деталі, збережіть його як файл і імпортуйте там.

## Як виглядає пост

```
post mymill
name My mill (.nc)
extension nc
line-numbers off
decimal-point no
canned-cycles no
modal motion G0 G1 G2 G3

on start
  comment Program {program}: {name}
  emit G21 G90 G17
end

on tool-change
  emit T{tool.number} M6
end

on rapid
  if moved
    emit G0~ X{x}~ Y{y}~ Z{z}~
  end
end
```

Рядки, що починаються з `//`, та порожні рядки ігноруються. Спочатку йдуть параметри; потім один блок `on <event>` для кожної події, закритий `end`. Подія, яку ви пропустите, нічого не записує.

| Параметр | Значення |
|---|---|
| `post <id>` | Ідентифікатор поста: літери, цифри, `-` і `_` |
| `name <text>` | Що показано у списку систем керування |
| `extension <ext>` | Розширення файлу: nc, ngc, tap … |
| `line-numbers 10` / `off` | `N10`, `N20` … у кожному рядку `emit` або без них |
| `decimal-point yes` / `no` | `10.` замість `10` (коментарі ніколи не містять крапки) |
| `canned-cycles yes` / `no` | `no`: отвори записуються як рухи G0/G1, які вони означають |
| `modal <group> <words>` | Слова групи (`modal motion G0 G1 G2 G3`), які записуються лише тоді, коли змінюються |

## Події

Вони виконуються в такому порядку для програми: `start`; потім для кожної операції `operation`, `tool-change` (коли змінюється інструмент), `spindle` (коли змінюється швидкість), `approach` (рух до першої точки, перед першим швидким переміщенням), `coolant-on`, а далі її рухи як `rapid`, `feed` і `arc`, а кожен усталений цикл як `cycle-start`, один `cycle-hole` на кожен отвір і `cycle-end`; наостанок `end`.

Кожна подія може використовувати змінні свого типу руху, записані як `{name}`: програма (`name`, `program`, `setup.axis`, `setup.origin`, `setup.coolant`), заготовка (`stock.kind`, `stock.d`, `stock.sx`, `stock.sy`, `stock.sz`, `stock.minx` … `stock.maxz`), інструмент (`tool.number`, `tool.desc`, `tool.kind`, `tool.d`, `tool.flutes`, `tool.fluteLen`), операція (`op.name`, `op.type`), `rpm`, точка руху (`x`, `y`, `z`, `f` і `moved`: true, коли змінилася вісь), дуги (`arc.g` 2 або 3, `arc.i`, `arc.j`, `arc.cx`, `arc.cy`) та отвори (`hole.x`, `hole.y`, `hole.z`, `hole.r`, `hole.q`, `hole.return`, `hole.first`, `cycle.kind`, `cycle.init`, `feed`). Список **Події та змінні** в редакторі показує, яку подію що бачить. Стан, який можна читати й встановлювати: `cool`, `offset`, а також `at.x`, `at.y`, `at.z`, `at.f` (останні записані значення).

## Інструкції

| Інструкція | Що робить |
|---|---|
| `raw TEXT` | Рядок саме так, як введено (без номера рядка) |
| `comment TEXT` | `(TEXT)` з вилученими не-ASCII символами та дужками |
| `emit WORD WORD …` | Рядок слів; слова, що стали порожніми, пропускаються; без слів — рядка немає |
| `word WORD …` | Додає слова до рядка, що формується; порожній `emit` завершує його |
| `if EXPR` … `else` … `end` | Умови: `a == b`, `a != b`, `not a`, `a and b`, `a or b`, `a??b` (a, інакше b) |
| `for tool in tools` … `end` | По одному разу для кожного інструмента, який використовує програма |
| `set NAME EXPR` | Запам’ятати значення (`set offset tool.number`) |
| `reset NAME …` | Забути модальні слова (групу, літеру адреси на кшталт `Z` або `at.z`) |
| `do rapid X Y Z` | Виконати подію `rapid` для точки |

Слово — це текст із отворами `{variable|filter}`. Фільтри: `upper`, `lower`, `pad:N` (доповнення нулями), `cut:N` (перші N символів), `safe` (ASCII, безпечний для коментарів) і `int`. Слово, що закінчується на `~`, є **модальним**: воно записується лише тоді, коли відрізняється від останнього записаного (`G1~`, `X{x}~`). Слово, що закінчується на `~!`, записується щоразу і також запам’ятовується. Назва, яка не є змінною, — звичайний текст (`G81`, `mist`). Числа округлюються до 0.001 mm і записуються без зайвих нулів.

## Чого пост не може

Пост визначає лише те, як записуються рухи, і нічого більше. Він не може змінити траєкторію інструмента, переставити операції, розбити дугу, додати вісь, знати ходи або кінематику вашого верстата чи виконувати арифметику з координатами (немає `+`). Зондування, цикли стійкості інструмента та підпрограм, вивід для 4-ї й 5-ї осей і коди токарного верстата не реалізовано. Файл поста `.cps` з іншої програми не можна завантажити: це інший, простіший формат.
