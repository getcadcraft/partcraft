ایک ہی ٹول پاتھ کو مختلف کنٹرولز کے لیے مختلف طریقے سے لکھنا پڑتا ہے: لائن نمبر ہوں یا نہیں، `M6` یا وقفہ، `G28` یا `G53`، `M30` یا `M2`۔ **پوسٹ** وہ مختصر متن ہے جو بتاتا ہے کہ یہ کیسے ہو۔ PartCraft کی تین بلٹ-اِن پوسٹس (Fanuc طرز، GRBL اور LinuxCNC) اسی فارمیٹ میں لکھی گئی ہیں، اس لیے آپ کی اپنی پوسٹ ان میں سے کسی کی کاپی سے شروع ہو سکتی ہے۔

کاٹنے سے پہلے اپنی مشین کے اپنے سمولیٹر میں آؤٹ پٹ جانچیں، اور پہلے اسے اسٹاک کے اوپر ہوا میں چلائیں۔ بلٹ-اِن پوسٹس وہی لکھتی ہیں جو وہ اس فارمیٹ سے پہلے لکھتی تھیں (ٹیسٹ سینکڑوں پروگراموں پر ان کے آؤٹ پٹ کو byte کے حساب سے موازنہ کرتے ہیں)، لیکن یہاں کچھ بھی آپ کی مشین پر ثابت نہیں ہوا، اور جو پوسٹ آپ بدلیں وہ آپ کی ہے، اور اسے آپ کو ثابت کرنا ہے۔

## ایک بنائیں

مینوفیکچر میں، **پوسٹ** کے تحت:

- کسی بلٹ-اِن کنٹرول پر {{ui:پوسٹ میں ترمیم کریں…}} **آپ کی اپنی کاپی** کھولتا ہے۔ آپ کی اپنی پوسٹ پر یہ وہی پوسٹ کھولتا ہے۔
- {{ui:نئی پوسٹ…}} ایک چھوٹی خالی پوسٹ شروع کرتا ہے جس میں ہر event موجود ہو۔
- {{ui:پوسٹ فائل درآمد کریں…}} ایک `.cpost` متنی فائل پڑھتا ہے (وہ فائل جو ایڈیٹر میں **Save as a file…** سے ملتی ہے)۔

ایڈیٹر متن دکھاتا ہے، ایک لائن بتاتی ہے کہ وہ پڑھی جا سکتی ہے یا نہیں (اور کون سی لائن غلط ہے)، اور وہ G-code دکھاتا ہے جو پوسٹ لکھتی ہے، جیسے جیسے آپ ٹائپ کرتے ہیں۔ **پیش منظر کے لیے** ایک چھوٹا نمونہ پروگرام منتخب ہوتا ہے جو ہر event چلاتا ہے، یا اس پرزے کا اپنا پروگرام۔ {{ui:محفوظ کریں}} پوسٹ کو پرزے کی فائل میں رکھتا ہے (20 پوسٹس تک) اور اسے کنٹرول کے طور پر منتخب کرتا ہے۔ پوسٹس پرزے کے ساتھ سفر کرتی ہیں؛ کسی اور پرزے میں استعمال کے لیے اسے فائل کے طور پر محفوظ کر کے وہاں درآمد کریں۔

## پوسٹ کیسی دکھتی ہے

```
post mymill
name My mill (.nc)
extension nc
line-numbers off
decimal-point no
canned-cycles no
modal motion G0 G1 G2 G3

on start
  comment Program {program}: {name}
  emit G21 G90 G17
end

on tool-change
  emit T{tool.number} M6
end

on rapid
  if moved
    emit G0~ X{x}~ Y{y}~ Z{z}~
  end
end
```

`//` سے شروع ہونے والی لائنیں اور خالی لائنیں نظرانداز ہوتی ہیں۔ اوپر سیٹنگز آتی ہیں؛ پھر ہر event کے لیے ایک `on <event>` بلاک، جو `end` سے بند ہو۔ جو event آپ چھوڑ دیں وہ کچھ نہیں لکھتا۔

| سیٹنگ | مطلب |
|---|---|
| `post <id>` | پوسٹ کی id: حروف، ہندسے، `-` اور `_` |
| `name <text>` | Control کی فہرست میں جو دکھتا ہے |
| `extension <ext>` | فائل کی توسیع: nc، ngc، tap … |
| `line-numbers 10` / `off` | ہر `emit` لائن پر `N10`، `N20` … یا کوئی نہیں |
| `decimal-point yes` / `no` | `10.` کے بجائے `10` (تبصروں میں کبھی نقطہ نہیں ہوتا) |
| `canned-cycles yes` / `no` | `no`: سوراخ وہ G0/G1 moves کے طور پر لکھے جاتے ہیں جن کی وہ نمائندگی کرتے ہیں |
| `modal <group> <words>` | کسی گروپ کے الفاظ (`modal motion G0 G1 G2 G3`) جو صرف بدلنے پر لکھے جاتے ہیں |

## Events

کسی پروگرام کے لیے یہ اس ترتیب میں چلتے ہیں: `start`؛ پھر ہر آپریشن کے لیے `operation`، `tool-change` (جب ٹول بدلے)، `spindle` (جب اسپیڈ بدلے)، `approach` (پہلے نقطے تک کی حرکت، پہلے rapid سے پہلے)، `coolant-on`، پھر اس کی moves `rapid`، `feed` اور `arc` کے طور پر، اور ہر canned cycle `cycle-start` کے طور پر، ہر سوراخ کے لیے ایک `cycle-hole` اور `cycle-end`؛ آخر میں `end`۔

تین محوروں سے آگے کی چیزوں کے لیے مزید events (جس event کے بغیر پوسٹ ایسا پروگرام انکار کرتی ہے اور جو event غائب ہے اس کا نام بتاتی ہے):

| Event | کب | اس کے متغیرات |
|---|---|---|
| `index` | اس آپریشن سے پہلے جس کی ٹول سمت پچھلی سے مختلف ہو، اور گھومنے والے محوروں والی مشین پر پہلے آپریشن سے پہلے | `rot.a`، `rot.b`، `rot.c` (جن پوزیشنز پر جانا ہے؛ جس محور پر مشین نہ ہو وہاں خالی)، `first.x`، `first.y`، `first.z` |
| `rapid-rotary`، `feed-rotary` | ایسے آپریشن کی moves جس کے گھومنے والے محور کاٹتے ہوئے حرکت کریں | `x`، `y`، `z`، `rot.a`، `rot.b`، `rot.c`، `f`، `rot.moved`، `inverse` (جب feed inverse time ہو تو yes)، `invf` (1/منٹ) |
| `rotary-end` | ایسے آپریشن کے بعد | |
| `probe-move` | ایک حرکت جو probe ٹرپ ہونے پر رک جائے | `x`، `y`، `z`، `f`، `probe.n` (1 تا 4)، `probe.axis` (x، y یا z)، `probe.k` (1، 2 یا 3) |
| `probe-set` | ایک probing cycle کے touches کے بعد | `probe.kind` (`"z"`، `"x"`، `"y"` یا `centre`)، `probe.action` (`set` یا `measure`)، `probe.expect`، `probe.cx`، `probe.cy` |
| `thread` | لیتھ پر threading کی حرکت | `x`، `z`، `thread.lead` |

ہر event کے لیے یہ بھی: `kin` (none، a، b، ac، bc)، `rotary` اور `tcp` (yes یا no، سیٹ اپ کی مشین سے)، `pivot.x`، `pivot.y`، `pivot.z`، آپریشن کے `op.tilt` اور `op.turn`، اور لیتھ پر `spin.mode` (css یا rpm)، `spin.css`، `spin.max` اور `tool.nose`۔ جس حرفی لفظ کی قیمت خالی ہو، جیسے کسی ایسی مشین پر `A{rot.a}` جس میں A محور نہ ہو، وہ لائن سے نکال دیا جاتا ہے۔ x، y اور z کو متن کے طور پر کوٹیشن میں موازنہ کریں (`if probe.kind == "z"`): بغیر کوٹیشن کے وہ حرکت کے کوآرڈینیٹ ہوتے ہیں۔

پوسٹ کے اوپر دو مزید لائنیں اسے لیتھ پوسٹ بناتی ہیں: `machine lathe` (تب یہ صرف X اور Z لکھتی ہے، اور milling پاتھز کو ایسے انکار کرتی ہے جیسے milling پوسٹ turning پاتھز کو) اور `lathe-x diameter` یا `lathe-x radius`۔

ہر event اپنی قسم کی حرکت کے متغیرات `{name}` کی شکل میں استعمال کر سکتا ہے: پروگرام (`name`، `program`، `setup.axis`، `setup.origin`، `setup.coolant`)، اسٹاک (`stock.kind`، `stock.d`، `stock.sx`، `stock.sy`، `stock.sz`، `stock.minx` … `stock.maxz`)، ٹول (`tool.number`، `tool.desc`، `tool.kind`، `tool.d`، `tool.flutes`، `tool.fluteLen`)، آپریشن (`op.name`، `op.type`)، `rpm`، حرکت کا نقطہ (`x`، `y`، `z`، `f`، اور `moved`: true جب کوئی محور بدلے)، قوسیں (`arc.g` 2 یا 3، `arc.i`، `arc.j`، `arc.cx`، `arc.cy`) اور سوراخ (`hole.x`، `hole.y`، `hole.z`، `hole.r`، `hole.q`، `hole.return`، `hole.first`، `cycle.kind`، `cycle.init`، `feed`)۔ ایڈیٹر کی **Events and variables** فہرست دکھاتی ہے کہ کون سا event کیا دیکھتا ہے۔ وہ حالت جسے آپ پڑھ اور مقرر کر سکتے ہیں: `cool`، `offset`، اور `at.x`، `at.y`، `at.z`، `at.f` (آخری لکھی گئی قدریں)۔

## بیانات

| بیان | یہ کیا کرتا ہے |
|---|---|
| `raw TEXT` | لائن بالکل ویسی جیسی لکھی گئی (لائن نمبر کے بغیر) |
| `comment TEXT` | `(TEXT)` جس میں غیر-ASCII اور قوسین نکال دی جاتی ہیں |
| `emit WORD WORD …` | الفاظ کی ایک لائن؛ جو الفاظ خالی نکلیں وہ چھوڑ دیے جاتے ہیں؛ کوئی لفظ نہیں تو کوئی لائن نہیں |
| `word WORD …` | بننے والی لائن میں الفاظ شامل کریں؛ ایک خالی `emit` لائن ختم کرتا ہے |
| `if EXPR` … `else` … `end` | شرائط: `a == b`، `a != b`، `not a`، `a and b`، `a or b`، `a??b` (a، ورنہ b) |
| `for tool in tools` … `end` | پروگرام کے استعمال کیے ہر ٹول کے لیے ایک بار |
| `set NAME EXPR` | قدر یاد رکھیں (`set offset tool.number`) |
| `reset NAME …` | modal الفاظ بھول جائیں (کوئی گروپ، `Z` جیسا پتہ کا حرف، یا `at.z`) |
| `do rapid X Y Z` | ایک نقطے کے لیے `rapid` event چلائیں |

لفظ ٹائپ شدہ متن ہے جس میں `{variable|filter}` خانے ہوتے ہیں۔ فلٹرز یہ ہیں: `upper`، `lower`، `pad:N` (صفر سے بھرنا)، `cut:N` (پہلے N حروف)، `safe` (تبصرے کے لیے محفوظ ASCII) اور `int`۔ جس لفظ کے آخر میں `~` ہو وہ **modal** ہے: وہ تب ہی لکھا جاتا ہے جب وہ آخری لکھی گئی قدر سے مختلف ہو (`G1~`، `X{x}~`)۔ جس لفظ کے آخر میں `~!` ہو وہ ہر بار لکھا جاتا ہے اور پھر بھی یاد رکھا جاتا ہے۔ جو نام متغیر نہ ہو وہ سادہ متن ہے (`G81`، `mist`)۔ اعداد 0.001 mm تک گول ہوتے ہیں اور آخری صفروں کے بغیر لکھے جاتے ہیں۔

## پوسٹ کیا نہیں کر سکتی

وہ صرف یہ طے کرتی ہے کہ moves کیسے لکھی جاتی ہیں، اور کچھ نہیں۔ وہ ٹول پاتھ نہیں بدل سکتی، آپریشنز کی ترتیب نہیں بدل سکتی، کوئی arc نہیں توڑ سکتی، محور شامل نہیں کر سکتی، آپ کی مشین کے سفر یا kinematics کو نہیں جانتی، یا کوآرڈینیٹس پر حساب نہیں کر سکتی (کوئی `+` نہیں ہے)۔ گھومنے والی پوزیشنز خود سیٹ اپ میں بیان کردہ مشین سے آتی ہیں، پوسٹ سے نہیں: پوسٹ ان کا نشان یا حروف بدل سکتی ہے، kinematics نہیں۔ Tool-life اور subprogram cycles ابھی نہیں بنائے گئے۔ دوسرے پروگرام کی `.cps` طرز کی پوسٹ فائل لوڈ نہیں ہو سکتی: یہ ایک مختلف، سادہ فارمیٹ ہے۔
