احتیاط سے ماڈلنگ بٹنوں سے زیادہ نظم و ضبط کی بات ہے۔ متن کی شکل میں لکھا گیا پارٹ پڑھا، جائزہ لیا، سطر بہ سطر موازنہ کیا جا سکتا ہے اور ایک اسکرپٹ سے دوبارہ بنایا جا سکتا ہے۔ PartCraft دونوں طرف کام کرتا ہے: کوئی بھی پارٹ اسکرپٹ کے طور پر لکھا جا سکتا ہے، اور ایک اسکرپٹ پارٹ بناتا ہے۔

## ایپ میں

{{ui:Parameters}} ٹیب میں، **اسکرپٹ** کے تحت:

- {{ui:Save as script}} کھلے پارٹ کو `<name>.pcscript` کے طور پر ڈاؤن لوڈ کرتا ہے۔
- {{ui:Open script}} ایک `.pcscript` فائل سے پارٹ بناتا ہے۔ غلطی اپنے سطر نمبر کے ساتھ دکھائی جاتی ہے اور کچھ بھی تبدیل نہیں ہوتا۔

## اسکرپٹ کا فارمیٹ

```
pcscript 1
part "Bracket"
  resolution 64

param width = 120
  note Plate width
param thick = 8
param bolt = 8.5
param margin = bolt * 1.5

sketch Plate
  on top
  point a 0, 0
  point b 120, 0
  point c 120, 60
  point d 0, 60
  line bottom a b
  line right b c
  line top c d
  line left d a
  coincident a O
  horizontal bottom
  horizontal top
  vertical left
  vertical right
  distance bottom = width
  distance left 60

extrude Base
  sketch Plate
  depth = thick

sketch HoleCentres
  on face Base end
  point h1 12, 12
  hdistance O h1 = margin
  vdistance O h1 = margin

hole Bolts
  sketch HoleCentres
  d = bolt
  through
```

قواعد:

- بائیں کنارے پر لگی سطر ایک بیان شروع کرتی ہے: `pcscript`، `part`، `param`، فیچر کی قسم (`sketch`، `extrude`، `revolve`، `hole`، `lpattern`، `cpattern`، `mirror`، `fillet`، `chamfer`، `shell`، `import` اور نئی اقسام) جس کے بعد اس کا نام آتا ہے، یا `rollback <feature>`۔
- انڈینٹ شدہ سطریں اوپر والے بیان کی ترتیبات ہیں۔ اکیلی ترتیب (`through`، `reverse`، `suppressed`) کا مطلب ہاں ہے۔
- عددی ترتیب ایک عدد ہے، یا `=` اور ایک اظہاریہ، جو مساوات بناتا ہے: `depth = thick`۔
- خاکے میں: `on` پلین کا نام دیتا ہے (`front`، `top`، `right`، `face Base end`، `face Revolve1 side l3`)؛ جیومیٹری `point <name> x, y`، `line <name> <point> <point>`، `circle <name> <centre> <radius>`، `arc <name> <centre> <start> <end>` (گھڑی کی مخالف سمت) یا `spline <name> fit|control <points>` ہے؛ ربط ان کی قسم اور ان ناموں سے لکھے جاتے ہیں جنہیں وہ جوڑتے ہیں (`O` مبدا ہے)؛ ڈائمینشن اپنی قدر یا `= expression` پر ختم ہوتی ہے۔
- جیومیٹری یا ربط کی سطر کی اختیاری ترتیبات آخر میں چوکور بریکٹ میں `;` سے الگ ہو کر آتی ہیں: `[construction]`، `[side -1; label 5, 3]`۔
- `#` تبصرہ شروع کرتا ہے (سطر کے آغاز پر یا خالی جگہ کے بعد)۔ خالی جگہ والے نام "ڈبل کوٹس" میں لکھے جاتے ہیں۔
- فیچر آئی ڈیز تحریر کی ترتیب میں f1 سے گنی جاتی ہیں۔ کنارے اور سطح کے حوالے انہیں استعمال کرتے ہیں، مثلاً `edge f2.side:l3 f2.end [at 50, 0, 10]`۔
- وہ ترتیبات جن کے لیے فارمیٹ میں الفاظ نہیں، `json` اور ایک قدر کے ساتھ لکھی جاتی ہیں؛ وہ جیسی ہیں ویسی ہی واپس پڑھی جاتی ہیں۔

ایپ سے محفوظ کی گئی اسکرپٹ میں ہر ترتیب شامل ہوتی ہے، اس لیے وہ وہی پارٹ کھلتی ہے۔ ایپ سے درآمد شدہ STEP ٹھوس اسکرپٹ کے اندر لکھا جاتا ہے، اور کمانڈ لائن سے `step-file` کے نام والی الگ `.step` فائل کے طور پر۔

## کمانڈ لائن ٹول

یہ ٹول Node.js 24 والے کمپیوٹر پر CadCraft سورس کی ایک کاپی سے چلتا ہے: `node tools/partcraft-cli/partcraft.mjs <command>`۔ یہ ڈیولپر ٹول ہے اور ایپ کے وہی ماڈیولز استعمال کرتا ہے۔ پارٹس `.partcraft.json` فائلیں یا `.pcscript` اسکرپٹس ہیں۔

| کمانڈ | کیا کرتی ہے |
|---|---|
| `info <part>` | فیچرز، پیرامیٹرز، رول بیک بار، بنے ہوئے ٹھوس کا حجم اور سائز |
| `params <part>` | ہر پیرامیٹر اور مساوات اپنی قدر کے ساتھ |
| `set <part> width=150 Base.depth==thick` | آگے کی سمت: پیرامیٹرز بدلیں، عددوں کو جوڑیں (`==` یا اظہاریہ)، سادہ عدد مقرر کریں |
| `drive <part> Base.depth=12` | پیچھے کی سمت: اس پیرامیٹر کو حل کریں جو کسی چلائے گئے عدد کے پیچھے ہے (`--prefer width` ایک چنتا ہے) |
| `build <part> --out x.step` | `.step`، `.stl`، `.3mf`، `.json`، `.pcscript` یا میکرو (`.swb`) لکھتا ہے |
| `build <part> --table sizes.csv --out-dir sizes` | ڈیزائن ٹیبل کی ہر قطار کے لیے ایک فائل |
| `variants <part> --out-dir d` یا `--zip f.zip` | ہر کنفیگریشن STEP، IFC، DWG اور پیش منظر، ویری اینٹس ٹیبل اور لائبریری آئٹم کے طور پر (`--only "A,B"`، `--formats step,ifc,dwg,preview`، `--no-item`)؛ دیکھیں [ویری اینٹ پیک بنائیں](topic:variant-pack) |
| `script <in.pcscript> -o part.json` | اسکرپٹ سے پارٹ |
| `to-script <part> -o part.pcscript` | پارٹ سے اسکرپٹ |
| `rollback <part> [<feature>]`، `forward <part> [--end]` | فائل میں رول بیک بار کو منتقل کریں |
| `check <part> [--strict]` | نظم و ضبط کی جانچ (نیچے) |

`build` `--set name=value` (صرف اس بلڈ کے لیے) اور `--upto <feature>` بھی لیتا ہے۔ ہر کمانڈ `--json` لیتی ہے۔ ایگزٹ کوڈز: 0 ٹھیک، 1 کوئی مسئلہ ملا، 2 کمانڈ غلط ٹائپ ہوئی۔ اسکرپٹ کبھی اپنی جگہ پر دوبارہ نہیں لکھی جاتی: تبدیل شدہ نقل محفوظ کرنے کے لیے `-o` دیں۔

## جانچ

`check` بتاتا ہے کہ کون سی چیز بعد میں پارٹ کو بدلنا مشکل بناتی ہے:

| نتیجہ | شمار |
|---|---|
| ایسا خاکہ جو حد سے زیادہ متعین ہو (متضاد یا دہرائے گئے ربط) | خرابی |
| ایسا فیچر جو نہیں بنتا | خرابی |
| غلطی والا پیرامیٹر یا مساوات، یا ایک دوسرے پر انحصار کرنے والے پیرامیٹرز | خرابی |
| ایسا خاکہ جو کم متعین ہو، اس کی آزادی کے درجات کے ساتھ | انتباہ |
| فیچرز اور ڈائمینشنز میں براہِ راست لکھے گئے عدد جنہیں کوئی پیرامیٹر نہیں چلاتا | انتباہ |
| ایسا پیرامیٹر جسے کچھ استعمال نہیں کرتا | انتباہ |
| دبایا گیا فیچر؛ رول بیک بار آخر میں نہ ہو | انتباہ |

`--strict` ہر انتباہ کو خرابی بنا دیتا ہے، تاکہ بلڈ اسکرپٹ ایسا پارٹ رد کر سکے جو مکمل طور پر چلایا نہ گیا ہو۔

:::note
`.swb` میکرو آؤٹ پٹ اس پارٹ ماڈلر کے لیے ہے جو زیادہ تر ورکشاپس استعمال کرتی ہیں: اس پروگرام کے اندر چلانے پر وہ پارٹ وہیں بناتا ہے۔ اسے یہاں اس پروگرام میں نہیں چلایا گیا (وہ ہمارے سرورز پر دستیاب نہیں)، اس لیے اسے غیر جانچا ہوا سمجھیں۔
:::
