Мұқият модельдеу батырмалардан гөрі тәртіпке көбірек байланысты. Мәтін ретінде жазылған бөлшекті оқуға, қарап шығуға, жол-жолмен салыстыруға және скриптпен қайта құруға болады. PartCraft екі бағытта да жұмыс істейді: кез келген бөлшекті скрипт ретінде жазуға болады, ал скрипт бөлшекті құрады.

## Қолданбада

{{ui:Parameters}} қойындысында, **Скрипт** астында:

- {{ui:Скрипт ретінде сақтау}} ашық бөлшекті `<name>.pcscript` ретінде жүктейді.
- {{ui:Скриптті ашу}} `.pcscript` файлынан бөлшек құрады. Қате жол нөмірімен хабарланады және ешнәрсе ауыстырылмайды.

## Скрипт форматы

```
pcscript 1
part "Bracket"
  resolution 64

param width = 120
  note Plate width
param thick = 8
param bolt = 8.5
param margin = bolt * 1.5

sketch Plate
  on top
  point a 0, 0
  point b 120, 0
  point c 120, 60
  point d 0, 60
  line bottom a b
  line right b c
  line top c d
  line left d a
  coincident a O
  horizontal bottom
  horizontal top
  vertical left
  vertical right
  distance bottom = width
  distance left 60

extrude Base
  sketch Plate
  depth = thick

sketch HoleCentres
  on face Base end
  point h1 12, 12
  hdistance O h1 = margin
  vdistance O h1 = margin

hole Bolts
  sketch HoleCentres
  d = bolt
  through
```

Ережелер:

- Сол жақ шеттегі жол мәлімдемені бастайды: `pcscript`, `part`, `param`, элемент түрі (`sketch`, `extrude`, `revolve`, `hole`, `lpattern`, `cpattern`, `mirror`, `fillet`, `chamfer`, `shell`, `import` және жаңа түрлері), одан кейін оның атауы, немесе `rollback <feature>`.
- Бос орын шегінген жолдар жоғарыдағы мәлімдеменің баптаулары болып табылады. Жеке тұрған баптау (`through`, `reverse`, `suppressed`) «иә» дегенді білдіреді.
- Сан баптауы — сан, немесе `=` және өрнек, ол теңдеу жасайды: `depth = thick`.
- Эскизде `on` жазықтықты атайды (`front`, `top`, `right`, `face Base end`, `face Revolve1 side l3`); геометрия — `point <name> x, y`, `line <name> <point> <point>`, `circle <name> <centre> <radius>`, `arc <name> <centre> <start> <end>` (сағат тіліне қарсы) немесе `spline <name> fit|control <points>`; байланыстар — олардың түрі және байланыстыратын атаулар (`O` — координаталар басы); өлшем өз мәнімен немесе `= өрнек` белгісімен аяқталады.
- Геометрия немесе байланыс жолының қосымша баптаулары жол соңында шаршы жақшада, `;` арқылы бөлініп жазылады: `[construction]`, `[side -1; label 5, 3]`.
- `#` түсініктеме бастайды (жол басында немесе бос орыннан кейін). Бос орыны бар атаулар «қос тырнақшада» жазылады.
- Элемент идентификаторлары жазылған ретпен f1-ден санала бастайды. Жиек және бет сілтемелері соларды пайдаланады, мысалы `edge f2.side:l3 f2.end [at 50, 0, 10]`.
- Пішімде сөздері жоқ баптаулар `json` және мән деп жазылады; олар дәл сол күйінде оқылады.

Қолданбадан сақталғанда скрипт әр баптауды қамтиды, сондықтан ол сол бөлшек ретінде ашылады. Импортталған STEP денесі қолданбадан скрипттің ішіне жазылады, ал пәрмен жолынан `step-file` арқылы аталған бөлек `.step` файлы ретінде жазылады.

## Пәрмен жолы құралы

Құрал Node.js 24 орнатылған компьютерде, CadCraft бастапқы кодының көшірмесінен жұмыс істейді: `node tools/partcraft-cli/partcraft.mjs <command>`. Бұл әзірлеушілік құрал, ол қолданбамен бірдей модульдерді пайдаланады. Бөлшектер — `.partcraft.json` файлдары немесе `.pcscript` скрипттері.

| Пәрмен | Не істейді |
|---|---|
| `info <part>` | Элементтер, параметрлер, кері қайтару жолағы, салынған дененің көлемі мен өлшемі |
| `params <part>` | Әр параметр мен теңдеу және олардың мәні |
| `set <part> width=150 Base.depth==thick` | Тікелей: параметрлерді өзгерту, сандарды байланыстыру (`==` немесе өрнек), жай сандарды орнату |
| `drive <part> Base.depth=12` | Кері: жетекші санның артындағы параметрді шешу (`--prefer width` бірін таңдайды) |
| `build <part> --out x.step` | `.step`, `.stl`, `.3mf`, `.json`, `.pcscript` немесе макросты (`.swb`) жазады |
| `build <part> --table sizes.csv --out-dir sizes` | Өлшем кестесінің әр жолына бір файл |
| `variants <part> --out-dir d` немесе `--zip f.zip` | Әр конфигурацияны STEP, IFC, DWG және алдын ала қарау, нұсқалар кестесі және кітапхана элементі ретінде (`--only "A,B"`, `--formats step,ifc,dwg,preview`, `--no-item`); қараңыз [Нұсқалар топтамасын жасау](topic:variant-pack) |
| `script <in.pcscript> -o part.json` | Скрипттен бөлшекке |
| `to-script <part> -o part.pcscript` | Бөлшектен скриптке |
| `rollback <part> [<feature>]`, `forward <part> [--end]` | Файлдағы кері қайтару жолағын жылжытады |
| `check <part> [--strict]` | Тәртіп тексеруі (төменде) |

`build` сонымен қатар `--set name=value` (тек осы құрастыру үшін) және `--upto <feature>` қабылдайды. Әр пәрмен `--json` қабылдайды. Шығу кодтары: 0 — жақсы, 1 — мәселе табылды, 2 — пәрмен дұрыс терілмеген. Скрипт ешқашан дәл орнында қайта жазылмайды: өзгертілген көшірмені сақтау үшін `-o` беріңіз.

## Тексеру

`check` бөлшекті кейін өзгертуді қиындататын нәрселерді хабарлайды:

| Табылған мәселе | Қалай санала ма |
|---|---|
| Артық анықталған эскиз (қарама-қайшы немесе қайталанған байланыстар) | қате |
| Құрылмайтын элемент | қате |
| Қатесі бар параметр немесе теңдеу, немесе бір-бірін пайдаланатын параметрлер | қате |
| Толық анықталмаған эскиз, оның еркіндік дәрежелерімен | ескерту |
| Ешбір параметр басқармайтын элементтер мен өлшемдерге тікелей енгізілген сандар | ескерту |
| Ешкім пайдаланбайтын параметр | ескерту |
| Өшірілген элемент; кері қайтару жолағы соңында емес | ескерту |

`--strict` әр ескертуді қатеге айналдырады, сондықтан құрастыру скрипті толық басқарылмаған бөлшекті қабылдамайды.

:::note
`.swb` макрос шығысы көптеген цехтар пайдаланатын бөлшек модельдеушіге арналған: сол бағдарламаның ішінде іске қосылса, бөлшекті сонда құрады. Ол мұнда сол бағдарламада іске қосылмаған (серверлерімізде қолжетімсіз), сондықтан оны сыналмаған деп есептеңіз.
:::
