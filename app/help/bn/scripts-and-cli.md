ভালো মডেলিং বোতামের চেয়ে শৃঙ্খলার ওপর বেশি নির্ভর করে। লেখা হিসেবে লেখা পার্ট পড়া যায়, পর্যালোচনা করা যায়, লাইন ধরে তুলনা করা যায় এবং একটি স্ক্রিপ্ট দিয়ে আবার তৈরি করা যায়। PartCraft দুই দিকেই কাজ করে: যেকোনো পার্ট স্ক্রিপ্ট হিসেবে লেখা যায়, আর একটি স্ক্রিপ্ট পার্টটি তৈরি করে।

## অ্যাপে

{{ui:Parameters}} ট্যাবে, **Script**-এর অধীনে:

- {{ui:Save as script}} খোলা পার্টটিকে `<name>.pcscript` হিসেবে ডাউনলোড করে।
- {{ui:Open script}} একটি `.pcscript` ফাইল থেকে পার্ট তৈরি করে। ভুল হলে তার লাইন নম্বরসহ জানানো হয় এবং কিছুই প্রতিস্থাপিত হয় না।

## স্ক্রিপ্ট ফরম্যাট

```
pcscript 1
part "Bracket"
  resolution 64

param width = 120
  note Plate width
param thick = 8
param bolt = 8.5
param margin = bolt * 1.5

sketch Plate
  on top
  point a 0, 0
  point b 120, 0
  point c 120, 60
  point d 0, 60
  line bottom a b
  line right b c
  line top c d
  line left d a
  coincident a O
  horizontal bottom
  horizontal top
  vertical left
  vertical right
  distance bottom = width
  distance left 60

extrude Base
  sketch Plate
  depth = thick

sketch HoleCentres
  on face Base end
  point h1 12, 12
  hdistance O h1 = margin
  vdistance O h1 = margin

hole Bolts
  sketch HoleCentres
  d = bolt
  through
```

নিয়মগুলো:

- বাঁ প্রান্তের লাইন একটি স্টেটমেন্ট শুরু করে: `pcscript`, `part`, `param`, একটি ফিচার টাইপ (`sketch`, `extrude`, `revolve`, `hole`, `lpattern`, `cpattern`, `mirror`, `fillet`, `chamfer`, `shell`, `import` এবং নতুন টাইপগুলো), তার নামসহ, অথবা `rollback <feature>`।
- ইনডেন্ট করা লাইন ওপরের স্টেটমেন্টের সেটিং। একা থাকা সেটিং (`through`, `reverse`, `suppressed`) মানে হ্যাঁ।
- একটি সংখ্যা-সেটিং একটি সংখ্যা, অথবা `=` ও একটি এক্সপ্রেশন, যা একটি সমীকরণ তৈরি করে: `depth = thick`।
- স্কেচে: `on` প্লেন নির্দিষ্ট করে (`front`, `top`, `right`, `face Base end`, `face Revolve1 side l3`); জ্যামিতি হলো `point <name> x, y`, `line <name> <point> <point>`, `circle <name> <centre> <radius>`, `arc <name> <centre> <start> <end>` (ঘড়ির কাঁটার বিপরীতে) বা `spline <name> fit|control <points>`; রিলেশন হলো তার ধরন ও যাদের যুক্ত করে তাদের নাম (`O` হলো অরিজিন); ডাইমেনশন তার মান বা `= expression` দিয়ে শেষ হয়।
- জ্যামিতি বা রিলেশন লাইনের ঐচ্ছিক সেটিং শেষে বর্গ বন্ধনীতে যায়, `;` দিয়ে আলাদা: `[construction]`, `[side -1; label 5, 3]`।
- `#` একটি মন্তব্য শুরু করে (লাইনের শুরুতে বা একটি স্পেসের পরে)। স্পেস থাকা নাম "ডাবল কোটেশনে" যায়।
- ফিচার আইডি লেখার ক্রমে f1 থেকে গোনা হয়। এজ ও ফেস রেফারেন্স এগুলো ব্যবহার করে, যেমন `edge f2.side:l3 f2.end [at 50, 0, 10]`।
- ফরম্যাটে শব্দ নেই এমন সেটিং `json` ও একটি মান দিয়ে লেখা হয়; সেগুলো যেমন আছে তেমনই পড়া হয়।

অ্যাপ থেকে সংরক্ষিত হলে স্ক্রিপ্টে প্রতিটি সেটিং থাকে, তাই সেটি একই পার্ট হিসেবে খোলে। অ্যাপ থেকে আমদানি করা STEP সলিড স্ক্রিপ্টের ভেতরে লেখা হয়, আর কমান্ড লাইন থেকে `step-file` দিয়ে নির্দিষ্ট একটি আলাদা `.step` ফাইল হিসেবে।

## কমান্ড লাইন টুল

টুলটি Node.js 24 সহ একটি কম্পিউটারে চলে, CadCraft সোর্সের একটি কপি থেকে: `node tools/partcraft-cli/partcraft.mjs <command>`। এটি একটি ডেভেলপার টুল এবং অ্যাপের একই মডিউল ব্যবহার করে। পার্ট হলো `.partcraft.json` ফাইল বা `.pcscript` স্ক্রিপ্ট।

| কমান্ড | এটি কী করে |
|---|---|
| `info <part>` | ফিচার, প্যারামিটার, রোলব্যাক বার, তৈরি সলিডের আয়তন ও আকার |
| `params <part>` | প্রতিটি প্যারামিটার ও সমীকরণ তার মানসহ |
| `set <part> width=150 Base.depth==thick` | সামনের দিকে: প্যারামিটার বদলান, সংখ্যা যুক্ত করুন (`==` বা একটি এক্সপ্রেশন), সাধারণ সংখ্যা সেট করুন |
| `drive <part> Base.depth=12` | পেছনের দিকে: একটি চালিত সংখ্যার পেছনের প্যারামিটার সমাধান করুন (`--prefer width` একটি বেছে নেয়) |
| `build <part> --out x.step` | লেখে `.step`, `.stl`, `.3mf`, `.json`, `.pcscript` বা একটি ম্যাক্রো (`.swb`) |
| `build <part> --table sizes.csv --out-dir sizes` | ডিজাইন টেবিলের প্রতিটি সারির জন্য একটি ফাইল |
| `variants <part> --out-dir d` বা `--zip f.zip` | প্রতিটি কনফিগারেশন STEP, IFC, DWG ও একটি প্রিভিউ হিসেবে, একটি ভেরিয়েন্ট টেবিল ও একটি লাইব্রেরি আইটেম (`--only "A,B"`, `--formats step,ifc,dwg,preview`, `--no-item`); দেখুন [একটি ভেরিয়েন্ট প্যাক তৈরি করুন](topic:variant-pack) |
| `script <in.pcscript> -o part.json` | স্ক্রিপ্ট থেকে পার্ট |
| `to-script <part> -o part.pcscript` | পার্ট থেকে স্ক্রিপ্ট |
| `rollback <part> [<feature>]`, `forward <part> [--end]` | ফাইলের রোলব্যাক বার সরান |
| `check <part> [--strict]` | নিচের শৃঙ্খলা পরীক্ষা |

`build` `--set name=value` (শুধু এই বিল্ডের জন্য) এবং `--upto <feature>`-ও নেয়। প্রতিটি কমান্ড `--json` নেয়। এক্সিট কোড: 0 ঠিক আছে, 1 একটি সমস্যা পাওয়া গেছে, 2 কমান্ড ভুলভাবে টাইপ করা হয়েছে। স্ক্রিপ্ট কখনো জায়গায় পুনরায় লেখা হয় না: বদলানো কপি সংরক্ষণ করতে `-o` দিন।

## পরীক্ষা

`check` জানায় কোন জিনিস পরে পার্ট বদলানো কঠিন করে:

| যা পাওয়া গেল | যেভাবে গণ্য হয় |
|---|---|
| স্কেচ যা বেশি সংজ্ঞায়িত (বিরোধী বা পুনরাবৃত্ত রিলেশন) | ত্রুটি |
| ফিচার যা তৈরি হয় না | ত্রুটি |
| ত্রুটিসহ একটি প্যারামিটার বা সমীকরণ, অথবা যে প্যারামিটারগুলো একে অপরকে ব্যবহার করে | ত্রুটি |
| স্কেচ যা কম সংজ্ঞায়িত, তার ডিগ্রি অফ ফ্রিডমসহ | সতর্কতা |
| ফিচার ও ডাইমেনশনে সরাসরি টাইপ করা সংখ্যা যা কোনো প্যারামিটার চালায় না | সতর্কতা |
| একটি প্যারামিটার যা কিছুই ব্যবহার করে না | সতর্কতা |
| একটি সাপ্রেস করা ফিচার; রোলব্যাক বার শেষে না থাকলে | সতর্কতা |

`--strict` প্রতিটি সতর্কতাকে ত্রুটি বানায়, যাতে একটি বিল্ড স্ক্রিপ্ট সম্পূর্ণ চালিত নয় এমন পার্ট প্রত্যাখ্যান করতে পারে।

:::note
`.swb` ম্যাক্রো আউটপুট বেশিরভাগ কারখানায় ব্যবহৃত পার্ট মডেলার প্রোগ্রামের জন্য: সেই প্রোগ্রামের ভেতরে চালালে সেখানে পার্টটি তৈরি হয়। এটি সেই প্রোগ্রামে এখানে চালানো হয়নি (এটি আমাদের সার্ভারে পাওয়া যায় না), তাই একে অপরীক্ষিত ধরুন।
:::
