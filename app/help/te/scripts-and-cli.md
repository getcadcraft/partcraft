జాగ్రత్తగా మోడలింగ్ చేయడం బటన్ల కంటే క్రమశిక్షణ గురించి ఎక్కువ. టెక్స్ట్‌గా వ్రాసిన భాగాన్ని చదవవచ్చు, సమీక్షించవచ్చు, లైన్ వారీగా పోల్చవచ్చు మరియు స్క్రిప్ట్ ద్వారా తిరిగి నిర్మించవచ్చు. PartCraft రెండు వైపులా వెళ్తుంది: ఏ భాగాన్నైనా స్క్రిప్ట్‌గా వ్రాయవచ్చు, మరియు స్క్రిప్ట్ భాగాన్ని నిర్మిస్తుంది.

## యాప్‌లో

{{ui:Parameters}} ట్యాబ్‌లో, **Script** కింద:

- {{ui:Save as script}} తెరిచిన భాగాన్ని `<name>.pcscript` గా డౌన్‌లోడ్ చేస్తుంది.
- {{ui:Open script}} ఒక `.pcscript` ఫైల్ నుండి భాగాన్ని నిర్మిస్తుంది. ఒక తప్పు దాని లైన్ నంబర్‌తో నివేదించబడుతుంది, మరియు ఏదీ భర్తీ చేయబడదు.

## స్క్రిప్ట్ ఫార్మాట్

```
pcscript 1
part "Bracket"
  resolution 64

param width = 120
  note Plate width
param thick = 8
param bolt = 8.5
param margin = bolt * 1.5

sketch Plate
  on top
  point a 0, 0
  point b 120, 0
  point c 120, 60
  point d 0, 60
  line bottom a b
  line right b c
  line top c d
  line left d a
  coincident a O
  horizontal bottom
  horizontal top
  vertical left
  vertical right
  distance bottom = width
  distance left 60

extrude Base
  sketch Plate
  depth = thick

sketch HoleCentres
  on face Base end
  point h1 12, 12
  hdistance O h1 = margin
  vdistance O h1 = margin

hole Bolts
  sketch HoleCentres
  d = bolt
  through
```

నియమాలు:

- ఎడమ అంచున ఉన్న లైన్ ఒక స్టేట్‌మెంట్‌ను ప్రారంభిస్తుంది: `pcscript`, `part`, `param`, ఒక ఫీచర్ రకం (`sketch`, `extrude`, `revolve`, `hole`, `lpattern`, `cpattern`, `mirror`, `fillet`, `chamfer`, `shell`, `import` మరియు కొత్త రకాలు) దాని పేరుతో, లేదా `rollback <feature>`.
- ఇండెంట్ చేసిన లైన్లు పైన ఉన్న స్టేట్‌మెంట్ యొక్క సెట్టింగ్‌లు. ఒంటరి సెట్టింగ్ (`through`, `reverse`, `suppressed`) అంటే అవును.
- సంఖ్య సెట్టింగ్ ఒక సంఖ్య, లేదా `=` మరియు ఎక్స్‌ప్రెషన్, ఇది ఈక్వేషన్ చేస్తుంది: `depth = thick`.
- స్కెచ్‌లో: `on` ప్లేన్‌కు పేరు ఇస్తుంది (`front`, `top`, `right`, `face Base end`, `face Revolve1 side l3`); జ్యామితి `point <name> x, y`, `line <name> <point> <point>`, `circle <name> <centre> <radius>`, `arc <name> <centre> <start> <end>` (అపసవ్య దిశలో) లేదా `spline <name> fit|control <points>`; రిలేషన్లు వాటి రకం మరియు అవి కలిపే పేర్లు (`O` ఆరిజిన్); డైమెన్షన్ దాని విలువతో లేదా `= expression` తో ముగుస్తుంది.
- జ్యామితి లేదా రిలేషన్ లైన్ యొక్క ఐచ్ఛిక సెట్టింగ్‌లు `;` తో వేరు చేయబడి చివర చదరపు బ్రాకెట్లలో ఉంటాయి: `[construction]`, `[side -1; label 5, 3]`.
- `#` ఒక వ్యాఖ్యను ప్రారంభిస్తుంది (లైన్ ప్రారంభంలో లేదా స్పేస్ తర్వాత). స్పేస్‌లు ఉన్న పేర్లు "డబుల్ కోట్స్" లో ఉంటాయి.
- ఫీచర్ ఐడీలు వ్రాసిన క్రమంలో f1 నుండి లెక్కించబడతాయి. ఎడ్జ్ మరియు ఫేస్ రిఫరెన్సులు వాటిని ఉపయోగిస్తాయి, ఉదాహరణకు `edge f2.side:l3 f2.end [at 50, 0, 10]`.
- ఫార్మాట్‌కు పదాలు లేని సెట్టింగ్‌లు `json` మరియు ఒక విలువతో వ్రాయబడతాయి; అవి ఉన్నట్లుగానే తిరిగి చదవబడతాయి.

యాప్ నుండి సేవ్ చేసినప్పుడు, స్క్రిప్ట్‌లో ప్రతి సెట్టింగ్ ఉంటుంది, కాబట్టి అది అదే భాగంగా తెరవబడుతుంది. దిగుమతి చేసిన STEP సాలిడ్ యాప్ నుండి స్క్రిప్ట్ లోపల వ్రాయబడుతుంది, మరియు కమాండ్ లైన్ నుండి `step-file` ద్వారా పేరు పెట్టబడిన ప్రత్యేక `.step` ఫైల్‌గా వ్రాయబడుతుంది.

## కమాండ్ లైన్ టూల్

ఈ టూల్ Node.js 24 ఉన్న కంప్యూటర్‌లో, CadCraft సోర్స్ కాపీ నుండి నడుస్తుంది: `node tools/partcraft-cli/partcraft.mjs <command>`. ఇది డెవలపర్ టూల్, మరియు యాప్ అదే మాడ్యూల్స్‌ను ఉపయోగిస్తుంది. భాగాలు `.partcraft.json` ఫైళ్లు లేదా `.pcscript` స్క్రిప్ట్‌లు.

| ఆదేశం | ఏమి చేస్తుంది |
|---|---|
| `info <part>` | ఫీచర్లు, పారామితులు, రోల్‌బ్యాక్ బార్, నిర్మించిన సాలిడ్ యొక్క ఘనపరిమాణం మరియు పరిమాణం |
| `params <part>` | ప్రతి పారామితి మరియు ఈక్వేషన్ దాని విలువతో |
| `set <part> width=150 Base.depth==thick` | ఫార్వర్డ్: పారామితులను మార్చు, సంఖ్యలను లింక్ చేయి (`==` లేదా ఎక్స్‌ప్రెషన్), సాదా సంఖ్యలను సెట్ చేయి |
| `drive <part> Base.depth=12` | వెనుకకు: నడిచే సంఖ్య వెనుక ఉన్న పారామితిని పరిష్కరించు (`--prefer width` ఒకదాన్ని ఎంచుకుంటుంది) |
| `build <part> --out x.step` | `.step`, `.stl`, `.3mf`, `.json`, `.pcscript` లేదా మ్యాక్రో (`.swb`) వ్రాస్తుంది |
| `build <part> --table sizes.csv --out-dir sizes` | ప్రతి డిజైన్ టేబుల్ వరుసకు ఒక ఫైల్ |
| `variants <part> --out-dir d` లేదా `--zip f.zip` | ప్రతి కాన్ఫిగరేషన్ STEP, IFC, DWG మరియు ప్రివ్యూగా, ఒక వేరియంట్స్ టేబుల్ మరియు లైబ్రరీ ఐటెమ్‌గా (`--only "A,B"`, `--formats step,ifc,dwg,preview`, `--no-item`); [వేరియంట్ ప్యాక్ తయారు చేయి](topic:variant-pack) చూడండి |
| `script <in.pcscript> -o part.json` | స్క్రిప్ట్ నుండి భాగానికి |
| `to-script <part> -o part.pcscript` | భాగం నుండి స్క్రిప్ట్‌కు |
| `rollback <part> [<feature>]`, `forward <part> [--end]` | ఫైల్‌లో రోల్‌బ్యాక్ బార్‌ను కదిలించు |
| `check <part> [--strict]` | క్రమశిక్షణ తనిఖీ (కింద) |

`build` `--set name=value` (ఈ బిల్డ్ కోసం మాత్రమే) మరియు `--upto <feature>` కూడా తీసుకుంటుంది. ప్రతి కమాండ్ `--json` తీసుకుంటుంది. ఎగ్జిట్ కోడ్‌లు: 0 సరైనది, 1 ఒక సమస్య కనుగొనబడింది, 2 కమాండ్ తప్పుగా టైప్ చేయబడింది. స్క్రిప్ట్ ఎప్పుడూ స్థానంలో తిరిగి వ్రాయబడదు: మార్చిన కాపీని సేవ్ చేయడానికి `-o` ఇవ్వండి.

## తనిఖీ

`check` ఒక భాగాన్ని తర్వాత మార్చడం కష్టతరం చేసేదాన్ని నివేదిస్తుంది:

| కనుగొనడం | ఇలా లెక్కించబడుతుంది |
|---|---|
| ఓవర్ డిఫైన్ చేయబడిన స్కెచ్ (విరుద్ధమైన లేదా పునరావృత రిలేషన్లు) | లోపం |
| నిర్మించబడని ఫీచర్ | లోపం |
| లోపంతో ఉన్న పారామితి లేదా ఈక్వేషన్, లేదా ఒకదానినొకటి ఉపయోగించుకునే పారామితులు | లోపం |
| అండర్ డిఫైన్ చేయబడిన స్కెచ్, దాని డిగ్రీస్ ఆఫ్ ఫ్రీడమ్‌తో | హెచ్చరిక |
| ఏ పారామితీ నడపని ఫీచర్లు మరియు డైమెన్షన్లలో నేరుగా టైప్ చేసిన సంఖ్యలు | హెచ్చరిక |
| ఏ పారామితీ ఉపయోగించని పారామితి | హెచ్చరిక |
| సప్రెస్ చేయబడిన ఫీచర్; రోల్‌బ్యాక్ బార్ చివరలో లేదు | హెచ్చరిక |

`--strict` ప్రతి హెచ్చరికను లోపంగా మారుస్తుంది, కాబట్టి బిల్డ్ స్క్రిప్ట్ పూర్తిగా నడపబడని భాగాన్ని తిరస్కరించగలదు.

:::note
`.swb` మ్యాక్రో అవుట్‌పుట్ చాలా షాప్‌లు ఉపయోగించే పార్ట్ మోడలర్ కోసం: ఆ ప్రోగ్రామ్ లోపల నడిచినప్పుడు, అది అక్కడ భాగాన్ని నిర్మిస్తుంది. అది ఇక్కడ ఆ ప్రోగ్రామ్‌లో నడపబడలేదు (ఇది మా సర్వర్లలో అందుబాటులో లేదు), కాబట్టి దాన్ని పరీక్షించనిదిగా పరిగణించండి.
:::
