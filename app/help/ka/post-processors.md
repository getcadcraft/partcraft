იგივე ინსტრუმენტის ტრაექტორია სხვადასხვა კონტროლერისთვის სხვაგვარად უნდა ჩაიწეროს: ხაზის ნომრებით ან მათ გარეშე, `M6` ან პაუზა, `G28` ან `G53`, `M30` ან `M2`. **პოსტი** არის მოკლე ტექსტი, რომელიც ამას განსაზღვრავს. PartCraft-ის სამი ჩაშენებული პოსტი (Fanuc-ის სტილის, GRBL და LinuxCNC) ამ ფორმატითაა დაწერილი, ამიტომ საკუთარი პოსტი შეიძლება ერთ-ერთის ასლიდან დაიწყოს.

შედეგი შეამოწმეთ თქვენი დანადგარის საკუთარ სიმულატორში დაჭრამდე და ჯერ ჰაერში, ნაჭრის თავზე გაუშვით. ჩაშენებული პოსტები ზუსტად იმას წერენ, რასაც ეს ფორმატი შემოღებამდე წერდა (ტესტები ასობით პროგრამაზე ბაიტ-ბაიტ ადარებენ მათ გამოსავალს), მაგრამ არც ერთი ეს თქვენს დანადგარზე არ არის დადასტურებული; შეცვლილი პოსტი თქვენი დასადასტურებელია.

## შექმენით ერთი

Manufacture-ში, **Post**-ის ქვეშ:

- {{ui:პოსტის რედაქტირება…}} ჩაშენებულ კონტროლერზე ხსნის **თქვენს საკუთარ ასლს**. საკუთარ პოსტზე ის ამ პოსტს ხსნის.
- {{ui:ახალი პოსტი…}} იწყებს მცირე ცარიელი პოსტით, რომელშიც ყველა მოვლენაა.
- {{ui:პოსტ-ფაილის იმპორტი…}} კითხულობს `.cpost` ტექსტურ ფაილს (რედაქტორში **ფაილად შენახვა…**-ს საშუალებით მიღებულს).

რედაქტორი აჩვენებს ტექსტს, სტრიქონს, რომელიც ამბობს, იკითხება თუ არა (და რომელი სტრიქონია არასწორი), და G-კოდს, რომელსაც პოსტი წერს თქვენი აკრეფისას. **წინასწარი ნახვა** ირჩევს მცირე სინჯურ პროგრამას, რომელიც ყველა მოვლენას ატარებს, ან ამ დეტალის საკუთარ პროგრამას. {{ui:შენახვა}} პოსტს ინახავს დეტალის ფაილში (მაქსიმუმ 20 პოსტი) და ირჩევს მას კონტროლერად. პოსტები დეტალს მიჰყვება; სხვა დეტალში გამოსაყენებლად შეინახეთ ფაილად და იმპორტით შეიტანეთ იქ.

## როგორ გამოიყურება პოსტი

```
post mymill
name My mill (.nc)
extension nc
line-numbers off
decimal-point no
canned-cycles no
modal motion G0 G1 G2 G3

on start
  comment Program {program}: {name}
  emit G21 G90 G17
end

on tool-change
  emit T{tool.number} M6
end

on rapid
  if moved
    emit G0~ X{x}~ Y{y}~ Z{z}~
  end
end
```

`//`-ით დაწყებული სტრიქონები და ცარიელი სტრიქონები უგულებელყოფილია. ზემოთ მოდის პარამეტრები; შემდეგ თითოეული მოვლენისთვის — `on <event>` ბლოკი, რომელიც `end`-ით მთავრდება. მოვლენა, რომელსაც გამოტოვებთ, არაფერს არ წერს.

| პარამეტრი | მნიშვნელობა |
|---|---|
| `post <id>` | პოსტის იდენტიფიკატორი: ასოები, ციფრები, `-` და `_` |
| `name <text>` | რას აჩვენებს კონტროლერების სია |
| `extension <ext>` | ფაილის გაფართოება: nc, ngc, tap … |
| `line-numbers 10` / `off` | `N10`, `N20` … ყოველ `emit` სტრიქონზე, ან არცერთზე |
| `decimal-point yes` / `no` | `10.` `10`-ის ნაცვლად (კომენტარებში წერტილი არასდროს იწერება) |
| `canned-cycles yes` / `no` | `no`: ხვრელები იწერება G0/G1 გადაადგილებებად, რომლებსაც ისინი წარმოადგენენ |
| `modal <group> <words>` | ჯგუფის სიტყვები (`modal motion G0 G1 G2 G3`), რომლებიც იწერება მხოლოდ მაშინ, როცა იცვლება |

## მოვლენები

პროგრამისთვის ისინი ამ თანმიმდევრობით მუშაობს: `start`; შემდეგ ყოველი ოპერაციისთვის `operation`, `tool-change` (როცა ინსტრუმენტი იცვლება), `spindle` (როცა სიჩქარე იცვლება), `approach` (მოძრაობა პირველ წერტილამდე, პირველ სწრაფ გადაადგილებამდე), `coolant-on`, შემდეგ მისი გადაადგილებები როგორც `rapid`, `feed` და `arc`, და ყოველი კანონიკური ციკლი როგორც `cycle-start`, თითო ხვრელზე `cycle-hole` და `cycle-end`; ბოლოს `end`.

თითოეულ მოვლენას შეუძლია გამოიყენოს თავისი ტიპის გადაადგილების ცვლადები, რომლებიც იწერება როგორც `{name}`: პროგრამის (`name`, `program`, `setup.axis`, `setup.origin`, `setup.coolant`), მასალის (`stock.kind`, `stock.d`, `stock.sx`, `stock.sy`, `stock.sz`, `stock.minx` … `stock.maxz`), ინსტრუმენტის (`tool.number`, `tool.desc`, `tool.kind`, `tool.d`, `tool.flutes`, `tool.fluteLen`), ოპერაციის (`op.name`, `op.type`), `rpm`, გადაადგილების წერტილის (`x`, `y`, `z`, `f`, და `moved`: true, როცა ღერძი შეიცვალა), რკალების (`arc.g` 2 ან 3, `arc.i`, `arc.j`, `arc.cx`, `arc.cy`) და ხვრელების (`hole.x`, `hole.y`, `hole.z`, `hole.r`, `hole.q`, `hole.return`, `hole.first`, `cycle.kind`, `cycle.init`, `feed`) ცვლადები. რედაქტორის **მოვლენები და ცვლადები** სია აჩვენებს, რომელი მოვლენა რას ხედავს. მდგომარეობა, რომლის წაკითხვაც და დაყენებაც შეიძლება: `cool`, `offset`, და `at.x`, `at.y`, `at.z`, `at.f` (ბოლოს ჩაწერილი მნიშვნელობები).

## ბრძანებები

| ბრძანება | რას აკეთებს |
|---|---|
| `raw TEXT` | სტრიქონი ზუსტად ისე, როგორც აკრიფეთ (ნომრის გარეშე) |
| `comment TEXT` | `(TEXT)` არა-ASCII სიმბოლოებისა და ფრჩხილების ამოღებით |
| `emit WORD WORD …` | სიტყვების სტრიქონი; ცარიელი გამოსული სიტყვები გამოტოვებულია; სიტყვების არქონა — სტრიქონის არქონა |
| `word WORD …` | სიტყვების დამატება აგებად სტრიქონს; ცარიელი `emit` მას ასრულებს |
| `if EXPR` … `else` … `end` | პირობები: `a == b`, `a != b`, `not a`, `a and b`, `a or b`, `a??b` (a, თუ არა — b) |
| `for tool in tools` … `end` | ერთხელ თითო ინსტრუმენტზე, რომელსაც პროგრამა იყენებს |
| `set NAME EXPR` | მნიშვნელობის დამახსოვრება (`set offset tool.number`) |
| `reset NAME …` | მოდალური სიტყვების დავიწყება (ჯგუფი, მისამართის ასო, მაგალითად `Z`, ან `at.z`) |
| `do rapid X Y Z` | `rapid` მოვლენის გაშვება წერტილისთვის |

სიტყვა არის ტექსტი `{variable|filter}` სახის ხვრელებით. ფილტრებია `upper`, `lower`, `pad:N` (ნულებით შევსება), `cut:N` (პირველი N სიმბოლო), `safe` (კომენტარისთვის უსაფრთხო ASCII) და `int`. სიტყვა, რომელიც `~`-ით მთავრდება, **მოდალურია**: იწერება მხოლოდ მაშინ, როცა განსხვავდება ბოლოს ჩაწერილისგან (`G1~`, `X{x}~`). სიტყვა, რომელიც `~!`-ით მთავრდება, ყოველთვის იწერება და მაინც მახსოვრდება. სახელი, რომელიც ცვლადი არ არის, უბრალო ტექსტია (`G81`, `mist`). რიცხვები მრგვალდება 0.001 mm-მდე და იწერება ბოლო ნულების გარეშე.

## რას ვერ შეძლებს პოსტი

ის მხოლოდ იმას განსაზღვრავს, როგორ იწერება გადაადგილებები, მეტს არაფერს. მას არ შეუძლია ინსტრუმენტის ტრაექტორიის შეცვლა, ოპერაციების რიგის შეცვლა, რკალის დაყოფა, ღერძის დამატება, თქვენი დანადგარის გადაადგილების დიაპაზონისა თუ კინემატიკის ცოდნა, ან კოორდინატებზე არითმეტიკა (`+` არ არსებობს). ზონდირება, ინსტრუმენტის რესურსი და ქვეპროგრამის ციკლები, მე-4 და მე-5 ღერძის გამოსავალი და ტრაქტორის კოდები ჯერ არ არის აგებული. სხვა პროგრამის `.cps`-ტიპის პოსტ-ფაილი ვერ ჩაიტვირთება: ეს სხვა, უფრო მარტივი ფორმატია.
