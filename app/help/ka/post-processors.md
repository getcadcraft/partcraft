იგივე ტრაექტორია სხვადასხვა მართვისთვის განსხვავებულად უნდა დაიწეროს: ხაზის ნომრებით ან მის გარეშე, `M6` ან პაუზა, `G28` ან `G53`, `M30` ან `M2`. **პოსტი** არის მოკლე ტექსტი, რომელიც ამის თქმას აკეთებს. PartCraft-ის სამი ჩაშენებული პოსტი (Fanuc-ის სტილის, GRBL და LinuxCNC) ამ ფორმატითაა დაწერილი, ასე რომ თქვენი საკუთარი პოსტი შეიძლება დაიწყოს ერთ-ერთის ასლიდან.

შეამოწმეთ გამოსავალი თქვენი მანქანის საკუთარ სიმულატორში დაჭრამდე და ჯერ გაუშვით ჰაერში, სამუშაო ნაჭრის ზემოთ. ჩაშენებული პოსტები ზუსტად იმას წერს, რასაც წერდა ეს ფორმატი არსებობამდე (ტესტები მათ გამოსავალს ბაიტ-ბაიტ ადარებს ასობით პროგრამაზე), მაგრამ აქ არაფერია დადასტურებული თქვენს მანქანაზე, და პოსტი, რომელსაც თქვენ შეცვლით, თქვენი დასამტკიცებელია.

## შექმენით ერთი

Manufacture-ში, **პოსტის** ქვეშ:

- {{ui:პოსტის რედაქტირება…}} ჩაშენებულ მართვაზე ხსნის **თქვენს საკუთარ ასლს**. თქვენს საკუთარ პოსტზე ის ხსნის ამ პოსტს.
- {{ui:ახალი პოსტი…}} იწყებს მცირე ცარიელ პოსტს, რომელშიც ყველა მოვლენაა.
- {{ui:პოსტ-ფაილის იმპორტი…}} კითხულობს `.cpost` ტექსტურ ფაილს (ფაილს, რომელსაც იღებთ რედაქტორში **ფაილად შენახვა…**-დან).

რედაქტორი აჩვენებს ტექსტს, ხაზს, რომელიც ამბობს, იკითხება თუ არა (და რომელი ხაზია არასწორი), და G-კოდს, რომელსაც პოსტი წერს, თქვენი აკრეფისას. **გადახედვა** ირჩევს პატარა სამაგალითო პროგრამას, რომელიც ყველა მოვლენას ატარებს, ან ამ დეტალის საკუთარ პროგრამას. {{ui:შენახვა}} ინახავს პოსტს დეტალის ფაილში (20 პოსტამდე) და ირჩევს მას როგორც მართვას. პოსტები დეტალთან ერთად მოგზაურობს; იმისთვის, რომ სხვა დეტალში გამოიყენოთ, შეინახეთ ის როგორც ფაილი და იმპორტი გააკეთეთ იქ.

## როგორ გამოიყურება პოსტი

```
post mymill
name My mill (.nc)
extension nc
line-numbers off
decimal-point no
canned-cycles no
modal motion G0 G1 G2 G3

on start
  comment Program {program}: {name}
  emit G21 G90 G17
end

on tool-change
  emit T{tool.number} M6
end

on rapid
  if moved
    emit G0~ X{x}~ Y{y}~ Z{z}~
  end
end
```

`//`-ით დაწყებული ხაზები და ცარიელი ხაზები უგულებელყოფილია. ზედა ნაწილში მოდის პარამეტრები; შემდეგ თითო მოვლენაზე ერთი `on <event>` ბლოკი, რომელიც `end`-ით იხურება. მოვლენა, რომელსაც გამოტოვებთ, არაფერს წერს.

| პარამეტრი | მნიშვნელობა |
|---|---|
| `post <id>` | პოსტის id: ასოები, ციფრები, `-` და `_` |
| `name <text>` | რას აჩვენებს მართვების სია |
| `extension <ext>` | ფაილის გაფართოება: nc, ngc, tap … |
| `line-numbers 10` / `off` | `N10`, `N20` … ყოველ `emit` ხაზზე, ან არცერთზე |
| `decimal-point yes` / `no` | `10.` `10`-ის ნაცვლად (კომენტარები არასდროს ატარებს წერტილს) |
| `canned-cycles yes` / `no` | `no`: ხვრელები იწერება G0/G1 გადაადგილებებად, რომლებსაც ისინი წარმოადგენს |
| `modal <group> <words>` | ჯგუფის სიტყვები (`modal motion G0 G1 G2 G3`), რომლებიც იწერება მხოლოდ მაშინ, როცა იცვლება |

## მოვლენები

პროგრამისთვის ისინი ამ თანმიმდევრობით მუშაობს: `start`; შემდეგ თითო ოპერაციაზე `operation`, `tool-change` (როცა ინსტრუმენტი იცვლება), `spindle` (როცა სიჩქარე იცვლება), `approach` (გადასვლა პირველ წერტილამდე, პირველ სწრაფ გადაადგილებამდე), `coolant-on`, შემდეგ მისი გადაადგილებები როგორც `rapid`, `feed` და `arc`, და ყოველი ჩაშენებული ციკლი როგორც `cycle-start`, თითო ხვრელზე ერთი `cycle-hole` და `cycle-end`; ბოლოს `end`.

მეტი მოვლენა იმისთვის, რაც სამ ღერძს სცდება (პოსტი მოვლენის გარეშე უარყოფს ასეთ პროგრამას და დაასახელებს მოვლენას, რომელიც აკლია):

| მოვლენა | როდის | მისი ცვლადები |
|---|---|---|
| `index` | ოპერაციამდე, რომლის ინსტრუმენტის მიმართულება წინასგან განსხვავდება, და პირველ ოპერაციამდე ბრუნვითი ღერძების მქონე მანქანაზე | `rot.a`, `rot.b`, `rot.c` (პოზიციები, სადაც უნდა წავიდეს; ცარიელი იმ ღერძისთვის, რომელიც მანქანას არ აქვს), `first.x`, `first.y`, `first.z` |
| `rapid-rotary`, `feed-rotary` | ოპერაციის გადაადგილებები, რომელშიც ბრუნვითი ღერძები ჭრისას მოძრაობს | `x`, `y`, `z`, `rot.a`, `rot.b`, `rot.c`, `f`, `rot.moved`, `inverse` (yes, როცა მიწოდება უნდა იყოს შებრუნებული დრო), `invf` (1/წუთებში) |
| `rotary-end` | ასეთი ოპერაციის შემდეგ | |
| `probe-move` | გადაადგილება, რომელიც ჩერდება, როცა ზონდი ირთვება | `x`, `y`, `z`, `f`, `probe.n` (1-დან 4-მდე), `probe.axis` (x, y ან z), `probe.k` (1, 2 ან 3) |
| `probe-set` | ერთი ზონდირების ციკლის შეხებების შემდეგ | `probe.kind` (`"z"`, `"x"`, `"y"` ან `centre`), `probe.action` (`set` ან `measure`), `probe.expect`, `probe.cx`, `probe.cy` |
| `thread` | ძაფის გადაადგილება ტოკარზე | `x`, `z`, `thread.lead` |

ყოველი მოვლენისთვის ასევე: `kin` (none, a, b, ac, bc), `rotary` და `tcp` (yes ან no, მანქანიდან დაყენებაში), `pivot.x`, `pivot.y`, `pivot.z`, ოპერაციის `op.tilt` და `op.turn`, და ტოკარზე `spin.mode` (css ან rpm), `spin.css`, `spin.max` და `tool.nose`. ასოიანი სიტყვა, რომლის მნიშვნელობა ცარიელია, მაგალითად `A{rot.a}` მანქანაზე A ღერძის გარეშე, ხაზიდან გამოტოვებულია. შეადარეთ x, y და z როგორც ტექსტი ბრჭყალებში (`if probe.kind == "z"`): შიშველი სახით ისინი გადაადგილების კოორდინატებია.

პოსტის ზედა ნაწილში ორი დამატებითი ხაზი მას ტოკარის პოსტად აქცევს: `machine lathe` (მაშინ ის წერს მხოლოდ X-სა და Z-ს და უარყოფს ფრეზვის ტრაექტორიებს, როგორც ფრეზვის პოსტი უარყოფს ტოკარის ტრაექტორიებს) და `lathe-x diameter` ან `lathe-x radius`.

ყოველი მოვლენა შეუძლია გამოიყენოს თავისი სახის გადაადგილების ცვლადები, რომლებიც იწერება როგორც `{name}`: პროგრამა (`name`, `program`, `setup.axis`, `setup.origin`, `setup.coolant`), სამუშაო ნაჭერი (`stock.kind`, `stock.d`, `stock.sx`, `stock.sy`, `stock.sz`, `stock.minx` … `stock.maxz`), ინსტრუმენტი (`tool.number`, `tool.desc`, `tool.kind`, `tool.d`, `tool.flutes`, `tool.fluteLen`), ოპერაცია (`op.name`, `op.type`), `rpm`, გადაადგილების წერტილი (`x`, `y`, `z`, `f`, და `moved`: true, როცა ღერძი შეიცვალა), რკალები (`arc.g` 2 ან 3, `arc.i`, `arc.j`, `arc.cx`, `arc.cy`) და ხვრელები (`hole.x`, `hole.y`, `hole.z`, `hole.r`, `hole.q`, `hole.return`, `hole.first`, `cycle.kind`, `cycle.init`, `feed`). რედაქტორის **მოვლენები და ცვლადები** სია აჩვენებს, რომელი მოვლენა რას ხედავს. მდგომარეობა, რომლის წაკითხვაც და დაყენებაც შეიძლება: `cool`, `offset`, და `at.x`, `at.y`, `at.z`, `at.f` (ბოლო დაწერილი მნიშვნელობები).

## განცხადებები

| განცხადება | რას აკეთებს |
|---|---|
| `raw TEXT` | ხაზი ზუსტად ისე, როგორც აკრიფეთ (ნომრის გარეშე) |
| `comment TEXT` | `(TEXT)`, არა-ASCII სიმბოლოებისა და ფრჩხილების გარეშე |
| `emit WORD WORD …` | სიტყვების ხაზი; ცარიელი შედეგის მქონე სიტყვები გამოტოვებულია; სიტყვების გარეშე, ხაზი არ არის |
| `word WORD …` | სიტყვების დამატება ხაზზე, რომელიც იქმნება; შიშველი `emit` ამთავრებს მას |
| `if EXPR` … `else` … `end` | პირობები: `a == b`, `a != b`, `not a`, `a and b`, `a or b`, `a??b` (a, თუ არა — b) |
| `for tool in tools` … `end` | ერთხელ თითოეული ინსტრუმენტისთვის, რომელსაც პროგრამა იყენებს |
| `set NAME EXPR` | მნიშვნელობის დამახსოვრება (`set offset tool.number`) |
| `reset NAME …` | მოდალური სიტყვების დავიწყება (ჯგუფი, მისამართის ასო, როგორიცაა `Z`, ან `at.z`) |
| `do rapid X Y Z` | გაუშვით `rapid` მოვლენა წერტილისთვის |

სიტყვა არის აკრეფილი ტექსტი `{variable|filter}` სახის ხვრელებით. ფილტრებია `upper`, `lower`, `pad:N` (ნულებით შევსება), `cut:N` (პირველი N სიმბოლო), `safe` (კომენტარისთვის უსაფრთხო ASCII) და `int`. სიტყვა, რომელიც `~`-ით მთავრდება, არის **მოდალური**: ის იწერება მხოლოდ მაშინ, როცა განსხვავდება ბოლოს დაწერილისგან (`G1~`, `X{x}~`). სიტყვა, რომელიც `~!`-ით მთავრდება, იწერება ყოველ ჯერზე და მაინც მახსოვრდება. სახელი, რომელიც ცვლადი არ არის, არის უბრალო ტექსტი (`G81`, `mist`). რიცხვები მრგვალდება 0.001 მმ-მდე და იწერება ბოლო ნულების გარეშე.

## რისი გაკეთება პოსტს არ შეუძლია

ის მხოლოდ წყვეტს, როგორ იწერება გადაადგილებები, მეტს არაფერს. მას არ შეუძლია ტრაექტორიის შეცვლა, ოპერაციების დალაგება, რკალის გაყოფა, ღერძის დამატება, თქვენი მანქანის სვლის ან კინემატიკის ცოდნა, ან კოორდინატებზე არითმეტიკის შესრულება (`+` არ არსებობს). ბრუნვითი პოზიციები თავად მოდის მანქანიდან, რომელიც აღწერილია დაყენებაში, და არა პოსტიდან: პოსტს შეუძლია შეცვალოს მათი ნიშანი ან ასოები, მაგრამ არა კინემატიკა. ინსტრუმენტის სიცოცხლისა და ქვეპროგრამის ციკლები არ არის აგებული. სხვა პროგრამის `.cps`-ის ტიპის პოსტ-ფაილი ვერ ჩაიტვირთება: ეს განსხვავებული, უფრო მარტივი ფორმატია.
