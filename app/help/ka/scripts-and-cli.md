ფრთხილი მოდელირება უფრო დისციპლინაზეა დამოკიდებული, ვიდრე ღილაკებზე. ტექსტად დაწერილი ნაწილის წაკითხვა, განხილვა, სტრიქონ-სტრიქონ შედარება და სკრიპტით ხელახლა აგება შეიძლება. PartCraft ორივე მიმართულებით მუშაობს: ნებისმიერი ნაწილი შეიძლება დაიწეროს სკრიპტად, და სკრიპტი ნაწილს აგებს.

## აპში

{{ui:პარამეტრები}} ჩანართზე, **სკრიპტის** ქვეშ:

- {{ui:შენახვა როგორც სკრიპტი}} ღია ნაწილს ჩამოტვირთავს როგორც `<name>.pcscript`.
- {{ui:სკრიპტის გახსნა}} `.pcscript` ფაილიდან აგებს ნაწილს. შეცდომა მითითებული იქნება თავისი სტრიქონის ნომრით და არაფერი შეიცვლება.

## სკრიპტის ფორმატი

```
pcscript 1
part "Bracket"
  resolution 64

param width = 120
  note Plate width
param thick = 8
param bolt = 8.5
param margin = bolt * 1.5

sketch Plate
  on top
  point a 0, 0
  point b 120, 0
  point c 120, 60
  point d 0, 60
  line bottom a b
  line right b c
  line top c d
  line left d a
  coincident a O
  horizontal bottom
  horizontal top
  vertical left
  vertical right
  distance bottom = width
  distance left 60

extrude Base
  sketch Plate
  depth = thick

sketch HoleCentres
  on face Base end
  point h1 12, 12
  hdistance O h1 = margin
  vdistance O h1 = margin

hole Bolts
  sketch HoleCentres
  d = bolt
  through
```

წესები:

- მარცხენა კიდეზე მდებარე სტრიქონი იწყებს ჩანაწერს: `pcscript`, `part`, `param`, ელემენტის ტიპი (`sketch`, `extrude`, `revolve`, `hole`, `lpattern`, `cpattern`, `mirror`, `fillet`, `chamfer`, `shell`, `import` და უახლესი ტიპები), რომელსაც მოსდევს მისი სახელი, ან `rollback <feature>`.
- შეწეული (indented) სტრიქონები ზემოთ მდებარე ჩანაწერის პარამეტრებია. პარამეტრი მარტო (`through`, `reverse`, `suppressed`) ნიშნავს „დიახ“.
- რიცხვითი პარამეტრი არის რიცხვი, ან `=` და გამოსახულება, რაც ქმნის განტოლებას: `depth = thick`.
- ესკიზში: `on` ასახელებს სიბრტყეს (`front`, `top`, `right`, `face Base end`, `face Revolve1 side l3`); გეომეტრია არის `point <name> x, y`, `line <name> <point> <point>`, `circle <name> <centre> <radius>`, `arc <name> <centre> <start> <end>` (საათის ისრის საწინააღმდეგოდ) ან `spline <name> fit|control <points>`; კავშირები არის მათი ტიპი და სახელები, რომლებსაც აერთებენ (`O` არის სათავე); ზომა მთავრდება თავისი მნიშვნელობით ან `= expression`-ით.
- გეომეტრიის ან კავშირის სტრიქონის არასავალდებულო პარამეტრები მიეწერება ბოლოს, კვადრატულ ფრჩხილებში, `;`-ით გამოყოფილი: `[construction]`, `[side -1; label 5, 3]`.
- `#` იწყებს კომენტარს (სტრიქონის დასაწყისში ან ჰარის შემდეგ). სახელები ჰარებით იწერება „ორმაგ ბრჭყალებში“.
- ელემენტების ID-ები იწყება f1-დან, დაწერის რიგით. წიბოსა და წახნაგის მითითებები მათ იყენებს, მაგალითად `edge f2.side:l3 f2.end [at 50, 0, 10]`.
- პარამეტრები, რომელთათვისაც ფორმატს სიტყვები არ აქვს, იწერება `json`-ით და მნიშვნელობით; ისინი უცვლელად იკითხება.

აპიდან შენახული სკრიპტი ყველა პარამეტრს მოიცავს, ამიტომ ის იგივე ნაწილად გაიხსნება. შემოტანილი STEP სხეული აპიდან სკრიპტის შიგნით იწერება, ხოლო ბრძანებათა ხაზიდან — ცალკე `.step` ფაილად, რომლის სახელს `step-file` განსაზღვრავს.

## ბრძანებათა ხაზის ხელსაწყო

ხელსაწყო მუშაობს კომპიუტერზე, სადაც Node.js 24-ია, CadCraft-ის წყაროს ასლიდან: `node tools/partcraft-cli/partcraft.mjs <command>`. ეს დეველოპერის ხელსაწყოა და აპის იგივე მოდულებს იყენებს. ნაწილები არის `.partcraft.json` ფაილები ან `.pcscript` სკრიპტები.

| ბრძანება | რას აკეთებს |
|---|---|
| `info <part>` | ელემენტები, პარამეტრები, დაბრუნების ზოლი, აგებული სხეულის მოცულობა და ზომა |
| `params <part>` | ყველა პარამეტრი და განტოლება თავისი მნიშვნელობით |
| `set <part> width=150 Base.depth==thick` | წინ: პარამეტრების შეცვლა, რიცხვების დაკავშირება (`==` ან გამოსახულება), უბრალო რიცხვების დაყენება |
| `drive <part> Base.depth=12` | უკან: იმ პარამეტრის ამოხსნა, რომელიც მართული რიცხვის უკან დგას (`--prefer width` ერთ-ერთს ირჩევს) |
| `build <part> --out x.step` | წერს `.step`, `.stl`, `.3mf`, `.json`, `.pcscript`-ს ან მაკროს (`.swb`) |
| `build <part> --table sizes.csv --out-dir sizes` | თითო ფაილი დიზაინის ცხრილის თითო სტრიქონზე |
| `variants <part> --out-dir d` ან `--zip f.zip` | ყველა კონფიგურაცია როგორც STEP, IFC, DWG და გადახედვა, ვარიანტების ცხრილი და ბიბლიოთეკის ელემენტი (`--only "A,B"`, `--formats step,ifc,dwg,preview`, `--no-item`); იხილეთ [ვარიანტების პაკეტის შექმნა](topic:variant-pack) |
| `script <in.pcscript> -o part.json` | სკრიპტიდან ნაწილში |
| `to-script <part> -o part.pcscript` | ნაწილიდან სკრიპტში |
| `rollback <part> [<feature>]`, `forward <part> [--end]` | ფაილში დაბრუნების ზოლის გადატანა |
| `check <part> [--strict]` | დისციპლინის შემოწმება (ქვემოთ) |

`build` ასევე იღებს `--set name=value`-ს (მხოლოდ ამ აგებისთვის) და `--upto <feature>`-ს. ყველა ბრძანება იღებს `--json`-ს. გასვლის კოდები: 0 — კარგად, 1 — ნაპოვნია პრობლემა, 2 — ბრძანება არასწორად არის აკრეფილი. სკრიპტი არასოდეს გადაიწერება ადგილზე: შეცვლილი ასლის შესანახად მიუთითეთ `-o`.

## შემოწმება

`check` აჩვენებს, რა ართულებს ნაწილის მოგვიანებით შეცვლას:

| მიგნება | ითვლება როგორც |
|---|---|
| ესკიზი ზედმეტად განსაზღვრულია (კონფლიქტური ან განმეორებადი კავშირები) | შეცდომა |
| ელემენტი არ აგებს | შეცდომა |
| პარამეტრი ან განტოლება შეცდომით, ან პარამეტრები ერთმანეთს იყენებენ | შეცდომა |
| ესკიზი არასაკმარისად განსაზღვრულია, მისი თავისუფლების ხარისხებით | გაფრთხილება |
| რიცხვები, რომლებიც პირდაპირ ელემენტებსა და ზომებში ჩაწერილია და არც ერთი პარამეტრი არ მართავს | გაფრთხილება |
| პარამეტრი, რომელსაც არაფერი იყენებს | გაფრთხილება |
| ჩაქრობილი ელემენტი; დაბრუნების ზოლი ბოლოში არ არის | გაფრთხილება |

`--strict` ყველა გაფრთხილებას შეცდომად აქცევს, ამიტომ აგების სკრიპტს შეუძლია უარი თქვას ნაწილზე, რომელიც სრულად არ არის მართული.

:::note
`.swb` მაკროს გამოსავალი განკუთვნილია ნაწილების მოდელირების იმ პროგრამისთვის, რომელსაც უმეტესი სახელოსნო იყენებს: მის შიგნით გაშვებისას ის ნაწილს იქ აგებს. აქ ის ამ პროგრამაში არ გაშვებულა (ის ჩვენს სერვერებზე არ არის ხელმისაწვდომი), ამიტომ მას არატესტირებულად მიიჩნიეთ.
:::
