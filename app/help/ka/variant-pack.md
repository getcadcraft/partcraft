## რას გააკეთებთ

გადასცემთ **ნაწილის ყველა ზომას ერთდროულად**: ერთ STEP, IFC და DWG ფაილს და სურათს ყოველი კონფიგურაციისთვის, ცხრილს, რომელიც ამბობს, რა არის თითო, და ბიბლიოთეკის ელემენტს, რომელიც ყველა მათგანს ერთ გვერდზე აჩვენებს.

ჯერ გჭირდებათ ნაწილი **კონფიგურაციებით** (იხ. [კონფიგურაციები და დიზაინის ცხრილები](topic:design-tables)). კონფიგურაცია, რომელიც ელემენტს გამორთავს, მაგალითად ფირფიტა ხვრელებით და ხვრელების გარეშე, თავისთავად ხდება ვარიანტი.

## ნაბიჯები

1. გახსენით ნაწილი. {{ui:პარამეტრები}} ჩანართზე იპოვეთ **კონფიგურაციები**.
2. დააწკაპუნეთ {{ui:ვარიანტების პაკეტი…}}.
3. მონიშნეთ ასაგები კონფიგურაციები (ყველა მონიშნულია) და ფაილები, რომლებიც უნდა ჩაიწეროს: STEP, IFC, DWG, გადახედვა და ბიბლიოთეკის ელემენტი.
4. დააწკაპუნეთ {{ui:პაკეტის შექმნა}}. სტატუსის ხაზი ითვლის ვარიანტებს მათი აგებისას; თქვენი ნაწილი არ იცვლება.
5. ჩამოიტვირთება ერთი zip: `<part> variants.zip`.

## zip-ში რა არის

| ფაილი | რა არის |
|---|---|
| `<name>.step` | კონფიგურაცია, როგორც STEP მყარი სხეული. |
| `<name>.ifc` | IFC4, ერთი ელემენტი აგებული სხეულით და ნაწილის პარამეტრები თვისებებად; მნიშვნელობა ამ კონფიგურაციისაა. |
| `<name>.dwg` | წინა, ზედა, მარჯვენა და იზომეტრიული ხედები ნახაზის ფურცლად, სრული ზომით. |
| `<name>.svg` | მისი იზომეტრიული ხაზოვანი სურათი. |
| `variants.csv`, `variants.json` | პარამეტრების ცხრილი: თითო ვარიანტის id, სახელი და ყოველი პარამეტრის მნიშვნელობა, ელემენტები, რომლებსაც გამორთავს, მისი ფაილები, მოცულობა და ზომა. |
| `<part>.item.json` | ნაწილი, როგორც ერთი ბიბლიოთეკის ელემენტი თავისი ვარიანტებით (იხ. ქვემოთ). |
| `README.txt` | რა შეიქმნა, ქვემოთ მოცემული შენიშვნები და ის, რაც არ აიგო. |

ფაილები სახელდება კონფიგურაციის მიხედვით. კონფიგურაცია, რომელიც ვერ აიგო (ელემენტი, რომელიც ამ მნიშვნელობებით ვერ შეიქმნება), გამოტოვებულია ფაილებიდან და ცხრილიდან, ჩამოთვლილია README-ში და შეტყობინებაში zip-ის შენახვის შემდეგ; დანარჩენები მაინც ჩაიწერება.

## სასარგებლო ცნობები

- **STEP** ზუსტია, როცა ზუსტი kernel ჩართულია თქვენს build-ში. მის გარეშე STEP წახნაგებულია (ბრტყელი სამკუთხედები), და README ამას ამბობს.
- **DWG** არის ნახაზის ფურცელი და არა 3D მოდელი. მისი ხაზები მესიდან მოდის, ამიტომ მრუდი წიბო ბევრი მოკლე ხაზია.
- **ბიბლიოთეკის ელემენტი** შეიცავს ერთ სხეულსა და ერთ საძირკველს თითო ვარიანტზე, ბიბლიოთეკის საკუთარ ღერძებში: Z ზემოთ, წინა მხარე −Y-კენ, ჩასმის წერტილი კი ქვედა უკანა მხარის შუაში. გეგმა არის თითო ვარიანტის შემომსაზღვრელი მართკუთხედი. ელემენტი შეზღუდულია 8 MB-ით, ამიტომ ძალიან მძიმე ვარიანტი ხდება თავისი ზომის ყუთი, და README ამბობს, რამდენი.
- ნაწილის აქტიური კონფიგურაცია ხდება ელემენტის ნაგულისხმევი ვარიანტი.
- პორტები (მილებისა და არხების შეერთების წერტილები) PartCraft-იდან არ დგინდება.

## ვარიანტების გვერდზე განთავსება ბიბლიოთეკაში

ატვირთეთ `<part>.item.json` საიტზე **ბიბლიოთეკა › ატვირთვა**. აირჩიეთ მისი კატეგორია, ლიცენზია და თქვენი ავტორობის ხაზი — და ის გახდება ბიბლიოთეკის ელემენტი თავისი ვარიანტებით. BimCraft-ში მისი ჩასმისას ჰკითხავს, რომელი ვარიანტი, ხოლო **გაცვლა** სხვებს შემოგთავაზებთ. გვერდი, სადაც ვიზიტორები ირჩევენ ვარიანტს, ხედავენ 3D-ს და ჩამოტვირთავენ მას, ამ დროისთვის **თანამშრომლებისთვის გადახედვაა** და ჯერ საჯაროდ არ არის ხელმისაწვდომი.

## ბრძანებათა ხაზიდან

```
node tools/partcraft-cli/partcraft.mjs variants plate.partcraft.json --out-dir plate-variants
node tools/partcraft-cli/partcraft.mjs variants plate.partcraft.json --only "Small,Large" --formats step,preview --zip plate.zip
```

`--only` ასახელებს კონფიგურაციებს, `--formats` იღებს ნებისმიერს `step`, `ifc`, `dwg`, `preview`-დან; `--no-item` ბიბლიოთეკის ელემენტს გამორიცხავს. ის წერს საქაღალდეს, zip-ს ან ორივეს და გადის კოდით 1, როცა ვარიანტი ვერ აიგო. იხ. [სკრიპტები და ბრძანებათა ხაზი](topic:scripts-and-cli).
