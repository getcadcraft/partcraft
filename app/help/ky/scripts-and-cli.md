Кылдат моделдөө баскычтарга караганда тартипке көбүрөөк байланыштуу. Текст катары жазылган деталды окууга, кароого, сап-сап салыштырууга жана скрипт менен кайра түзүүгө болот. PartCraft экөөсүнө тең жарайт: ар кандай деталды скрипт катары жазууга болот, ал эми скрипт деталды түзөт.

## Колдонмодо

{{ui:Параметрлер}} өтмөгүндө, **Скрипт** астында:

- {{ui:Скрипт катары сактоо}} ачык деталды `<name>.pcscript` катары жүктөйт.
- {{ui:Скриптти ачуу}} `.pcscript` файлынан деталь түзөт. Ката сап номери менен көрсөтүлөт жана эч нерсе алмаштырылбайт.

## Скрипт форматы

```
pcscript 1
part "Bracket"
  resolution 64

param width = 120
  note Plate width
param thick = 8
param bolt = 8.5
param margin = bolt * 1.5

sketch Plate
  on top
  point a 0, 0
  point b 120, 0
  point c 120, 60
  point d 0, 60
  line bottom a b
  line right b c
  line top c d
  line left d a
  coincident a O
  horizontal bottom
  horizontal top
  vertical left
  vertical right
  distance bottom = width
  distance left 60

extrude Base
  sketch Plate
  depth = thick

sketch HoleCentres
  on face Base end
  point h1 12, 12
  hdistance O h1 = margin
  vdistance O h1 = margin

hole Bolts
  sketch HoleCentres
  d = bolt
  through
```

Эрежелер:

- Сол четинен баштаган сап билдирүүнү баштайт: `pcscript`, `part`, `param`, элемент түрү (`sketch`, `extrude`, `revolve`, `hole`, `lpattern`, `cpattern`, `mirror`, `fillet`, `chamfer`, `shell`, `import` жана жаңыраак түрлөр) анын аты менен, же `rollback <feature>`.
- Чегинип жазылган сап жогорудагы билдирүүнүн жөндөөлөрү болот. Өзүнчө турган жөндөө (`through`, `reverse`, `suppressed`) ооба дегенди билдирет.
- Сан жөндөөсү сан, же `=` жана туюнтма болот, ал теңдеме жасайт: `depth = thick`.
- Эскизде: `on` тегиздикти атайт (`front`, `top`, `right`, `face Base end`, `face Revolve1 side l3`); геометрия — `point <name> x, y`, `line <name> <point> <point>`, `circle <name> <centre> <radius>`, `arc <name> <centre> <start> <end>` (саат жебесине каршы) же `spline <name> fit|control <points>`; байланыштар — өз түрү жана аларды байланыштырган аттар (`O` — башталыш координата); өлчөм маанисинин же `= туюнтманын` аягында келет.
- Геометриянын же байланыш сабынын милдеттүү эмес жөндөөлөрү аягында квадраттык кашаа ичинде, `;` менен бөлүнүп жазылат: `[construction]`, `[side -1; label 5, 3]`.
- `#` комментарий баштайт (сап башында же бош орундан кийин). Аттары бош орун бар аттар кош тырмакчаларда жазылат.
- Элементтин ID'лери биринчи жазылган тартиптен f1 дан санала башталат. Четтин жана беттин шилтемелери аларды колдонот, мисалы `edge f2.side:l3 f2.end [at 50, 0, 10]`.
- Формат үчүн сөздөрү жок жөндөөлөр `json` жана маани деп жазылат; алар ошол бойдон окулат.

Колдонмодон сакталган скрипт бардык жөндөөлөрдү камтыйт, ошондуктан ал ошол эле деталь катары ачылат. Импорттолгон STEP катуу дене колдонмодон скрипттин ичине жазылат, ал эми буйрук сабынан `step-file` аркылуу аталган өзүнчө `.step` файлы катары жазылат.

## Буйрук сабынын куралы

Курал Node.js 24 орнотулган компьютерде, CadCraft булак кодунун көчүрмөсүнөн иштейт: `node tools/partcraft-cli/partcraft.mjs <command>`. Бул иштеп чыгуучунун куралы жана колдонмодогу ошол эле модулдарды колдонот. Деталдар — `.partcraft.json` файлдары же `.pcscript` скрипттер.

| Буйрук | Эмне кылат |
|---|---|
| `info <part>` | Элементтер, параметрлер, rollback тилкеси, түзүлгөн катуу дененин көлөмү жана өлчөмү |
| `params <part>` | Ар бир параметр жана теңдеме анын маанисине ылайык |
| `set <part> width=150 Base.depth==thick` | Түз: параметрлерди өзгөртүү, сандарды байланыштыруу (`==` же туюнтма), жөнөкөй сандарды коюу |
| `drive <part> Base.depth=12` | Кайра: айдалган санды башкарган параметрди чечүү (`--prefer width` бирин тандайт) |
| `build <part> --out x.step` | `.step`, `.stl`, `.3mf`, `.json`, `.pcscript` же макросту (`.swb`) жазат |
| `build <part> --table sizes.csv --out-dir sizes` | Дизайн таблицасынын ар бир катарына бир файл |
| `variants <part> --out-dir d` же `--zip f.zip` | Ар бир конфигурация STEP, IFC, DWG жана алдын ала көрүү, варианттар таблицасы жана китепкана элементи катары (`--only "A,B"`, `--formats step,ifc,dwg,preview`, `--no-item`); см. [Варианттар топтомун жасоо](topic:variant-pack) |
| `script <in.pcscript> -o part.json` | Скрипттен деталга |
| `to-script <part> -o part.pcscript` | Деталдан скриптке |
| `rollback <part> [<feature>]`, `forward <part> [--end]` | Rollback тилкесин файлда жылдыруу |
| `check <part> [--strict]` | Тартип текшерүүсү (төмөндө) |

`build` дагы `--set name=value` (бул түзүү үчүн гана) жана `--upto <feature>` кабыл алат. Ар бир буйрук `--json` кабыл алат. Чыгуу коддору: 0 жакшы, 1 көйгөй табылды, 2 буйрук туура эмес терилди. Скрипт эч качан ордунда кайра жазылбайт: өзгөртүлгөн көчүрмөнү сактоо үчүн `-o` бериңиз.

## Текшерүү

`check` деталды кийинчерээк өзгөртүүнү кыйындаткан нерселерди билдирет:

| Табылган нерсе | Эсептелет |
|---|---|
| Ашыкча аныкталган эскиз (карама-каршы же кайталанган байланыштар) | ката |
| Курула албаган элемент | ката |
| Ката бар параметр же теңдеме, же бири-бирин колдонгон параметрлер | ката |
| Аныкталбаган эскиз, анын эркиндик даражалары менен | эскертүү |
| Элементтерге жана өлчөмдөргө түздөн-түз терилген, эч бир параметр айдабаган сандар | эскертүү |
| Эч ким колдонбогон параметр | эскертүү |
| Басылган элемент; rollback тилкеси аягында эмес | эскертүү |

`--strict` ар бир эскертүүнү катага айлантат, ошондуктан түзүү скрипти толук айдалбаган деталды четке кага алат.

:::note
`.swb` макросунун чыгышы көпчүлүк цехтер колдонгон деталь моделдөөчү программа үчүн: ошол программада иштетилсе, деталь ал жерде түзүлөт. Ал бул жерде ал программада иштетилген эмес (биздин серверлерде жок), ошондуктан аны сыналбаган деп эсептеңиз.
:::
