د احتیاط سره ماډلول د تڼیو پر ځای د ډیسپلین پورې ډېر اړه لري. هغه پرزه چې په متن کې لیکل شوې وي کولی شي ولوستل شي، کتنه وشي، کرښه په کرښه پرتله شي او د سکریپټ په واسطه بیا جوړه شي. PartCraft دواړه لارې ته کار کوي: هره پرزه کولی شي د سکریپټ په توګه ولیکل شي، او سکریپټ پرزه جوړوي.

## په اپلیکیشن کې

د {{ui:پارامترونه}} ټب کې، لاندې **سکریپټ**:

- {{ui:د سکریپټ په توګه خوندي کول}} خلاصه پرزه د `<name>.pcscript` په توګه ډاونلوډوي.
- {{ui:سکریپټ پرانیستل}} د `.pcscript` فایل څخه پرزه جوړوي. تېروتنه د هغې د کرښې شمېره سره راپورته کېږي او هېڅ نه بدلېږي.

## د سکریپټ بڼه

```
pcscript 1
part "Bracket"
  resolution 64

param width = 120
  note Plate width
param thick = 8
param bolt = 8.5
param margin = bolt * 1.5

sketch Plate
  on top
  point a 0, 0
  point b 120, 0
  point c 120, 60
  point d 0, 60
  line bottom a b
  line right b c
  line top c d
  line left d a
  coincident a O
  horizontal bottom
  horizontal top
  vertical left
  vertical right
  distance bottom = width
  distance left 60

extrude Base
  sketch Plate
  depth = thick

sketch HoleCentres
  on face Base end
  point h1 12, 12
  hdistance O h1 = margin
  vdistance O h1 = margin

hole Bolts
  sketch HoleCentres
  d = bolt
  through
```

قواعد:

- هغه کرښه چې په کیڼ څنډه پیلېږي یو بیان پیلوي: `pcscript`، `part`، `param`، د ځانګړتیا ډول (`sketch`، `extrude`، `revolve`، `hole`، `lpattern`، `cpattern`، `mirror`، `fillet`، `chamfer`، `shell`، `import` او نور نوي ډولونه) چې نوم یې تعقیبوي، یا `rollback <feature>`.
- دننه ټکی شوې کرښې د پورتني بیان امستنې دي. یوازې امستنه (`through`، `reverse`، `suppressed`) یعنې هو.
- د شمېرې امستنه یا یوه شمېره ده، یا `=` او یوه څرګندونه، چې معادله جوړوي: `depth = thick`.
- په سکېچ کې: `on` الوتکه نوموي (`front`، `top`، `right`، `face Base end`، `face Revolve1 side l3`)؛ هندسه `point <name> x, y`، `line <name> <point> <point>`، `circle <name> <centre> <radius>`، `arc <name> <centre> <start> <end>` (د ساعت د ګرځېدو مخالف) یا `spline <name> fit|control <points>` ده؛ اړیکې د خپل ډول او هغو نومونو سره دي چې نښلوي (`O` مبدا ده)؛ یوه اندازه د خپل ارزښت یا `= expression` سره پای ته رسېږي.
- اختیاري امستنې د هندسې یا اړیکې کرښې په پای کې د مربع قوسونو کې ځای لري، د `;` په واسطه جلا: `[construction]`، `[side -1; label 5, 3]`.
- `#` یوه تبصره پیلوي (د کرښې په پیل کې یا له یوه ځای وروسته). هغه نومونه چې ځایونه لري په "ډبل کوټیشن" کې ځای نیسي.
- د ځانګړتیا پیژندګلي د f1 څخه د لیکلو په ترتیب شمېرل کېږي. د څنډې او مخ حوالې ورڅخه کار اخلي، د بېلګې په توګه `edge f2.side:l3 f2.end [at 50, 0, 10]`.
- هغه امستنې چې بڼه یې لپاره کلمې نه لري د `json` او یوه ارزښت په توګه لیکل کېږي؛ همغسې بیرته لوستل کېږي.

له اپلیکیشن څخه خوندي شوی، سکریپټ هره امستنه لري، نو همغه پرزه په توګه پرانیستل کېږي. وارد شوی STEP جامد د اپلیکیشن څخه د سکریپټ دننه لیکل کېږي، او د کمانډ کرښې څخه د `step-file` په نوم بېل `.step` فایل په توګه.

## د کمانډ کرښې وسیله

وسیله په کمپیوټر کې د Node.js 24 سره، د CadCraft سرچینې له کاپي څخه چلېږي: `node tools/partcraft-cli/partcraft.mjs <command>`. دا د پراختیا کوونکي وسیله ده او د اپلیکیشن ورته ماډولونه کاروي. پرزې `.partcraft.json` فایلونه یا `.pcscript` سکریپټونه دي.

| کمانډ | څه کوي |
|---|---|
| `info <part>` | ځانګړتیاوې، پارامترونه، د بېرته ګرځیدو بار، د جوړ شوي جامد حجم او اندازه |
| `params <part>` | هر پارامتر او معادله د خپل ارزښت سره |
| `set <part> width=150 Base.depth==thick` | مخته: پارامترونه بدلول، شمېرې نښلول (`==` یا یوه څرګندونه)، ساده شمېرې ټاکل |
| `drive <part> Base.depth=12` | شا ته: هغه پارامتر حل کول چې د یوې چلول شوې شمېرې تر شا دی (`--prefer width` یوه ټاکي) |
| `build <part> --out x.step` | `.step`، `.stl`، `.3mf`، `.json`، `.pcscript` یا ماکرو (`.swb`) لیکي |
| `build <part> --table sizes.csv --out-dir sizes` | د ډیزاین جدول د هر قطار لپاره یو فایل |
| `variants <part> --out-dir d` یا `--zip f.zip` | هره ترتیب د STEP، IFC، DWG او مخکتنې، د ډولونو جدول او د کتابتون توکي په توګه (`--only "A,B"`، `--formats step,ifc,dwg,preview`، `--no-item`)؛ وګورئ [د ډولونو بسته جوړول](topic:variant-pack) |
| `script <in.pcscript> -o part.json` | له سکریپټ څخه پرزې ته |
| `to-script <part> -o part.pcscript` | له پرزې څخه سکریپټ ته |
| `rollback <part> [<feature>]`، `forward <part> [--end]` | د فایل کې د بېرته ګرځیدو بار حرکت کول |
| `check <part> [--strict]` | د ډیسپلین ازموینه (لاندې) |

`build` همدارنګه `--set name=value` (یوازې د دې جوړونې لپاره) او `--upto <feature>` منی. هر کمانډ `--json` منی. د وتلو کودونه: 0 ښه، 1 یوه ستونزه وموندل شوه، 2 کمانډ غلط ولیکل شو. سکریپټ هېڅکله په خپل ځای کې نه بدلېږي: د بدل شوي کاپي د خوندي کولو لپاره `-o` ورکړئ.

## ازموینه

`check` هغه څه راپور ورکوي چې پرزه وروسته بدلول ستونزمن کوي:

| موندنه | شمېرل کېږي د |
|---|---|
| سکېچ چې ډېر تعریف شوی وي (ټکرې یا تکراري اړیکې) | تېروتنه |
| ځانګړتیا چې نه جوړېږي | تېروتنه |
| پارامتر یا معادله چې تېروتنه ولري، یا پارامترونه چې یو بل کاروي | تېروتنه |
| سکېچ چې کم تعریف شوی وي، د خپلو ازادو درجو سره | خبرداری |
| شمېرې چې په ځانګړتیاوو او اندازو کې مستقیم ولیکل شوي او هېڅ پارامتر یې نه چلوي | خبرداری |
| هغه پارامتر چې هېڅ شی یې نه کاروي | خبرداری |
| پټه شوې ځانګړتیا؛ د بېرته ګرځیدو بار په پای کې نه وي | خبرداری |

`--strict` هر خبرداری تېروتنه جوړوي، نو د جوړونې سکریپټ کولی شي هغه پرزه رد کړي چې بشپړ نه وي چلول شوې.

:::note
د `.swb` ماکرو ځواب د هغه پرزې ماډلر لپاره دی چې ډېری ورکشاپونه کاروي: په همغه پروګرام کې چلېږي، هلته پرزه جوړوي. دلته په هغه پروګرام کې نه دی چلول شوی (زموږ په سرور کې شتون نه لري)، نو داسې وګڼئ چې ازمول شوی نه دی.
:::
