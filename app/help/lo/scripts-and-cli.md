ການຈຳລອງແບບຢ່າງລະມັດລະວັງແມ່ນເລື່ອງວິໄນຫຼາຍກວ່າປຸ່ມ. ຊິ້ນສ່ວນທີ່ຂຽນເປັນຂໍ້ຄວາມສາມາດຖືກອ່ານ, ກວດທານ, ປຽບທຽບເທື່ອລະບັນທັດ ແລະ ສ້າງໃໝ່ດ້ວຍສະຄຣິບ. PartCraft ເຮັດໄດ້ທັງສອງທິດທາງ: ຊິ້ນສ່ວນໃດກໍໄດ້ສາມາດຂຽນເປັນສະຄຣິບ, ແລະ ສະຄຣິບສ້າງຊິ້ນສ່ວນນັ້ນ.

## ໃນແອັບ

ໃນແຖບ {{ui:Parameters}}, ພາຍໃຕ້ **ສະຄຣິບ**:

- {{ui:Save as script}} ດາວໂຫຼດຊິ້ນສ່ວນທີ່ເປີດຢູ່ເປັນ `<name>.pcscript`.
- {{ui:Open script}} ສ້າງຊິ້ນສ່ວນຈາກໄຟລ໌ `.pcscript`. ຂໍ້ຜິດພາດຈະຖືກລາຍງານພ້ອມເລກແຖວ ແລະ ບໍ່ມີຫຍັງຖືກແທນທີ່.

## ຮູບແບບສະຄຣິບ

```
pcscript 1
part "Bracket"
  resolution 64

param width = 120
  note Plate width
param thick = 8
param bolt = 8.5
param margin = bolt * 1.5

sketch Plate
  on top
  point a 0, 0
  point b 120, 0
  point c 120, 60
  point d 0, 60
  line bottom a b
  line right b c
  line top c d
  line left d a
  coincident a O
  horizontal bottom
  horizontal top
  vertical left
  vertical right
  distance bottom = width
  distance left 60

extrude Base
  sketch Plate
  depth = thick

sketch HoleCentres
  on face Base end
  point h1 12, 12
  hdistance O h1 = margin
  vdistance O h1 = margin

hole Bolts
  sketch HoleCentres
  d = bolt
  through
```

ກົດເກນ:

- ບັນທັດທີ່ຢູ່ຂອບຊ້າຍເລີ່ມຄຳສັ່ງ: `pcscript`, `part`, `param`, ປະເພດຂອງຟີເຈີ (`sketch`, `extrude`, `revolve`, `hole`, `lpattern`, `cpattern`, `mirror`, `fillet`, `chamfer`, `shell`, `import` ແລະ ປະເພດໃໝ່ກວ່າ) ຕາມດ້ວຍຊື່ຂອງມັນ, ຫຼື `rollback <feature>`.
- ບັນທັດທີ່ຍ່ອຍເຂົ້າໄປ (indent) ແມ່ນການຕັ້ງຄ່າຂອງຄຳສັ່ງຂ້າງເທິງ. ການຕັ້ງຄ່າດ່ຽວໆ (`through`, `reverse`, `suppressed`) ໝາຍເຖິງ ແມ່ນ.
- ການຕັ້ງຄ່າຕົວເລກແມ່ນຕົວເລກ, ຫຼື `=` ແລະ ນິພົນ, ເຊິ່ງກາຍເປັນສົມຜົນ: `depth = thick`.
- ໃນພາບຮ່າງ: `on` ລະບຸຍົນ (`front`, `top`, `right`, `face Base end`, `face Revolve1 side l3`); ເລຂາຄະນິດແມ່ນ `point <name> x, y`, `line <name> <point> <point>`, `circle <name> <centre> <radius>`, `arc <name> <centre> <start> <end>` (ທວນເຂັມໂມງ) ຫຼື `spline <name> fit|control <points>`; ຄວາມສຳພັນແມ່ນປະເພດຂອງມັນ ແລະ ຊື່ທີ່ມັນເຊື່ອມ (`O` ແມ່ນຈຸດກຳເນີດ); ຂະໜາດຈົບດ້ວຍຄ່າຂອງມັນ ຫຼື `= expression`.
- ການຕັ້ງຄ່າທາງເລືອກຂອງບັນທັດເລຂາຄະນິດ ຫຼື ຄວາມສຳພັນ ຢູ່ທ້າຍໃນວົງເລັບເຫຼ່ຍ, ແຍກດ້ວຍ `;`: `[construction]`, `[side -1; label 5, 3]`.
- `#` ເລີ່ມໝາຍເຫດ (ຕົ້ນບັນທັດ ຫຼື ຫຼັງຊ່ອງວ່າງ). ຊື່ທີ່ມີຊ່ອງວ່າງໃສ່ໄວ້ໃນເຄື່ອງໝາຍຄຳເວົ້າຄູ່ "...".
- ເລກຟີເຈີນັບຈາກ f1 ຕາມລຳດັບທີ່ຂຽນ. ການອ້າງອີງຂອບ ແລະ ໜ້າໃຊ້ເລກເຫຼົ່ານີ້, ຕົວຢ່າງ `edge f2.side:l3 f2.end [at 50, 0, 10]`.
- ການຕັ້ງຄ່າທີ່ຮູບແບບບໍ່ມີຄຳສັບ ຂຽນເປັນ `json` ແລະ ຄ່າ; ມັນຖືກອ່ານກັບຄືນໃນແບບເດີມ.

ເມື່ອບັນທຶກຈາກແອັບ, ສະຄຣິບລວມທຸກການຕັ້ງຄ່າ, ສະນັ້ນມັນເປີດເປັນຊິ້ນສ່ວນດຽວກັນ. solid STEP ທີ່ນຳເຂົ້າຖືກຂຽນໄວ້ໃນສະຄຣິບຈາກແອັບ, ແລະ ເປັນໄຟລ໌ `.step` ແຍກຕ່າງຫາກທີ່ລະບຸດ້ວຍ `step-file` ຈາກຄຳສັ່ງເສັ້ນ.

## ເຄື່ອງມືຄຳສັ່ງເສັ້ນ

ເຄື່ອງມືນີ້ເຮັດວຽກໃນຄອມພິວເຕີທີ່ມີ Node.js 24, ຈາກສຳເນົາຂອງ source CadCraft: `node tools/partcraft-cli/partcraft.mjs <command>`. ມັນເປັນເຄື່ອງມືສຳລັບນັກພັດທະນາ ແລະ ໃຊ້ໂມດູນດຽວກັນກັບແອັບ. ຊິ້ນສ່ວນແມ່ນໄຟລ໌ `.partcraft.json` ຫຼື ສະຄຣິບ `.pcscript`.

| ຄຳສັ່ງ | ມັນເຮັດຫຍັງ |
|---|---|
| `info <part>` | ຟີເຈີ, ພາລາມິເຕີ, ແຖບ rollback, ປະລິມາດ ແລະ ຂະໜາດຂອງ solid ທີ່ສ້າງແລ້ວ |
| `params <part>` | ທຸກພາລາມິເຕີ ແລະ ສົມຜົນ ພ້ອມຄ່າຂອງມັນ |
| `set <part> width=150 Base.depth==thick` | ໄປໜ້າ: ປ່ຽນພາລາມິເຕີ, ເຊື່ອມຕົວເລກ (`==` ຫຼື ນິພົນ), ຕັ້ງຕົວເລກທຳມະດາ |
| `drive <part> Base.depth=12` | ຍ້ອນຫຼັງ: ແກ້ພາລາມິເຕີທີ່ຢູ່ເບື້ອງຫຼັງຕົວເລກທີ່ຖືກຂັບເຄື່ອນ (`--prefer width` ເລືອກໜຶ່ງ) |
| `build <part> --out x.step` | ຂຽນ `.step`, `.stl`, `.3mf`, `.json`, `.pcscript` ຫຼື macro (`.swb`) |
| `build <part> --table sizes.csv --out-dir sizes` | ໄຟລ໌ໜຶ່ງຕໍ່ແຖວຂອງຕາຕະລາງການອອກແບບ |
| `variants <part> --out-dir d` ຫຼື `--zip f.zip` | ທຸກການຕັ້ງຄ່າເປັນ STEP, IFC, DWG ແລະ ຕົວຢ່າງ, ຕາຕະລາງ variant ແລະ ລາຍການຄັງ (`--only "A,B"`, `--formats step,ifc,dwg,preview`, `--no-item`); ເບິ່ງ [ສ້າງຊຸດ variant](topic:variant-pack) |
| `script <in.pcscript> -o part.json` | ສະຄຣິບ ເປັນ ຊິ້ນສ່ວນ |
| `to-script <part> -o part.pcscript` | ຊິ້ນສ່ວນ ເປັນ ສະຄຣິບ |
| `rollback <part> [<feature>]`, `forward <part> [--end]` | ຍ້າຍແຖບ rollback ໃນໄຟລ໌ |
| `check <part> [--strict]` | ການກວດວິໄນ (ຂ້າງລຸ່ມ) |

`build` ຍັງຮັບ `--set name=value` (ສຳລັບການສ້າງຄັ້ງນີ້ເທົ່ານັ້ນ) ແລະ `--upto <feature>`. ທຸກຄຳສັ່ງຮັບ `--json`. ລະຫັດອອກ: 0 ປົກກະຕິ, 1 ພົບບັນຫາ, 2 ພິມຄຳສັ່ງຜິດ. ສະຄຣິບບໍ່ຖືກຂຽນທັບໃນບ່ອນເດີມ: ໃຫ້ `-o` ເພື່ອບັນທຶກສຳເນົາທີ່ປ່ຽນແລ້ວ.

## ການກວດສອບ

`check` ລາຍງານສິ່ງທີ່ເຮັດໃຫ້ຊິ້ນສ່ວນແກ້ໄຂຍາກໃນພາຍຫຼັງ:

| ສິ່ງທີ່ພົບ | ນັບເປັນ |
|---|---|
| ພາບຮ່າງທີ່ນິຍາມເກີນ (ຄວາມສຳພັນຂັດກັນ ຫຼື ຊ້ຳກັນ) | ຂໍ້ຜິດພາດ |
| ຟີເຈີທີ່ສ້າງບໍ່ໄດ້ | ຂໍ້ຜິດພາດ |
| ພາລາມິເຕີ ຫຼື ສົມຜົນທີ່ມີຂໍ້ຜິດພາດ, ຫຼື ພາລາມິເຕີທີ່ໃຊ້ກັນເອງ | ຂໍ້ຜິດພາດ |
| ພາບຮ່າງທີ່ນິຍາມບໍ່ພຽງພໍ, ພ້ອມອົງສາອິດສະຫຼະຂອງມັນ | ຄຳເຕືອນ |
| ຕົວເລກທີ່ພິມໃສ່ໂດຍກົງໃນຟີເຈີ ແລະ ຂະໜາດ ທີ່ບໍ່ມີພາລາມິເຕີໃດຂັບເຄື່ອນ | ຄຳເຕືອນ |
| ພາລາມິເຕີທີ່ບໍ່ມີໃຜໃຊ້ | ຄຳເຕືອນ |
| ຟີເຈີທີ່ຖືກລະງັບ; ແຖບ rollback ບໍ່ຢູ່ທ້າຍ | ຄຳເຕືອນ |

`--strict` ເຮັດໃຫ້ທຸກຄຳເຕືອນເປັນຂໍ້ຜິດພາດ, ສະນັ້ນສະຄຣິບສ້າງສາມາດປະຕິເສດຊິ້ນສ່ວນທີ່ບໍ່ໄດ້ຖືກຂັບເຄື່ອນຢ່າງສົມບູນ.

:::note
ຜົນ macro `.swb` ແມ່ນສຳລັບຜູ້ສ້າງແບບຊິ້ນສ່ວນທີ່ຮ້ານສ່ວນໃຫຍ່ໃຊ້: ເມື່ອເຮັດວຽກພາຍໃນໂປຣແກຣມນັ້ນ, ມັນຈະສ້າງຊິ້ນສ່ວນຢູ່ທີ່ນັ້ນ. ມັນຍັງບໍ່ໄດ້ຖືກແລ່ນໃນໂປຣແກຣມນັ້ນຢູ່ທີ່ນີ້ (ມັນບໍ່ມີໃຫ້ໃຊ້ໃນເຊີຟເວີຂອງພວກເຮົາ), ສະນັ້ນໃຫ້ຖືວ່າມັນຍັງບໍ່ໄດ້ທົດສອບ.
:::
