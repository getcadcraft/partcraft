Акуратнае мадэляванне — больш пытанне дысцыпліны, чым кнопак. Дэталь, запісаная як тэкст, можна чытаць, правяраць, параўноўваць радок за радком і перабудоўваць скриптам. PartCraft працуе ў абодва бакі: любую дэталь можна запісаць як скрыпт, а скрыпт пабудуе дэталь.

## У праграме

На ўкладцы {{ui:Parameters}}, у раздзеле **Script**:

- {{ui:Save as script}} спампоўвае адкрытую дэталь як `<назва>.pcscript`.
- {{ui:Open script}} будуе дэталь з файла `.pcscript`. Памылка паведамляецца з нумарам радка, і нічога не замяняецца.

## Фармат скрыпта

```
pcscript 1
part "Bracket"
  resolution 64

param width = 120
  note Plate width
param thick = 8
param bolt = 8.5
param margin = bolt * 1.5

sketch Plate
  on top
  point a 0, 0
  point b 120, 0
  point c 120, 60
  point d 0, 60
  line bottom a b
  line right b c
  line top c d
  line left d a
  coincident a O
  horizontal bottom
  horizontal top
  vertical left
  vertical right
  distance bottom = width
  distance left 60

extrude Base
  sketch Plate
  depth = thick

sketch HoleCentres
  on face Base end
  point h1 12, 12
  hdistance O h1 = margin
  vdistance O h1 = margin

hole Bolts
  sketch HoleCentres
  d = bolt
  through
```

Правілы:

- Радок, які пачынаецца з левага краю, пачынае аператар: `pcscript`, `part`, `param`, тып элемента (`sketch`, `extrude`, `revolve`, `hole`, `lpattern`, `cpattern`, `mirror`, `fillet`, `chamfer`, `shell`, `import` і больш новыя тыпы), за якім ідзе яго назва, або `rollback <элемент>`.
- Радкі з водступам — гэта налады аператара вышэй. Налада без значэння (`through`, `reverse`, `suppressed`) азначае «так».
- Лікавая налада — гэта лік або `=` і выраз, што ўтварае раўнанне: `depth = thick`.
- У эскізе: `on` называе плоскасць (`front`, `top`, `right`, `face Base end`, `face Revolve1 side l3`); геаметрыя — гэта `point <назва> x, y`, `line <назва> <кропка> <кропка>`, `circle <назва> <цэнтр> <радыус>`, `arc <назва> <цэнтр> <пачатак> <канец>` (супраць гадзіннікавай стрэлкі) або `spline <назва> fit|control <кропкі>`; сувязі — гэта іх тып і назвы, якія яны звязваюць (`O` — пачатак каардынат); памер заканчваецца сваім значэннем або `= выраз`.
- Неабавязковыя налады радка геаметрыі або сувязі пішуцца ў квадратных дужках у канцы, падзеленыя `;`: `[construction]`, `[side -1; label 5, 3]`.
- `#` пачынае каментарый (на пачатку радка або пасля прабела). Назвы з прабеламі пішуцца ў «падвойных двукоснеках».
- Ідэнтыфікатары элементаў лічацца з f1 у парадку запісу. Пасылкі на рэбры і грані выкарыстоўваюць іх, напрыклад `edge f2.side:l3 f2.end [at 50, 0, 10]`.
- Налады, для якіх фармат не мае слоў, пішуцца як `json` і значэнне; іх чытаюць назад без змяненняў.

Пры захаванні з праграмы скрыпт змяшчае ўсе налады, таму ён адкрываецца як тая ж дэталь. Імпартаванае цвёрдае цела STEP запісваецца ўнутры скрыпта з праграмы, а з каманднага радка — як асобны файл `.step`, названы праз `step-file`.

## Інструмент каманднага радка

Інструмент працуе на кампутары з Node.js 24, з копіі зыходнага кода CadCraft: `node tools/partcraft-cli/partcraft.mjs <каманда>`. Гэта інструмент распрацоўшчыка, ён выкарыстоўвае тыя ж модулі, што і праграма. Дэталі — гэта файлы `.partcraft.json` або скрыпты `.pcscript`.

| Каманда | Што робіць |
|---|---|
| `info <дэталь>` | Элементы, параметры, панэль адкату, аб'ём і памер пабудаванага цела |
| `params <дэталь>` | Кожны параметр і раўнанне з яго значэннем |
| `set <дэталь> width=150 Base.depth==thick` | Прамы ход: змяніць параметры, звязаць лікі (`==` або выраз), задаць простыя лікі |
| `drive <дэталь> Base.depth=12` | Зваротны ход: вылічыць параметр, які стаіць за кіруемым лікам (`--prefer width` выбірае адзін) |
| `build <дэталь> --out x.step` | Запісвае `.step`, `.stl`, `.3mf`, `.json`, `.pcscript` або макрас (`.swb`) |
| `build <дэталь> --table sizes.csv --out-dir sizes` | Адзін файл на кожны радок табліцы канструкцый |
| `variants <дэталь> --out-dir d` або `--zip f.zip` | Кожная канфігурацыя як STEP, IFC, DWG і папярэдні прагляд, табліца варыянтаў і элемент бібліятэкі (`--only "A,B"`, `--formats step,ifc,dwg,preview`, `--no-item`); гл. [Стварыць пакет варыянтаў](topic:variant-pack) |
| `script <in.pcscript> -o part.json` | Скрыпт у дэталь |
| `to-script <дэталь> -o part.pcscript` | Дэталь у скрыпт |
| `rollback <дэталь> [<элемент>]`, `forward <дэталь> [--end]` | Перасоўвае панэль адкату ў файле |
| `check <дэталь> [--strict]` | Праверка дысцыпліны (ніжэй) |

`build` таксама прымае `--set name=value` (толькі для гэтай зборкі) і `--upto <элемент>`. Кожная каманда прымае `--json`. Коды выхаду: 0 — добра, 1 — знойдзена праблема, 2 — каманда набрана няправільна. Скрыпт ніколі не перапісваецца на месцы: каб захаваць зменены варыянт, задайце `-o`.

## Праверка

`check` паведамляе, што будзе ўскладняць змяненне дэталі ў будучыні:

| Вынік | Лічыцца як |
|---|---|
| Эскіз, які перавызначаны (канфліктныя або паўтораныя сувязі) | памылка |
| Элемент, які не будуецца | памылка |
| Параметр або раўнанне з памылкай, альбо параметры, якія ўжываюць адзін аднаго | памылка |
| Эскіз, які недавызначаны, з яго ступенямі свабоды | папярэджанне |
| Лікі, уведзеныя напрамую ў элементы і памеры, якія ніводзін параметр не кіруе | папярэджанне |
| Параметр, які ніхто не выкарыстоўвае | папярэджанне |
| Падаўлены элемент; панэль адкату не ў канцы | папярэджанне |

`--strict` ператварае кожнае папярэджанне ў памылку, так што скрыпт пабудовы можа адмовіцца ад дэталі, якая не цалкам кіруецца параметрамі.

:::note
Вынік макраса `.swb` прызначаны для мадэлёра дэталяў, якім карыстаецца большасць майстэрняў: калі яго запусціць у той праграме, ён пабудуе дэталь там. Тут яго не запускалі ў той праграме (яна недаступная на нашых серверах), таму ставіцеся да яго як да неправераінага.
:::
