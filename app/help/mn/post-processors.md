Нэг багажийн замыг өөр өөр удирдлагад өөр байдлаар бичих шаардлагатай: мөрийн дугаартай эсвэл дугааргүй, `M6` эсвэл түр зогсолт, `G28` эсвэл `G53`, `M30` эсвэл `M2`. **Пост** нь үүнийг хэрхэн хийхийг хэлэх богино текст юм. PartCraft-ийн гурван суулгагдсан пост (Fanuc маягийн, GRBL ба LinuxCNC) энэ форматаар бичигдсэн тул өөрийн постыг тэдгээрийн аль нэгээс хуулж эхлүүлж болно.

Боловсруулахаасаа өмнө машиныхаа өөрийн симулятор дээр гаралтыг шалгаж, эхлээд материалын дээгүүр агаарт туршина уу. Суулгагдсан постууд энэ формат гарахаас өмнөх яг адилаар бичдэг (тест нь хэдэн зуун програмын гаралтыг байтаар нь харьцуулдаг), гэхдээ энд юу ч таны машин дээр баталгаажаагүй. Таны өөрчилсөн пост таны өөрийн баталгаа шаарддаг.

## Нэг пост үүсгэх

Manufacture-ийн **Post** доор:

- Суулгагдсан удирдлага дээр {{ui:Постыг засах…}} нь таны **өөрийн хуулбар**-ыг нээнэ. Өөрийн постон дээр бол тэр постыг нээнэ.
- {{ui:Шинэ пост…}} нь бүх үйл явдал агуулсан жижиг хоосон постоор эхэлнэ.
- {{ui:Постын файл импортлох…}} нь `.cpost` текст файлыг уншина (засварлагчийн **Файл болгон хадгалах…**-аас авсан файл).

Засварлагч текстийг, пост уншигдаж байгаа эсэхийг (мөн аль мөр буруу байгааг) харуулж, таны бичих бүрт постын бичих G-code-ийг харуулна. **Урьдчилан харах** нь үйл явдал бүрийг ажиллуулдаг жижиг жишээ програм эсвэл энэ эд ангийн өөрийн програмыг сонгоно. {{ui:Хадгалах}} нь постыг эд ангийн файлд хадгалж (20 хүртэл пост), удирдлага болгон сонгоно. Постууд эд ангийн хамт явдаг; өөр эд ангид ашиглахын тулд файл болгон хадгалаад тэнд импортлоно.

## Пост ямар харагддаг вэ

```
post mymill
name My mill (.nc)
extension nc
line-numbers off
decimal-point no
canned-cycles no
modal motion G0 G1 G2 G3

on start
  comment Program {program}: {name}
  emit G21 G90 G17
end

on tool-change
  emit T{tool.number} M6
end

on rapid
  if moved
    emit G0~ X{x}~ Y{y}~ Z{z}~
  end
end
```

`//`-ээр эхэлсэн мөрүүд болон хоосон мөрүүд үл тоомсорлогдоно. Дээд талд тохиргоонууд байна; дараа нь үйл явдал бүрт нэг `on <event>` блок, `end`-ээр хаагдсан. Орхигдсон үйл явдал юу ч бичихгүй.

| Тохиргоо | Утга |
|---|---|
| `post <id>` | Постын id: үсэг, цифр, `-` ба `_` |
| `name <text>` | Удирдлагын жагсаалтад харагдах нэр |
| `extension <ext>` | Файлын өргөтгөл: nc, ngc, tap … |
| `line-numbers 10` / `off` | Бүх `emit` мөрөнд `N10`, `N20` … эсвэл огт байхгүй |
| `decimal-point yes` / `no` | `10.` гэхийн оронд `10` (тайлбарт цэг огт орохгүй) |
| `canned-cycles yes` / `no` | `no`: нүхнүүд нь илэрхийлж буй G0/G1 хөдөлгөөн болгож бичигдэнэ |
| `modal <group> <words>` | Бүлгийн үгс (`modal motion G0 G1 G2 G3`) зөвхөн өөрчлөгдөх үед л бичигдэнэ |

## Үйл явдлууд

Програмын хувьд тэд дараах дарааллаар ажиллана: `start`; дараа нь үйлдэл бүрт `operation`, багаж солигдох үед `tool-change`, хурд өөрчлөгдөх үед `spindle`, эхний цэг рүү хөдөлгөөн (эхний `rapid`-ийн өмнө) `approach`, `coolant-on`; дараа нь түүний хөдөлгөөнүүд `rapid`, `feed` ба `arc` гэж, мөн мөчлөг бүр `cycle-start`, нүх бүрт нэг `cycle-hole` ба `cycle-end` гэж; эцэст нь `end`.

Үйл явдал бүр өөрийн төрлийн хөдөлгөөний хувьсагчдыг `{name}` хэлбэрээр ашиглаж болно: програм (`name`, `program`, `setup.axis`, `setup.origin`, `setup.coolant`), түүхий эд (`stock.kind`, `stock.d`, `stock.sx`, `stock.sy`, `stock.sz`, `stock.minx` … `stock.maxz`), багаж (`tool.number`, `tool.desc`, `tool.kind`, `tool.d`, `tool.flutes`, `tool.fluteLen`), үйлдэл (`op.name`, `op.type`), `rpm`, хөдөлгөөний цэг (`x`, `y`, `z`, `f`, мөн тэнхлэг өөрчлөгдсөн бол `moved`: true), нуман (`arc.g` 2 эсвэл 3, `arc.i`, `arc.j`, `arc.cx`, `arc.cy`) ба нүх (`hole.x`, `hole.y`, `hole.z`, `hole.r`, `hole.q`, `hole.return`, `hole.first`, `cycle.kind`, `cycle.init`, `feed`). Засварлагчийн **Үйл явдал ба хувьсагч** жагсаалт аль үйл явдал аль хувьсагчийг харахыг харуулна. Унших ба тохируулж болох төлөв: `cool`, `offset`, мөн `at.x`, `at.y`, `at.z`, `at.f` (хамгийн сүүлд бичигдсэн утгууд).

## Мэдэгдлүүд

| Мэдэгдэл | Юу хийдэг |
|---|---|
| `raw TEXT` | Мөрийг яг бичсэнээр (мөрийн дугааргүй) |
| `comment TEXT` | `(TEXT)` болгоно, ASCII-гаас бусад тэмдэг ба хаалтыг хасна |
| `emit WORD WORD …` | Үгсийн мөр; хоосон гарсан үгсийг орхино; үг байхгүй бол мөр байхгүй |
| `word WORD …` | Бүтээгдэж буй мөрөнд үг нэмнэ; хоосон `emit` тэр мөрийг дуусгана |
| `if EXPR` … `else` … `end` | Нөхцөл: `a == b`, `a != b`, `not a`, `a and b`, `a or b`, `a??b` (a, эсвэл b) |
| `for tool in tools` … `end` | Програмын ашигладаг багаж бүрт нэг удаа |
| `set NAME EXPR` | Утга санах (`set offset tool.number`) |
| `reset NAME …` | Модал үгсийг мартах (бүлэг, `Z` гэх мэт тэнхлэгийн үсэг, эсвэл `at.z`) |
| `do rapid X Y Z` | Нэг цэгт `rapid` үйл явдлыг ажиллуулна |

Үг нь бичсэн текст ба `{variable|filter}` нүхнүүдээс бүрдэнэ. Шүүлтүүрүүд: `upper`, `lower`, `pad:N` (тэгээр дүүргэх), `cut:N` (эхний N тэмдэг), `safe` (тайлбарт аюулгүй ASCII) ба `int`. `~`-ээр төгссөн үг **модал** байна: зүгээр сүүлд бичсэнээсээ ялгаатай үед л бичигдэнэ (`G1~`, `X{x}~`). `~!`-ээр төгссөн үг бүр дахин бичигдэж, мөн санагдана. Хувьсагч биш нэр нь энгийн текст (`G81`, `mist`). Тоонууд 0.001 мм хүртэл бүхэлдэж, араас нь тэг бичигдэхгүй.

## Пост юу хийж чадахгүй вэ

Пост зөвхөн хөдөлгөөнүүд хэрхэн бичигдэхийг шийднэ, өөр юу ч биш. Энэ нь багажны замыг өөрчилж чадахгүй, үйлдлүүдийг эрэмбэлж чадахгүй, нуманг хуваахгүй, тэнхлэг нэмэхгүй, таны машины явах зай эсвэл кинематикийг мэддэггүй, координатад арифметик хийдэггүй (`+` байхгүй). Хайлт (probing), багажийн амьдрал ба дэд програмын мөчлөг, 4-р ба 5-р тэнхлэгийн гаралт, токарийн код бүтээгдээгүй. Өөр програмын `.cps` маягийн пост файлыг ачаалах боломжгүй: энэ бол өөр, илүү энгийн формат.
