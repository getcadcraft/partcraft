Ուշադիր մոդելավորումն ավելի շատ կարգապահության, քան կոճակների մասին է. տեքստի տեսքով գրված դետալը կարելի է կարդալ, վերանայել, համեմատել տող առ տող և վերակառուցել սցենարով։ PartCraft-ը աշխատում է երկու ուղղությամբ. ցանկացած դետալ կարող է գրվել որպես սցենար, և սցենարը կառուցում է դետալը։

## Ծրագրում

{{ui:Պարամետրեր}}-ի ներդիրում, **Սցենար**-ի տակ՝

- {{ui:Պահել որպես սցենար}}-ը ներբեռնում է բաց դետալը որպես `<անուն>.pcscript`։
- {{ui:Բացել սցենարը}}-ը կառուցում է դետալը `.pcscript` ֆայլից։ Սխալը հայտնվում է իր տողի համարով, և ոչինչ չի փոխարինվում։

## Սցենարի ձևաչափ

```
pcscript 1
part "Bracket"
  resolution 64

param width = 120
  note Plate width
param thick = 8
param bolt = 8.5
param margin = bolt * 1.5

sketch Plate
  on top
  point a 0, 0
  point b 120, 0
  point c 120, 60
  point d 0, 60
  line bottom a b
  line right b c
  line top c d
  line left d a
  coincident a O
  horizontal bottom
  horizontal top
  vertical left
  vertical right
  distance bottom = width
  distance left 60

extrude Base
  sketch Plate
  depth = thick

sketch HoleCentres
  on face Base end
  point h1 12, 12
  hdistance O h1 = margin
  vdistance O h1 = margin

hole Bolts
  sketch HoleCentres
  d = bolt
  through
```

Կանոնները՝

- Ձախ եզրից սկսվող տողը սկսում է հայտարարություն. `pcscript`, `part`, `param`, գործառույթի տեսակ (`sketch`, `extrude`, `revolve`, `hole`, `lpattern`, `cpattern`, `mirror`, `fillet`, `chamfer`, `shell`, `import` և նորերը), որին հաջորդում է իր անունը, կամ `rollback <feature>`։
- Ներքև մտած տողերը վերևի հայտարարության կարգավորումներն են. առանձին կարգավորումը (`through`, `reverse`, `suppressed`) նշանակում է այո։
- Թվային կարգավորումը թիվ է, կամ `=` և արտահայտություն, որը դարձնում է հավասարում. `depth = thick`։
- Էսքիզում `on`-ը նշում է հարթությունը (`front`, `top`, `right`, `face Base end`, `face Revolve1 side l3`)։ Երկրաչափությունը` `point <name> x, y`, `line <name> <point> <point>`, `circle <name> <centre> <radius>`, `arc <name> <centre> <start> <end>` (ժամացույցի սլաքին հակառակ) կամ `spline <name> fit|control <points>`։ Կապերը իրենց տեսակն ու միացրած անուններն են (`O`-ն սկզբնակետն է)։ Չափը վերջանում է իր արժեքով կամ `= expression`-ով։
- Երկրաչափության կամ կապի տողի կամընտիր կարգավորումները գրվում են վերջում քառակուսի փակագծերում, `;`-ով բաժանված՝ `[construction]`, `[side -1; label 5, 3]`։
- `#`-ը սկսում է մեկնաբանություն (տողի սկզբում կամ բացատից հետո)։ Բացատներ ունեցող անունները գրվում են «կրկնակի չակերտների» մեջ։
- Գործառույթների id-ները հաշվվում են f1-ից՝ գրված հերթականությամբ։ Եզրերի և երեսների հղումները օգտագործում են դրանք, օրինակ՝ `edge f2.side:l3 f2.end [at 50, 0, 10]`։
- Ձևաչափի համար բառեր չունեցող կարգավորումները գրվում են `json`-ով և արժեքով. դրանք կարդացվում են այնպես, ինչպես գրված են։

Ծրագրից պահված սցենարը ներառում է յուրաքանչյուր կարգավորում, ուստի այն բացվում է որպես նույն դետալը։ Ծրագրից ներմուծված STEP մարմինը գրվում է սցենարի ներսում, իսկ հրամանի տողից՝ առանձին `.step` ֆայլով, որի անունը նշված է `step-file`-ով։

## Հրամանի տող գործիքը

Գործիքը աշխատում է Node.js 24-ով համակարգչում, CadCraft սորսի պատճենից՝ `node tools/partcraft-cli/partcraft.mjs <command>`։ Այն մշակողի գործիք է և օգտագործում է նույն մոդուլները, ինչ ծրագիրը։ Դետալները `.partcraft.json` ֆայլեր են կամ `.pcscript` սցենարներ։

| Հրաման | Ինչ է անում |
|---|---|
| `info <part>` | Գործառույթներ, պարամետրեր, rollback գոտին, կառուցված մարմնի ծավալը և չափը |
| `params <part>` | Յուրաքանչյուր պարամետր և հավասարում՝ իր արժեքով |
| `set <part> width=150 Base.depth==thick` | Ուղիղ. փոխում է պարամետրերը, կապում թվեր (`==` կամ արտահայտություն), սահմանում պարզ թվեր |
| `drive <part> Base.depth=12` | Հակառակ. լուծում է պարամետրը, որը վարում է վարվող թիվը (`--prefer width`-ը ընտրում է մեկը) |
| `build <part> --out x.step` | Գրում է `.step`, `.stl`, `.3mf`, `.json`, `.pcscript` կամ մակրո (`.swb`) |
| `build <part> --table sizes.csv --out-dir sizes` | Մեկ ֆայլ՝ ձևավորման աղյուսակի յուրաքանչյուր տողի համար |
| `variants <part> --out-dir d` կամ `--zip f.zip` | Յուրաքանչյուր կոնֆիգուրացիա՝ որպես STEP, IFC, DWG և նախադիտում, տարբերակների աղյուսակ և գրադարանի տարր (`--only "A,B"`, `--formats step,ifc,dwg,preview`, `--no-item`)։ Տես [Ստեղծել տարբերակների փաթեթ](topic:variant-pack) |
| `script <in.pcscript> -o part.json` | Սցենարից դետալ |
| `to-script <part> -o part.pcscript` | Դետալից սցենար |
| `rollback <part> [<feature>]`, `forward <part> [--end]` | Տեղափոխում է rollback գոտին ֆայլում |
| `check <part> [--strict]` | Կարգապահության ստուգում (ստորև) |

`build`-ը նաև ընդունում է `--set name=value` (միայն այս կառուցման համար) և `--upto <feature>`։ Յուրաքանչյուր հրաման ընդունում է `--json`։ Ելքի կոդերը՝ 0՝ լավ, 1՝ գտնվել է խնդիր, 2՝ հրամանը սխալ է գրվել։ Սցենարը երբեք տեղում չի վերագրվում. փոփոխված պատճենը պահելու համար տվեք `-o`։

## Ստուգումը

`check`-ը հայտնում է, թե ինչն է դետալը դարձնում ավելի դժվար փոփոխելի հետագայում։

| Հայտնաբերում | Համարվում է |
|---|---|
| Էսքիզ, որը գերսահմանված է (հակասող կամ կրկնվող կապեր) | սխալ |
| Գործառույթ, որը չի կառուցվում | սխալ |
| Պարամետր կամ հավասարում սխալով, կամ պարամետրեր, որոնք օգտագործում են միմյանց | սխալ |
| Էսքիզ, որը թերսահմանված է, իր ազատության աստիճաններով | նախազգուշացում |
| Թվեր, որոնք ուղղակի մուտքագրված են գործառույթներում և չափերում, և որոնք որևէ պարամետր չի վարում | նախազգուշացում |
| Պարամետր, որն ոչ ոք չի օգտագործում | նախազգուշացում |
| Անջատված գործառույթ. rollback գոտին ոչ վերջում | նախազգուշացում |

`--strict`-ը յուրաքանչյուր նախազգուշացում դարձնում է սխալ, ուստի կառուցման սկրիպտը կարող է մերժել դետալը, որը լրիվ վարված չէ։

:::note
`.swb` մակրոյի ելքը նախատեսված է այն մոդելավորիչի համար, որն օգտագործում են շատ արհեստանոցներ. այդ ծրագրի ներսում գործարկելիս այն դետալը կառուցում է այնտեղ։ Այն այստեղ չի գործարկվել այդ ծրագրում (այն մեր սերվերներին հասանելի չէ), ուստի դիտարկեք այն որպես չփորձարկված։
:::
