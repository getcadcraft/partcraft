Նույն գործիքի ուղին տարբեր կառավարումների համար պետք է գրվի տարբեր ձևով. տողերի համարներով կամ առանց դրանց, `M6` կամ դադարով, `G28` կամ `G53`, `M30` կամ `M2`։ **Պոստը** կարճ տեքստ է, որը ասում է, թե ինչպես։ PartCraft-ի երեք ներկառուցված պոստերը (Fanuc ոճի, GRBL և LinuxCNC) գրված են այս ձևաչափով, ուստի ձեր սեփական պոստը կարող է սկսվել դրանցից մեկի պատճենից։

Ստուգեք ելքը ձեր մեքենայի սեփական սիմուլյատորում՝ նախքան կտրելը, և նախ աշխատեցրեք այն նյութի վերևում՝ օդում։ Ներկառուցված պոստերը գրում են ճիշտ նույնը, ինչ գրում էին մինչև այս ձևաչափի գոյությունը (թեստերը համեմատում են իրենց ելքը բայթ առ բայթ հարյուրավոր ծրագրերի վրա), բայց ոչինչ այստեղ չի ապացուցված ձեր մեքենայի վրա, և ձեր փոփոխած պոստն ինքն է պետք ապացուցի։

## Ստեղծել մեկը

Manufacture-ում, **Post** բաժնում՝

- {{ui:Խմբագրել պոստը…}}՝ ներկառուցված կառավարման վրա, բացում է **ձեր սեփական պատճենը**։ Ձեր սեփական պոստերից մեկի վրա այն բացում է հենց այդ պոստը։
- {{ui:Նոր պոստ…}}-ը սկսում է փոքր դատարկ պոստից, որում կան բոլոր իրադարձությունները։
- {{ui:Ներմուծել պոստի ֆայլը…}}-ը կարդում է `.cpost` տեքստային ֆայլ (այն ֆայլը, որը ստանում եք խմբագրիչում **Պահել որպես ֆայլ…**-ով)։

Խմբագրիչը ցույց է տալիս տեքստը, տող, որը ասում է, կարդացվում է արդյոք (և որ տողն է սխալ), և G-code-ը, որը գրում է պոստը, երբ գրում եք։ **Նախադիտել՝** ընտրում է փոքր նմուշային ծրագիր, որն աշխատեցնում է բոլոր իրադարձությունները, կամ այս մասի սեփական ծրագիրը։ {{ui:Պահել}}-ը պահում է պոստը մասի ֆայլում (մինչև 20 պոստ) և այն ընտրում է որպես կառավարում։ Պոստները ուղեկցում են մասին. մեկ այլ մասում օգտագործելու համար պահեք այն որպես ֆայլ և այնտեղ ներմուծեք։

## Ինչ տեսք ունի պոստը

```
post mymill
name My mill (.nc)
extension nc
line-numbers off
decimal-point no
canned-cycles no
modal motion G0 G1 G2 G3

on start
  comment Program {program}: {name}
  emit G21 G90 G17
end

on tool-change
  emit T{tool.number} M6
end

on rapid
  if moved
    emit G0~ X{x}~ Y{y}~ Z{z}~
  end
end
```

`//`-ով սկսվող տողերը և դատարկ տողերը անտեսվում են։ Վերևում գալիս են կարգավորումները, ապա յուրաքանչյուր իրադարձության համար՝ մեկ `on <event>` բլոկ, որը փակվում է `end`-ով։ Բաց թողած իրադարձությունը ոչինչ չի գրում։

| Կարգավորում | Իմաստը |
|---|---|
| `post <id>` | Պոստի identifier-ը՝ տառեր, թվեր, `-` և `_` |
| `name <text>` | Ինչ է ցույց տալիս Կառավարումների ցանկը |
| `extension <ext>` | Ֆայլի ընդլայնում՝ nc, ngc, tap … |
| `line-numbers 10` / `off` | `N10`, `N20` … յուրաքանչյուր `emit` տողի վրա, կամ ոչ մի |
| `decimal-point yes` / `no` | `10.` `10`-ի փոխարեն (մեկնաբանությունները երբեք կետ չեն պարունակում) |
| `canned-cycles yes` / `no` | `no`. անցքերը գրվում են այն G0/G1 շարժումներով, որոնք նշանակում են |
| `modal <group> <words>` | Խմբի բառեր (`modal motion G0 G1 G2 G3`), որոնք գրվում են միայն երբ փոխվում են |

## Իրադարձություններ

Ծրագրի համար դրանք աշխատում են հետևյալ հերթականությամբ՝ `start`։ Ապա յուրաքանչյուր գործողության համար՝ `operation`, `tool-change` (երբ գործիքը փոխվում է), `spindle` (երբ արագությունը փոխվում է), `approach` (շարժումը մինչև առաջին կետը, առաջին արագ շարժումից առաջ), `coolant-on`, ապա դրա շարժումները՝ `rapid`, `feed` և `arc`, և յուրաքանչյուր կանոնական ցիկլ՝ որպես `cycle-start`, յուրաքանչյուր անցքի համար մեկ `cycle-hole` և `cycle-end`։ Վերջում՝ `end`։

Յուրաքանչյուր իրադարձություն կարող է օգտագործել իր տեսակի շարժման փոփոխականները, գրված `{name}`-ով. ծրագիրը (`name`, `program`, `setup.axis`, `setup.origin`, `setup.coolant`), նյութը (`stock.kind`, `stock.d`, `stock.sx`, `stock.sy`, `stock.sz`, `stock.minx` … `stock.maxz`), գործիքը (`tool.number`, `tool.desc`, `tool.kind`, `tool.d`, `tool.flutes`, `tool.fluteLen`), գործողությունը (`op.name`, `op.type`), `rpm`, շարժման կետը (`x`, `y`, `z`, `f`, և `moved`՝ true, երբ առանցքը փոխվել է), աղեղները (`arc.g` 2 կամ 3, `arc.i`, `arc.j`, `arc.cx`, `arc.cy`) և անցքերը (`hole.x`, `hole.y`, `hole.z`, `hole.r`, `hole.q`, `hole.return`, `hole.first`, `cycle.kind`, `cycle.init`, `feed`)։ Խմբագրիչի **Իրադարձություններ և փոփոխականներ** ցանկը ցույց է տալիս, թե որ իրադարձությունն է տեսնում որը։ Վիճակը, որը կարող եք կարդալ և սահմանել. `cool`, `offset`, և `at.x`, `at.y`, `at.z`, `at.f` (վերջին գրված արժեքները)։

## Հայտարարություններ

| Հայտարարություն | Ինչ է անում |
|---|---|
| `raw TEXT` | Տողը ճիշտ այնպես, ինչպես գրված է (առանց տողի համարի) |
| `comment TEXT` | `(TEXT)`՝ ոչ-ASCII նիշերը և փակագծերը հանած |
| `emit WORD WORD …` | Բառերի տող։ Դատարկ դուրս եկած բառերը բաց են թողնվում։ Բառեր չկան՝ տող չկա |
| `word WORD …` | Ավելացնում է բառեր կառուցվող տողին։ Մերկ `emit`-ը այն ավարտում է |
| `if EXPR` … `else` … `end` | Պայմաններ՝ `a == b`, `a != b`, `not a`, `a and b`, `a or b`, `a??b` (a, իսկ եթե չկա՝ b) |
| `for tool in tools` … `end` | Մեկ անգամ յուրաքանչյուր գործիքի համար, որը օգտագործում է ծրագիրը |
| `set NAME EXPR` | Հիշում է արժեք (`set offset tool.number`) |
| `reset NAME …` | Մոռանում է մոդալ բառերը (խումբ, հասցեի տառ՝ ինչպես `Z`, կամ `at.z`) |
| `do rapid X Y Z` | Կատարում է `rapid` իրադարձությունը կետի համար |

Բառը տեքստ է՝ `{variable|filter}` անցքերով։ Զտիչներն են՝ `upper`, `lower`, `pad:N` (զրոներով լրացում), `cut:N` (առաջին N նիշը), `safe` (մեկնաբանության համար անվտանգ ASCII) և `int`։ `~`-ով ավարտվող բառը **մոդալ** է. այն գրվում է միայն այն դեպքում, երբ տարբերվում է վերջին գրվածից (`G1~`, `X{x}~`)։ `~!`-ով ավարտվող բառը գրվում է ամեն անգամ և միևնույն է հիշվում է։ Փոփոխական չհանդիսացող անունը սովորական տեքստ է (`G81`, `mist`)։ Թվերը կլորացվում են մինչև 0.001 mm և գրվում են առանց վերջնական զրոների։

## Ինչ չի կարող անել պոստը

Այն որոշում է միայն, թե ինչպես են գրվում շարժումները, ավելին՝ ոչ։ Այն չի կարող փոխել գործիքի ուղին, դասավորել գործողությունները, բաժանել աղեղը, ավելացնել առանցք, իմանալ ձեր մեքենայի շարժման տիրույթը կամ կինեմատիկան, կամ կատարել թվաբանություն կոորդինատների վրա (չկա `+`)։ Չկան զոնդավորումը, գործիքի կյանքի և ենթածրագրային ցիկլերը, 4-րդ և 5-րդ առանցքի ելքը և տաշող մեքենայի կոդերը։ Մեկ այլ ծրագրի `.cps` տիպի պոստի ֆայլը չի կարող բեռնվել. սա այլ, ավելի պարզ ձևաչափ է։
