ප්‍රවේශමෙන් මොඩලගත කිරීම බොත්තම් ගැන වඩා විනය ගැන වේ. පෙළ ලෙස ලියන ලද කොටසක් කියවිය, සමාලෝචනය කළ, පේළියෙන් පේළියට සංසන්දනය කළ හැකි අතර ස්ක්‍රිප්ටයකින් නැවත ගොඩනැගිය හැක. PartCraft දෙපැත්තටම ක්‍රියා කරයි: ඕනෑම කොටසක් ස්ක්‍රිප්ටයක් ලෙස ලිවිය හැක, සහ ස්ක්‍රිප්ටයක් කොටස ගොඩනඟයි.

- {{ui:ස්ක්‍රිප්ට් ලෙස සුරකින්න}} විවෘත කොටස `<name>.pcscript` ලෙස බාගනී.
- {{ui:ස්ක්‍රිප්ට් විවෘත කරන්න}} `.pcscript` ගොනුවකින් කොටසක් ගොඩනඟයි. වැරැද්දක් එහි පේළි අංකය සමග වාර්තා වන අතර කිසිවක් ප්‍රතිස්ථාපනය නොවේ.

## ස්ක්‍රිප්ට් ආකෘතිය

```
pcscript 1
part "Bracket"
  resolution 64

param width = 120
  note Plate width
param thick = 8
param bolt = 8.5
param margin = bolt * 1.5

sketch Plate
  on top
  point a 0, 0
  point b 120, 0
  point c 120, 60
  point d 0, 60
  line bottom a b
  line right b c
  line top c d
  line left d a
  coincident a O
  horizontal bottom
  horizontal top
  vertical left
  vertical right
  distance bottom = width
  distance left 60

extrude Base
  sketch Plate
  depth = thick

sketch HoleCentres
  on face Base end
  point h1 12, 12
  hdistance O h1 = margin
  vdistance O h1 = margin

hole Bolts
  sketch HoleCentres
  d = bolt
  through
```

නීති:

- වම් දාරයේ පේළියක් ප්‍රකාශයක් ආරම්භ කරයි: `pcscript`, `part`, `param`, විශේෂාංග වර්ගයක් (`sketch`, `extrude`, `revolve`, `hole`, `lpattern`, `cpattern`, `mirror`, `fillet`, `chamfer`, `shell`, `import` සහ නව වර්ග) එහි නමෙන් පසු, හෝ `rollback <feature>`.
- ඉඩ තැබූ පේළි ඉහත ප්‍රකාශයේ සැකසීම් වේ. තනිව ඇති සැකසීමක් (`through`, `reverse`, `suppressed`) ඔව් යන්නයි.
- අංක සැකසීමක් යනු අංකයක්, හෝ `=` සහ ප්‍රකාශනයක්, එය සමීකරණයක් සාදයි: `depth = thick`.
- ස්කෙච් එකක: `on` තලය නම් කරයි (`front`, `top`, `right`, `face Base end`, `face Revolve1 side l3`); ජ්‍යාමිතිය වන්නේ `point <name> x, y`, `line <name> <point> <point>`, `circle <name> <centre> <radius>`, `arc <name> <centre> <start> <end>` (වාමාවර්ත) හෝ `spline <name> fit|control <points>`; සම්බන්ධතා ඒවායේ වර්ගය සහ ඒවා සම්බන්ධ කරන නම් වේ (`O` යනු මූලය); මානයක් එහි අගයෙන් හෝ `= expression` එකෙන් අවසන් වේ.
- ජ්‍යාමිතියක හෝ සම්බන්ධතා පේළියක විකල්ප සැකසීම් අවසානයේ චතුරස්‍ර වරහන් තුළ, `;` මගින් වෙන් කර, දමයි: `[construction]`, `[side -1; label 5, 3]`.
- `#` අදහස් දැක්වීමක් ආරම්භ කරයි (පේළියේ ආරම්භයේ හෝ ඉඩකට පසුව). ඉඩ ඇති නම් "ද්විත්ව උද්ධෘත" තුළ දමන්න.
- විශේෂාංග id ලියන අනුපිළිවෙලට f1 සිට ගණනය වේ. දාර සහ මුහුණත් යොමු ඒවා භාවිත කරයි, උදාහරණයක් ලෙස `edge f2.side:l3 f2.end [at 50, 0, 10]`.
- ආකෘතියට වචන නැති සැකසීම් `json` සහ අගයක් ලෙස ලියයි; ඒවා ඇති ආකාරයෙන්ම නැවත කියවේ.

යෙදුමෙන් සුරකින විට, ස්ක්‍රිප්ටයේ සෑම සැකසීමක්ම ඇතුළත් වේ, එබැවින් එය එම කොටසම ලෙස විවෘත වේ. ආයාත කළ STEP ඝන වස්තුව යෙදුමෙන් ස්ක්‍රිප්ටය ඇතුළේ ලියයි, සහ විධාන රේඛාවෙන් `step-file` මගින් නම් කළ වෙනම `.step` ගොනුවක් ලෙසද ලියයි.

## විධාන රේඛා මෙවලම

මෙවලම Node.js 24 ඇති පරිගණකයක, CadCraft මූලාශ්‍රයේ පිටපතකින් ධාවනය වේ: `node tools/partcraft-cli/partcraft.mjs <command>`. එය සංවර්ධක මෙවලමකි සහ යෙදුමේ එම මොඩියුල භාවිත කරයි. කොටස් `.partcraft.json` ගොනු හෝ `.pcscript` ස්ක්‍රිප්ට වේ.

| විධානය | එය කරන දේ |
|---|---|
| `info <part>` | විශේෂාංග, පරාමිති, rollback තීරුව, ගොඩනඟන ලද ඝන වස්තුවේ පරිමාව සහ ප්‍රමාණය |
| `params <part>` | සෑම පරාමිතියක්ම සහ සමීකරණයක්ම එහි අගය සමග |
| `set <part> width=150 Base.depth==thick` | ඉදිරියට: පරාමිති වෙනස් කරන්න, අංක සම්බන්ධ කරන්න (`==` හෝ ප්‍රකාශනයක්), සරල අංක සකසන්න |
| `drive <part> Base.depth=12` | පසුපසට: ධාවනය කළ අංකයක් පිටුපස ඇති පරාමිතිය විසඳන්න (`--prefer width` එකක් තෝරයි) |
| `build <part> --out x.step` | `.step`, `.stl`, `.3mf`, `.json`, `.pcscript` හෝ macro (`.swb`) ලියයි |
| `build <part> --table sizes.csv --out-dir sizes` | සැලසුම් වගුවේ පේළියකට එක් ගොනුවක් |
| `variants <part> --out-dir d` හෝ `--zip f.zip` | සෑම වින්‍යාසයක්ම STEP, IFC, DWG සහ පෙරදසුනක්, variants වගුවක් සහ පුස්තකාල අයිතමයක් ලෙස (`--only "A,B"`, `--formats step,ifc,dwg,preview`, `--no-item`); බලන්න [variant pack එකක් සාදන්න](topic:variant-pack) |
| `script <in.pcscript> -o part.json` | ස්ක්‍රිප්ටයේ සිට කොටසට |
| `to-script <part> -o part.pcscript` | කොටසේ සිට ස්ක්‍රිප්ටයට |
| `rollback <part> [<feature>]`, `forward <part> [--end]` | ගොනුවේ rollback තීරුව ගෙනයන්න |
| `check <part> [--strict]` | විනය පරීක්ෂාව (පහතින්) |

`build` `--set name=value` (මෙම build සඳහා පමණි) සහ `--upto <feature>` ද ගනී. සෑම විධානයක්ම `--json` ගනී. පිටවීමේ කේත: 0 හොඳයි, 1 ගැටලුවක් හමු විය, 2 විධානය වැරදියට ටයිප් කරන ලදී. ස්ක්‍රිප්ටයක් කිසි විටෙක ස්ථානගතව නැවත ලියනු නොලැබේ: වෙනස් කළ පිටපතක් සුරැකීමට `-o` දෙන්න.

## පරීක්ෂාව

`check` කොටසක් පසුව වෙනස් කිරීම දුෂ්කර කරන දේ වාර්තා කරයි:

| සොයාගැනීම | ගණන් ගන්නේ |
|---|---|
