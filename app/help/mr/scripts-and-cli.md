काळजीपूर्वक मॉडेलिंग म्हणजे बटणांपेक्षा शिस्त जास्त. मजकुरात लिहिलेला भाग वाचता येतो, तपासता येतो, ओळ-ओळ तुलना करता येते आणि स्क्रिप्टने पुन्हा तयार करता येतो. PartCraft दोन्ही दिशांनी जातो: कोणताही भाग स्क्रिप्ट म्हणून लिहिता येतो, आणि स्क्रिप्ट भाग तयार करते.

## ॲपमध्ये

{{ui:Parameters}} टॅबवर, **स्क्रिप्ट** खाली:

- {{ui:Save as script}} उघडा भाग `<name>.pcscript` म्हणून डाउनलोड करतो.
- {{ui:Open script}} `.pcscript` फाइलवरून भाग तयार करतो. चूक झाली तर तिची ओळ क्रमांकासह नोंदवली जाते आणि काहीही बदलले जात नाही.

## स्क्रिप्ट फॉरमॅट

```
pcscript 1
part "Bracket"
  resolution 64

param width = 120
  note Plate width
param thick = 8
param bolt = 8.5
param margin = bolt * 1.5

sketch Plate
  on top
  point a 0, 0
  point b 120, 0
  point c 120, 60
  point d 0, 60
  line bottom a b
  line right b c
  line top c d
  line left d a
  coincident a O
  horizontal bottom
  horizontal top
  vertical left
  vertical right
  distance bottom = width
  distance left 60

extrude Base
  sketch Plate
  depth = thick

sketch HoleCentres
  on face Base end
  point h1 12, 12
  hdistance O h1 = margin
  vdistance O h1 = margin

hole Bolts
  sketch HoleCentres
  d = bolt
  through
```

नियम:

- डाव्या कडेला सुरू होणारी ओळ नवे विधान सुरू करते: `pcscript`, `part`, `param`, फीचर प्रकार (`sketch`, `extrude`, `revolve`, `hole`, `lpattern`, `cpattern`, `mirror`, `fillet`, `chamfer`, `shell`, `import` आणि नवे प्रकार) त्याच्या नावासह, किंवा `rollback <feature>`.
- इंडेंट केलेल्या ओळी वरील विधानाच्या सेटिंग्ज आहेत. एकट्या सेटिंग (`through`, `reverse`, `suppressed`) म्हणजे होय.
- संख्या सेटिंग म्हणजे संख्या, किंवा `=` आणि एक्सप्रेशन, जे समीकरण बनवते: `depth = thick`.
- स्केचमध्ये: `on` प्लेनचे नाव देतो (`front`, `top`, `right`, `face Base end`, `face Revolve1 side l3`); भूमिती म्हणजे `point <name> x, y`, `line <name> <point> <point>`, `circle <name> <centre> <radius>`, `arc <name> <centre> <start> <end>` (घड्याळाच्या उलट दिशेने) किंवा `spline <name> fit|control <points>`; संबंध त्यांचा प्रकार आणि ते जोडणारी नावे असतात (`O` हा उगम आहे); डायमेन्शन त्याच्या मूल्याने किंवा `= expression` ने संपते.
- भूमिती किंवा संबंध ओळीच्या पर्यायी सेटिंग्ज शेवटी चौरस कंसात `;` ने वेगळ्या लिहितात: `[construction]`, `[side -1; label 5, 3]`.
- `#` ओळीच्या सुरुवातीला किंवा स्पेसनंतर कमेंट सुरू करतो. स्पेस असलेली नावे "दुहेरी अवतरणचिन्हांत" लिहा.
- फीचर आयडी लिहिलेल्या क्रमाने f1 पासून मोजले जातात. एज आणि फेस संदर्भ त्यांचा वापर करतात, उदाहरणार्थ `edge f2.side:l3 f2.end [at 50, 0, 10]`.
- फॉरमॅटला शब्द नसलेल्या सेटिंग्ज `json` आणि एक मूल्य लिहून दिल्या जातात; त्या जशाच्या तशा परत वाचल्या जातात.

ॲपमधून जतन केलेल्या स्क्रिप्टमध्ये प्रत्येक सेटिंग असते, त्यामुळे ती तोच भाग म्हणून उघडते. ॲपमधून आयात केलेला STEP सॉलिड स्क्रिप्टच्या आत लिहिला जातो, आणि कमांड लाइनवरून `step-file` ने नाव दिलेली स्वतंत्र `.step` फाइल म्हणून.

## कमांड लाइन टूल

हे टूल Node.js 24 असलेल्या संगणकावर, CadCraft स्रोताच्या प्रतीवरून चालते: `node tools/partcraft-cli/partcraft.mjs <command>`. हे डेव्हलपर टूल आहे आणि ॲपसारखेच मॉड्यूल्स वापरते. भाग म्हणजे `.partcraft.json` फाइल्स किंवा `.pcscript` स्क्रिप्ट्स.

| कमांड | काय करते |
|---|---|
| `info <part>` | फीचर्स, पॅरामीटर्स, रोलबॅक बार, तयार सॉलिडचे आकारमान आणि आकार |
| `params <part>` | प्रत्येक पॅरामीटर आणि समीकरण त्याच्या मूल्यासह |
| `set <part> width=150 Base.depth==thick` | पुढे: पॅरामीटर्स बदला, संख्या जोडा (`==` किंवा एक्सप्रेशन), साध्या संख्या सेट करा |
| `drive <part> Base.depth=12` | मागे: चालवलेल्या संख्येमागील पॅरामीटर सोडवा (`--prefer width` एक निवडते) |
| `build <part> --out x.step` | `.step`, `.stl`, `.3mf`, `.json`, `.pcscript` किंवा मॅक्रो (`.swb`) लिहिते |
| `build <part> --table sizes.csv --out-dir sizes` | डिझाइन टेबलच्या प्रत्येक ओळीसाठी एक फाइल |
| `variants <part> --out-dir d` किंवा `--zip f.zip` | प्रत्येक कॉन्फिगरेशन STEP, IFC, DWG आणि पूर्वावलोकन, व्हेरिएंट्स टेबल आणि लायब्ररी आयटम म्हणून (`--only "A,B"`, `--formats step,ifc,dwg,preview`, `--no-item`); [व्हेरिएंट पॅक बनवा](topic:variant-pack) पहा |
| `script <in.pcscript> -o part.json` | स्क्रिप्टवरून भाग |
| `to-script <part> -o part.pcscript` | भागावरून स्क्रिप्ट |
| `rollback <part> [<feature>]`, `forward <part> [--end]` | फाइलमधील रोलबॅक बार हलवा |
| `check <part> [--strict]` | शिस्त तपासणी (खाली) |

`build` `--set name=value` (फक्त या बिल्डसाठी) आणि `--upto <feature>` स्वीकारतो. प्रत्येक कमांड `--json` स्वीकारते. एक्झिट कोड: 0 ठीक, 1 समस्या आढळली, 2 कमांड चुकीची टाइप केली. स्क्रिप्ट जागेवर कधीही पुन्हा लिहिली जात नाही: बदललेली प्रत जतन करण्यासाठी `-o` द्या.

## तपासणी

`check` अहवाल देतो की भाग नंतर बदलणे कठीण का होतो:

| सापडते | मोजले जाते म्हणून |
|---|---|
| स्केच जे अतिनिर्धारित आहे (विरोधाभासी किंवा पुनरावृत्त संबंध) | त्रुटी |
| फीचर जे तयार होत नाही | त्रुटी |
| पॅरामीटर किंवा समीकरणात त्रुटी, किंवा एकमेकांचा वापर करणारे पॅरामीटर्स | त्रुटी |
| स्केच जे कमी-निर्धारित आहे, त्याच्या स्वातंत्र्याच्या अंशांसह | चेतावणी |
| फीचर्स आणि डायमेन्शन्समध्ये थेट टाइप केलेल्या संख्या ज्या कोणताही पॅरामीटर चालवत नाही | चेतावणी |
| कोणीही न वापरलेला पॅरामीटर | चेतावणी |
| दाबलेला फीचर; रोलबॅक बार शेवटी नसणे | चेतावणी |

`--strict` प्रत्येक चेतावणीला त्रुटी बनवतो, म्हणजे बिल्ड स्क्रिप्ट पूर्णपणे चालवलेला नसलेला भाग नाकारू शकते.

:::note
`.swb` मॅक्रो आउटपुट बहुतेक शॉप्स वापरत असलेल्या भाग मॉडेलरसाठी आहे: त्या प्रोग्राममध्ये चालवल्यावर तो तिथे भाग तयार करतो. तो येथे त्या प्रोग्राममध्ये चालवलेला नाही (तो आमच्या सर्व्हरवर उपलब्ध नाही), म्हणून त्याला चाचणी न केलेला समजा.
:::
