सावधानीपूर्वक मोडेलिङ बटनभन्दा अनुशासनमा बढी निर्भर छ। पाठको रूपमा लेखिएको भाग पढ्न, समीक्षा गर्न, पङ्क्तिअनुसार तुलना गर्न र स्क्रिप्टले पुनः निर्माण गर्न सकिन्छ। PartCraft दुवै दिशामा जान्छ: जुनसुकै भाग स्क्रिप्टको रूपमा लेख्न सकिन्छ, र स्क्रिप्टले भाग बनाउँछ।

## एपमा

{{ui:Parameters}} ट्याबमा, **स्क्रिप्ट** अन्तर्गत:

- {{ui:Save as script}} ले खुला भागलाई `<name>.pcscript` को रूपमा डाउनलोड गर्छ।
- {{ui:Open script}} ले `.pcscript` फाइलबाट भाग बनाउँछ। त्रुटि भएमा त्यसको लाइन नम्बरसहित रिपोर्ट हुन्छ, र केही पनि बदलिँदैन।

## स्क्रिप्ट ढाँचा

```
pcscript 1
part "Bracket"
  resolution 64

param width = 120
  note Plate width
param thick = 8
param bolt = 8.5
param margin = bolt * 1.5

sketch Plate
  on top
  point a 0, 0
  point b 120, 0
  point c 120, 60
  point d 0, 60
  line bottom a b
  line right b c
  line top c d
  line left d a
  coincident a O
  horizontal bottom
  horizontal top
  vertical left
  vertical right
  distance bottom = width
  distance left 60

extrude Base
  sketch Plate
  depth = thick

sketch HoleCentres
  on face Base end
  point h1 12, 12
  hdistance O h1 = margin
  vdistance O h1 = margin

hole Bolts
  sketch HoleCentres
  d = bolt
  through
```

नियमहरू:

- बायाँ किनारमा सुरु हुने लाइनले कथन सुरु गर्छ: `pcscript`, `part`, `param`, फिचर प्रकार (`sketch`, `extrude`, `revolve`, `hole`, `lpattern`, `cpattern`, `mirror`, `fillet`, `chamfer`, `shell`, `import` र नयाँ प्रकारहरू) त्यसको नामसहित, वा `rollback <feature>`।
- इन्डेन्ट गरिएका लाइनहरू माथिको कथनका सेटिङ हुन्। एक्लो सेटिङ (`through`, `reverse`, `suppressed`) ले हो भन्छ।
- संख्या सेटिङ एउटा संख्या हो, वा `=` र एक्सप्रेसन, जसले समीकरण बनाउँछ: `depth = thick`।
- स्केचमा: `on` ले प्लेनको नाम दिन्छ (`front`, `top`, `right`, `face Base end`, `face Revolve1 side l3`); ज्यामिति हो `point <name> x, y`, `line <name> <point> <point>`, `circle <name> <centre> <radius>`, `arc <name> <centre> <start> <end>` (घडीको उल्टो दिशा) वा `spline <name> fit|control <points>`; सम्बन्धहरू तिनको प्रकार र तिनीहरूले जोड्ने नामहरू हुन् (`O` उत्पत्ति हो); डाइमेन्सन आफ्नो मानसँग वा `= expression` ले सकिन्छ।
- ज्यामिति वा सम्बन्ध लाइनका वैकल्पिक सेटिङ लाइनको अन्त्यमा वर्गाकार कोष्ठकमा राखिन्छन्, `;` ले छुट्याइएका: `[construction]`, `[side -1; label 5, 3]`।
- `#` ले टिप्पणी सुरु गर्छ (लाइनको सुरुमा वा स्पेसपछि)। खाली ठाउँ भएका नामहरू "double quotes" भित्र राखिन्छन्।
- फिचर ID हरू लेखिएको क्रममा f1 बाट गन्न सुरु हुन्छन्। किनार र सतहका सन्दर्भहरूले तिनलाई प्रयोग गर्छन्, उदाहरणका लागि `edge f2.side:l3 f2.end [at 50, 0, 10]`।
- ढाँचामा शब्द नभएका सेटिङहरू `json` र मानसहित लेखिन्छन्; तिनलाई जस्ताको तस्तै फेरि पढिन्छ।

एपबाट बचत गरिएको स्क्रिप्टमा हरेक सेटिङ हुन्छ, त्यसैले त्यो उही भागको रूपमा खुल्छ। आयात गरिएको STEP सोलिड एपबाट स्क्रिप्ट भित्र लेखिन्छ, र कमाण्ड लाइनबाट `step-file` ले नाम दिएको छुट्टै `.step` फाइलको रूपमा।

## कमाण्ड लाइन उपकरण

यो उपकरण Node.js 24 भएको कम्प्युटरमा CadCraft स्रोतको प्रतिलिपिबाट चल्छ: `node tools/partcraft-cli/partcraft.mjs <command>`। यो विकासकर्ता उपकरण हो र एपले प्रयोग गर्ने उही मोड्युलहरू प्रयोग गर्छ। भागहरू `.partcraft.json` फाइल वा `.pcscript` स्क्रिप्ट हुन्।

| कमाण्ड | के गर्छ |
|---|---|
| `info <part>` | फिचरहरू, प्यारामिटरहरू, रोलब्याक बार, निर्मित सोलिडको आयतन र आकार |
| `params <part>` | हरेक प्यारामिटर र समीकरण आफ्नो मानसहित |
| `set <part> width=150 Base.depth==thick` | अगाडि: प्यारामिटर परिवर्तन गर्नुहोस्, संख्या जोड्नुहोस् (`==` वा एक्सप्रेसन), सादा संख्या सेट गर्नुहोस् |
| `drive <part> Base.depth=12` | पछाडि: चालित संख्यापछाडिको प्यारामिटर समाधान गर्नुहोस् (`--prefer width` ले एउटा छान्छ) |
| `build <part> --out x.step` | `.step`, `.stl`, `.3mf`, `.json`, `.pcscript` वा म्याक्रो (`.swb`) लेख्छ |
| `build <part> --table sizes.csv --out-dir sizes` | डिजाइन तालिकाको हरेक पङ्क्तिका लागि एक फाइल |
| `variants <part> --out-dir d` वा `--zip f.zip` | हरेक कन्फिगरेसन STEP, IFC, DWG र पूर्वावलोकन, भेरियन्ट तालिका र लाइब्रेरी वस्तुको रूपमा (`--only "A,B"`, `--formats step,ifc,dwg,preview`, `--no-item`); हेर्नुहोस् [भेरियन्ट प्याक बनाउनुहोस्](topic:variant-pack) |
| `script <in.pcscript> -o part.json` | स्क्रिप्टबाट भाग |
| `to-script <part> -o part.pcscript` | भागबाट स्क्रिप्ट |
| `rollback <part> [<feature>]`, `forward <part> [--end]` | फाइलमा रोलब्याक बार सार्नुहोस् |
| `check <part> [--strict]` | तलको अनुशासन जाँच |

`build` ले `--set name=value` (यो निर्माणका लागि मात्र) र `--upto <feature>` पनि लिन्छ। हरेक कमाण्डले `--json` लिन्छ। निकास कोडहरू: 0 ठीक, 1 समस्या भेटियो, 2 कमाण्ड गलत टाइप भयो। स्क्रिप्ट कहिल्यै ठाउँमै पुनः लेखिँदैन: परिवर्तित प्रतिलिपि बचत गर्न `-o` दिनुहोस्।

## जाँच

`check` ले भाग पछि परिवर्तन गर्न कठिन बनाउने कुराहरू रिपोर्ट गर्छ:

| फेला परेको कुरा | गणना |
|---|---|
| धेरै परिभाषित स्केच (बाझिने वा दोहोरिएका सम्बन्धहरू) | त्रुटि |
| फिचर जुन निर्माण हुँदैन | त्रुटि |
| त्रुटि भएको प्यारामिटर वा समीकरण, वा एकअर्कालाई प्रयोग गर्ने प्यारामिटरहरू | त्रुटि |
| कम परिभाषित स्केच, यसका स्वतन्त्रताका अंशहरूसहित | चेतावनी |
| फिचर र डाइमेन्सनमा सिधै टाइप गरिएका संख्याहरू जुन कुनै प्यारामिटरले चलाउँदैन | चेतावनी |
| कुनै पनि प्रयोग नभएको प्यारामिटर | चेतावनी |
| निष्क्रिय फिचर; रोलब्याक बार अन्त्यमा नभएको | चेतावनी |

`--strict` ले हरेक चेतावनीलाई त्रुटि बनाउँछ, ताकि निर्माण स्क्रिप्टले पूर्ण रूपमा चलाइएको नभएको भाग अस्वीकार गर्न सकोस्।

:::note
`.swb` म्याक्रो आउटपुट धेरैजसो कार्यशालाले प्रयोग गर्ने भाग मोडेलर कार्यक्रमका लागि हो: त्यस कार्यक्रम भित्र चलाउँदा त्यहाँ भाग बन्छ। यो यहाँ त्यस कार्यक्रममा चलाइएको छैन (यो हाम्रा सर्भरमा उपलब्ध छैन), त्यसैले यसलाई अपरीक्षित मान्नुहोस्।
:::
