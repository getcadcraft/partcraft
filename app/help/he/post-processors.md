אותו מסלול כלי צריך להיכתב בצורה שונה לבקרים שונים: מספרי שורות או בלעדיהם, `M6` או השהיה, `G28` או `G53`, `M30` או `M2`. **פוסט** הוא הטקסט הקצר שאומר איך. שלושת הפוסטים המובנים של PartCraft (בסגנון Fanuc, GRBL ו-LinuxCNC) כתובים בפורמט הזה, ולכן פוסט משלכם יכול להתחיל כעותק של אחד מהם.

בדקו את הפלט בסימולטור של המכונה שלכם לפני החיתוך, והריצו אותו באוויר מעל חומר הגלם קודם. הפוסטים המובנים כותבים בדיוק את מה שכתבו לפני שהפורמט הזה היה קיים (הבדיקות משוות את הפלט שלהם בית אחר בית על מאות תוכניות), אבל שום דבר כאן לא הוכח על המכונה שלכם, ופוסט ששיניתם הוא שלכם להוכיח.

## יצירת פוסט

בסביבת העבודה ייצור, תחת **פוסט-פרוססור**:

- {{ui:Edit post…}} על בקר מובנה פותח **את העותק שלכם** שלו. על אחד מהפוסטים שלכם הוא פותח את הפוסט עצמו.
- {{ui:New post…}} מתחיל מפוסט ריק וקטן שבו כל האירועים מופיעים.
- {{ui:Import post file…}} קורא קובץ טקסט `.cpost` (הקובץ שאתם מקבלים מ-**שמירה כקובץ…** בעורך).

העורך מציג את הטקסט, שורה שאומרת אם הוא נקרא (ואיזו שורה שגויה), ואת קוד ה-G שהפוסט כותב, תוך כדי הקלדה. **תצוגה מקדימה עם** בוחר תוכנית לדוגמה קטנה שמריצה כל אירוע, או את תוכנית החלק הזה. {{ui:Save}} שומר את הפוסט בקובץ החלק (עד 20 פוסטים) ובוחר אותו כבקר. פוסטים נעים עם החלק; כדי להשתמש באחד מהם בחלק אחר, שמרו אותו כקובץ וייבאו אותו שם.

## איך נראה פוסט

```
post mymill
name My mill (.nc)
extension nc
line-numbers off
decimal-point no
canned-cycles no
modal motion G0 G1 G2 G3

on start
  comment Program {program}: {name}
  emit G21 G90 G17
end

on tool-change
  emit T{tool.number} M6
end

on rapid
  if moved
    emit G0~ X{x}~ Y{y}~ Z{z}~
  end
end
```

שורות שמתחילות ב-`//` ושורות ריקות מתעלמים מהן. בראש באות ההגדרות; אחריהן בלוק `on <event>` לכל אירוע, שנסגר ב-`end`. אירוע שתשמיטו לא כותב דבר.

| הגדרה | משמעות |
|---|---|
| `post <id>` | מזהה הפוסט: אותיות, ספרות, `-` ו-`_` |
| `name <text>` | מה שרשימת הבקרים מציגה |
| `extension <ext>` | סיומת הקובץ: nc, ngc, tap … |
| `line-numbers 10` / `off` | `N10`, `N20` … בכל שורת `emit`, או בלי |
| `decimal-point yes` / `no` | `10.` במקום `10` (הערות לעולם אינן נושאות נקודה) |
| `canned-cycles yes` / `no` | `no`: חורים נכתבים כתנועות G0/G1 שהם מייצגים |
| `modal <group> <words>` | מילים של קבוצה (`modal motion G0 G1 G2 G3`) שנכתבות רק כשהן משתנות |

## אירועים

הם רצים בסדר הזה לתוכנית: `start`; ואז לכל פעולה `operation`, `tool-change` (כשהכלי מתחלף), `spindle` (כשהמהירות משתנה), `approach` (התנועה עד הנקודה הראשונה, לפני התנועה המהירה הראשונה), `coolant-on`, ואז התנועות שלה כ-`rapid`, `feed` ו-`arc`, וכל מחזור קבוע כ-`cycle-start`, `cycle-hole` אחד לכל חור ו-`cycle-end`; לבסוף `end`.

אירועים נוספים, למה שחורג משלושה צירים (פוסט בלי האירוע מסרב לתוכנית כזו ומציין את האירוע שחסר לו):

| אירוע | מתי | המשתנים שלו |
|---|---|---|
| `index` | לפני פעולה שכיוון הכלי שלה שונה מהאחרון, ולפני הפעולה הראשונה במכונה עם צירי סיבוב | `rot.a`, `rot.b`, `rot.c` (המיקומים שאליהם הולכים; ריק לציר שאין למכונה), `first.x`, `first.y`, `first.z` |
| `rapid-rotary`, `feed-rotary` | המהלכים של פעולה שצירי הסיבוב שלה זזים בזמן החיתוך | `x`, `y`, `z`, `rot.a`, `rot.b`, `rot.c`, `f`, `rot.moved`, `inverse` (כן כשההזנה חייבת להיות זמן הפוך), `invf` (1/דקות) |
| `rotary-end` | אחרי פעולה כזו | |
| `probe-move` | מהלך שנעצר כשהגשש נדלק | `x`, `y`, `z`, `f`, `probe.n` (1 עד 4), `probe.axis` (x, y או z), `probe.k` (1, 2 או 3) |
| `probe-set` | אחרי המגעים של מחזור גישוש אחד | `probe.kind` (`"z"`, `"x"`, `"y"` או `centre`), `probe.action` (`set` או `measure`), `probe.expect`, `probe.cx`, `probe.cy` |
| `thread` | מהלך הברגה במחרטה | `x`, `z`, `thread.lead` |

בכל אירוע: `kin` (none, a, b, ac, bc), `rotary` ו-`tcp` (yes או no, מהמכונה בהגדרה), `pivot.x`, `pivot.y`, `pivot.z`, `op.tilt` ו-`op.turn` של הפעולה, ובמחרטה `spin.mode` (css או rpm), `spin.css`, `spin.max` ו-`tool.nose`. מילת אות שהערך שלה ריק, כמו `A{rot.a}` במכונה בלי ציר A, מושמטת מהשורה. השוו עם x, y ו-z כטקסט בגרשיים (`if probe.kind == "z"`): בלי גרשיים, הם הקואורדינטות של המהלך.

שתי שורות נוספות בראש הפוסט הופכות אותו לפוסט מחרטה: `machine lathe` (אז הוא כותב רק X ו-Z, ומסרב למסלולי טחינה כפי שפוסט טחינה מסרב למסלולי חריטה) ו-`lathe-x diameter` או `lathe-x radius`.

כל אירוע יכול להשתמש במשתני הסוג של המהלך שלו, שנכתבים `{name}`: התוכנית (`name`, `program`, `setup.axis`, `setup.origin`, `setup.coolant`), חומר הגלם (`stock.kind`, `stock.d`, `stock.sx`, `stock.sy`, `stock.sz`, `stock.minx` … `stock.maxz`), הכלי (`tool.number`, `tool.desc`, `tool.kind`, `tool.d`, `tool.flutes`, `tool.fluteLen`), הפעולה (`op.name`, `op.type`), `rpm`, הנקודה של מהלך (`x`, `y`, `z`, `f`, ו-`moved`: אמת כשציר השתנה), קשתות (`arc.g` 2 או 3, `arc.i`, `arc.j`, `arc.cx`, `arc.cy`) וחורים (`hole.x`, `hole.y`, `hole.z`, `hole.r`, `hole.q`, `hole.return`, `hole.first`, `cycle.kind`, `cycle.init`, `feed`). הרשימה **אירועים ומשתנים** בעורך מראה איזה אירוע רואה מה. מצב שאפשר לקרוא ולקבוע: `cool`, `offset`, ו-`at.x`, `at.y`, `at.z`, `at.f` (הערכים האחרונים שנכתבו).

## פקודות

| פקודה | מה היא עושה |
|---|---|
| `raw TEXT` | שורה בדיוק כפי שהוקלדה (בלי מספר שורה) |
| `comment TEXT` | `(TEXT)` עם תווים שאינם ASCII וסוגריים שהוסרו |
| `emit WORD WORD …` | שורה של מילים; מילים שיוצאות ריקות מושמטות; בלי מילים, בלי שורה |
| `word WORD …` | מוסיף מילים לשורה שנבנית; `emit` ריק מסיים אותה |
| `if EXPR` … `else` … `end` | תנאים: `a == b`, `a != b`, `not a`, `a and b`, `a or b`, `a??b` (a, אחרת b) |
| `for tool in tools` … `end` | פעם אחת לכל כלי שהתוכנית משתמשת בו |
| `set NAME EXPR` | שמירת ערך (`set offset tool.number`) |
| `reset NAME …` | שכחת מילים מודאליות (קבוצה, אות כתובת כמו `Z`, או `at.z`) |
| `do rapid X Y Z` | הרצת האירוע `rapid` לנקודה |

מילה היא טקסט מוקלד עם חורים מסוג `{variable|filter}`. המסננים הם `upper`, `lower`, `pad:N` (מילוי באפסים), `cut:N` (N התווים הראשונים), `safe` (ASCII בטוח להערה) ו-`int`. מילה שמסתיימת ב-`~` היא **מודאלית**: היא נכתבת רק כשהיא שונה ממה שנכתב לאחרונה (`G1~`, `X{x}~`). מילה שמסתיימת ב-`~!` נכתבת בכל פעם ונזכרת בכל זאת. שם שאינו משתנה הוא טקסט רגיל (`G81`, `mist`). מספרים מעוגלים ל-0.001 mm ונכתבים בלי אפסים מיותרים בסוף.

## מה פוסט לא יכול לעשות

הוא קובע איך המהלכים נכתבים, לא יותר. הוא לא יכול לשנות מסלול כלי, לסדר פעולות מחדש, לפצל קשת, להוסיף ציר, לדעת את מרחקי הנסיעה או הקינמטיקה של המכונה שלכם, או לבצע חשבון על קואורדינטות (אין `+`). המיקומים הסיבוביים עצמם באים מהמכונה שמתוארת בהגדרה, לא מהפוסט: פוסט יכול לשנות את הסימן שלהם או את האותיות שלהם, לא את הקינמטיקה. מחזורי חיי כלי ותת-תוכניות אינם נבנו. קובץ פוסט בסגנון `.cps` מתוכנה אחרת אי אפשר לטעון: זה פורמט אחר, פשוט יותר.
