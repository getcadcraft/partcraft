אותו מסלול כלי צריך להירשם בצורה שונה לבקרים שונים: עם מספרי שורות או בלעדיהם, `M6` או הפסקה, `G28` או `G53`, `M30` או `M2`. **פוסט** הוא הטקסט הקצר שקובע איך. שלושת הפוסטים המובנים של PartCraft (בסגנון Fanuc, GRBL ו-LinuxCNC) כתובים בפורמט הזה, ולכן פוסט משלכם יכול להתחיל כעותק של אחד מהם.

בדקו את הפלט בסימולטור של המכונה שלכם לפני חיתוך, והריצו אותו קודם באוויר, מעל חומר הגלם. הפוסטים המובנים כותבים בדיוק את מה שכתבו לפני שהפורמט הזה קיים (הבדיקות משוות את הפלט שלהם בייט אחר בייט על מאות תוכניות), אבל שום דבר כאן לא הוכח על המכונה שלכם, ופוסט ששיניתם הוא באחריותכם להוכיח.

## יצירת פוסט

בתחום הייצור, תחת **פוסט**:

- {{ui:עריכת פוסט…}} על בקר מובנה פותח **עותק משלכם** שלו. על פוסט משלכם הוא פותח את הפוסט עצמו.
- {{ui:פוסט חדש…}} מתחיל מפוסט ריק קטן שבו כל אירוע מופיע.
- {{ui:ייבוא קובץ פוסט…}} קורא קובץ טקסט `.cpost` (הקובץ שמקבלים מ-**שמירה כקובץ…** בעורך).

העורך מציג את הטקסט, שורה שאומרת אם הפוסט נקרא (ואיזו שורה שגויה), ואת ה-G-code שהפוסט כותב תוך כדי הקלדה. **תצוגה מקדימה עם** בוחר תוכנית לדוגמה קטנה שמפעילה כל אירוע, או את תוכנית החלק הזה. {{ui:שמירה}} שומר את הפוסט בקובץ החלק (עד 20 פוסטים) ובוחר אותו כבקר. הפוסטים נלווים לחלק; כדי להשתמש באחד מהם בחלק אחר, שמרו אותו כקובץ וייבאו אותו שם.

## כך נראה פוסט

```
post mymill
name My mill (.nc)
extension nc
line-numbers off
decimal-point no
canned-cycles no
modal motion G0 G1 G2 G3

on start
  comment Program {program}: {name}
  emit G21 G90 G17
end

on tool-change
  emit T{tool.number} M6
end

on rapid
  if moved
    emit G0~ X{x}~ Y{y}~ Z{z}~
  end
end
```

שורות שמתחילות ב-`//` ושורות ריקות מתעלמים מהן. בראש באות ההגדרות; לאחר מכן בלוק `on <event>` לכל אירוע, שנסגר ב-`end`. אירוע שתשמיטו לא כותב דבר.

| הגדרה | משמעות |
|---|---|
| `post <id>` | מזהה הפוסט: אותיות, ספרות, `-` ו-`_` |
| `name <text>` | מה שרשימת הבקרים מציגה |
| `extension <ext>` | סיומת הקובץ: nc, ngc, tap … |
| `line-numbers 10` / `off` | `N10`, `N20` … בכל שורת `emit`, או ללא |
| `decimal-point yes` / `no` | `10.` במקום `10` (הערות לעולם אינן נושאות נקודה) |
| `canned-cycles yes` / `no` | `no`: חורים נכתבים כמהלכי G0/G1 שהם מייצגים |
| `modal <group> <words>` | מילים של קבוצה (`modal motion G0 G1 G2 G3`) שנכתבות רק כשהן משתנות |

## אירועים

הם רצים בסדר הזה לתוכנית: `start`; ואז לכל פעולה `operation`, `tool-change` (כשהכלי משתנה), `spindle` (כשהמהירות משתנה), `approach` (המהלך אל הנקודה הראשונה, לפני ה-`rapid` הראשון), `coolant-on`, ואז המהלכים שלה כ-`rapid`, `feed` ו-`arc`, וכל מחזור קבוע כ-`cycle-start`, לכל חור `cycle-hole` אחד, ו-`cycle-end`; לבסוף `end`.

כל אירוע יכול להשתמש במשתני סוג המהלך שלו, הכתובים `{name}`: התוכנית (`name`, `program`, `setup.axis`, `setup.origin`, `setup.coolant`), חומר הגלם (`stock.kind`, `stock.d`, `stock.sx`, `stock.sy`, `stock.sz`, `stock.minx` … `stock.maxz`), הכלי (`tool.number`, `tool.desc`, `tool.kind`, `tool.d`, `tool.flutes`, `tool.fluteLen`), הפעולה (`op.name`, `op.type`), `rpm`, נקודת המהלך (`x`, `y`, `z`, `f`, וגם `moved`: אמת כשציר השתנה), קשתות (`arc.g` 2 או 3, `arc.i`, `arc.j`, `arc.cx`, `arc.cy`) וחורים (`hole.x`, `hole.y`, `hole.z`, `hole.r`, `hole.q`, `hole.return`, `hole.first`, `cycle.kind`, `cycle.init`, `feed`). הרשימה **אירועים ומשתנים** בעורך מראה איזה אירוע רואה מה. מצב שאפשר לקרוא ולהגדיר: `cool`, `offset`, וגם `at.x`, `at.y`, `at.z`, `at.f` (הערכים האחרונים שנכתבו).

## משפטים

| משפט | מה הוא עושה |
|---|---|
| `raw TEXT` | שורה בדיוק כפי שהוקלדה (ללא מספר שורה) |
| `comment TEXT` | `(TEXT)` ללא תווים שאינם ASCII וללא סוגריים |
| `emit WORD WORD …` | שורת מילים; מילים שיוצאות ריקות מושמטות; אין מילים, אין שורה |
| `word WORD …` | הוספת מילים לשורה שנבנית; `emit` חשוף מסיים אותה |
| `if EXPR` … `else` … `end` | תנאים: `a == b`, `a != b`, `not a`, `a and b`, `a or b`, `a??b` (a, אחרת b) |
| `for tool in tools` … `end` | פעם לכל כלי שהתוכנית משתמשת בו |
| `set NAME EXPR` | זכירת ערך (`set offset tool.number`) |
| `reset NAME …` | שכחה של מילים מודאליות (קבוצה, אות כתובת כמו `Z`, או `at.z`) |
| `do rapid X Y Z` | הרצת האירוע `rapid` לנקודה |

מילה היא טקסט מוקלד עם חורים מסוג `{variable|filter}`. המסננים הם `upper`, `lower`, `pad:N` (מילוי באפסים), `cut:N` (N התווים הראשונים), `safe` (ASCII בטוח להערות) ו-`int`. מילה שמסתיימת ב-`~` היא **מודאלית**: היא נכתבת רק כשהיא שונה ממה שנכתב לאחרונה (`G1~`, `X{x}~`). מילה שמסתיימת ב-`~!` נכתבת בכל פעם ונשמרת בזיכרון. שם שאינו משתנה הוא טקסט רגיל (`G81`, `mist`). מספרים מעוגלים ל-0.001 mm ונכתבים בלי אפסים מיותרים בסוף.

## מה פוסט אינו יכול לעשות

הוא קובע רק איך נכתבים המהלכים, לא יותר. הוא לא יכול לשנות מסלול כלי, לסדר פעולות, לפצל קשת, להוסיף ציר, לדעת את מרחב התנועה או הקינמטיקה של המכונה שלכם, או לבצע חשבון על קואורדינטות (אין `+`). מדידה (probing), מחזורי חיי כלי ותת-תוכנית, פלט של הציר הרביעי והחמישי, וקודי מחרטה לא נבנו. קובץ פוסט בסגנון `.cps` מתוכנה אחרת אי אפשר לטעון: זהו פורמט אחר, פשוט יותר.
