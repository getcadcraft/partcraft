مدل‌سازی دقیق بیشتر به نظم وابسته است تا به دکمه‌ها. قطعه‌ای که به‌صورت متن نوشته شود می‌تواند خوانده، بازبینی، سطر به سطر مقایسه و با یک اسکریپت دوباره ساخته شود. PartCraft در هر دو جهت کار می‌کند: هر قطعه‌ای می‌تواند به‌صورت اسکریپت نوشته شود، و یک اسکریپت قطعه را می‌سازد.

## در برنامه

در زبانه {{ui:پارامترها}}، زیر **اسکریپت**:

- {{ui:ذخیره به‌عنوان اسکریپت}} قطعه باز را به‌صورت `<name>.pcscript` دانلود می‌کند.
- {{ui:باز کردن اسکریپت}} از یک فایل `.pcscript` قطعه می‌سازد. خطا همراه شماره سطرش گزارش می‌شود و چیزی جایگزین نمی‌شود.

## قالب اسکریپت

```
pcscript 1
part "Bracket"
  resolution 64

param width = 120
  note Plate width
param thick = 8
param bolt = 8.5
param margin = bolt * 1.5

sketch Plate
  on top
  point a 0, 0
  point b 120, 0
  point c 120, 60
  point d 0, 60
  line bottom a b
  line right b c
  line top c d
  line left d a
  coincident a O
  horizontal bottom
  horizontal top
  vertical left
  vertical right
  distance bottom = width
  distance left 60

extrude Base
  sketch Plate
  depth = thick

sketch HoleCentres
  on face Base end
  point h1 12, 12
  hdistance O h1 = margin
  vdistance O h1 = margin

hole Bolts
  sketch HoleCentres
  d = bolt
  through
```

قواعد:

- سطری که از لبه چپ شروع شود یک دستور را آغاز می‌کند: `pcscript`، `part`، `param`، یک نوع فیچر (`sketch`، `extrude`، `revolve`، `hole`، `lpattern`، `cpattern`، `mirror`، `fillet`، `chamfer`، `shell`، `import` و انواع جدیدتر) که نامش بعد از آن می‌آید، یا `rollback <feature>`.
- سطرهای تورفته تنظیمات دستور بالای خودشان هستند. تنظیمی که تنهایی بیاید (`through`، `reverse`، `suppressed`) یعنی بله.
- تنظیم عددی یک عدد است، یا `=` و یک عبارت که معادله می‌سازد: `depth = thick`.
- در یک اسکچ: `on` صفحه را نام می‌برد (`front`، `top`، `right`، `face Base end`، `face Revolve1 side l3`)؛ هندسه به‌صورت `point <name> x, y`، `line <name> <point> <point>`، `circle <name> <centre> <radius>`، `arc <name> <centre> <start> <end>` (خلاف جهت عقربه‌های ساعت) یا `spline <name> fit|control <points>` است؛ روابط نوع خودشان و نام‌هایی هستند که به هم وصل می‌کنند (`O` مبدأ است)؛ یک اندازه با مقدارش یا با `= expression` تمام می‌شود.
- تنظیمات اختیاری یک خط هندسه یا رابطه در پایان داخل کروشه و جداشده با `;` می‌آیند: `[construction]`، `[side -1; label 5, 3]`.
- `#` یک توضیح را شروع می‌کند (در ابتدای سطر یا بعد از یک فاصله). نام‌هایی که فاصله دارند داخل "گیومه دوتایی" نوشته می‌شوند.
- شناسه فیچرها از f1 به ترتیب نوشته شدن شمارش می‌شود. ارجاع لبه و وجه از آن‌ها استفاده می‌کند، برای مثال `edge f2.side:l3 f2.end [at 50, 0, 10]`.
- تنظیم‌هایی که قالب برای‌شان واژه‌ای ندارد با `json` و یک مقدار نوشته می‌شوند؛ همان‌طور که هستند خوانده می‌شوند.

اسکریپتی که از برنامه ذخیره شود همه تنظیمات را دارد، پس به همان قطعه باز می‌شود. جسم STEP واردشده از برنامه داخل اسکریپت نوشته می‌شود، و از خط فرمان به‌صورت یک فایل `.step` جدا نوشته می‌شود که نامش با `step-file` مشخص می‌شود.

## ابزار خط فرمان

این ابزار روی رایانه‌ای با Node.js 24 و از یک نسخه کپی‌شده از سورس CadCraft اجرا می‌شود: `node tools/partcraft-cli/partcraft.mjs <command>`. این یک ابزار توسعه‌دهنده است و از همان ماژول‌های برنامه استفاده می‌کند. قطعه‌ها فایل‌های `.partcraft.json` یا اسکریپت‌های `.pcscript` هستند.

| دستور | کار آن |
|---|---|
| `info <part>` | فیچرها، پارامترها، نوار بازگشت، حجم و اندازه جسم ساخته‌شده |
| `params <part>` | هر پارامتر و معادله همراه با مقدارش |
| `set <part> width=150 Base.depth==thick` | رو به جلو: تغییر پارامترها، پیوند عددها (`==` یا یک عبارت)، تنظیم عددهای ساده |
| `drive <part> Base.depth=12` | رو به عقب: حل پارامتری که پشت یک عدد هدایت‌شده است (`--prefer width` یکی را انتخاب می‌کند) |
| `build <part> --out x.step` | می‌نویسد `.step`، `.stl`، `.3mf`، `.json`، `.pcscript` یا یک ماکرو (`.swb`) |
| `build <part> --table sizes.csv --out-dir sizes` | یک فایل برای هر ردیف جدول طراحی |
| `variants <part> --out-dir d` یا `--zip f.zip` | هر پیکربندی به‌صورت STEP، IFC، DWG و پیش‌نمایش، یک جدول نوع‌ها و یک مورد کتابخانه (`--only "A,B"`، `--formats step,ifc,dwg,preview`، `--no-item`)؛ [ساختن بسته نوع‌ها](topic:variant-pack) را ببینید |
| `script <in.pcscript> -o part.json` | از اسکریپت به قطعه |
| `to-script <part> -o part.pcscript` | از قطعه به اسکریپت |
| `rollback <part> [<feature>]`، `forward <part> [--end]` | جابه‌جایی نوار بازگشت در فایل |
| `check <part> [--strict]` | بررسی نظم (در ادامه) |

`build` همچنین `--set name=value` (فقط برای همین ساخت) و `--upto <feature>` را می‌پذیرد. هر دستور `--json` را می‌پذیرد. کدهای خروج: 0 یعنی خوب، 1 یعنی مشکلی پیدا شد، 2 یعنی دستور اشتباه تایپ شده است. یک اسکریپت هرگز در جای خودش بازنویسی نمی‌شود: برای ذخیره یک نسخه تغییریافته `-o` بدهید.

## بررسی

`check` گزارش می‌دهد چه چیزی تغییر دادن قطعه را بعداً دشوار می‌کند:

| یافته | به حساب می‌آید به‌عنوان |
|---|---|
| اسکچی که بیش از حد تعریف شده است (روابط متناقض یا تکراری) | خطا |
| فیچری که ساخته نمی‌شود | خطا |
| پارامتر یا معادله‌ای با خطا، یا پارامترهایی که به هم وابسته‌اند | خطا |
| اسکچی که کم تعریف شده است، همراه با درجات آزادی‌اش | هشدار |
| عددهایی که مستقیم در فیچرها و اندازه‌ها تایپ شده و هیچ پارامتری هدایتشان نمی‌کند | هشدار |
| پارامتری که هیچ چیزی از آن استفاده نمی‌کند | هشدار |
| فیچر پنهان‌شده؛ نوار بازگشت در انتها نیست | هشدار |

`--strict` هر هشداری را خطا می‌کند، تا یک اسکریپت ساخت بتواند قطعه‌ای را که کاملاً هدایت نشده است رد کند.

:::note
خروجی ماکرو `.swb` برای نرم‌افزار مدل‌سازی قطعه‌ای است که بیشتر کارگاه‌ها استفاده می‌کنند: وقتی داخل آن برنامه اجرا شود، قطعه را آن‌جا می‌سازد. این ماکرو در آن برنامه این‌جا اجرا نشده است (روی سرورهای ما در دسترس نیست)، پس آن را آزمایش‌نشده در نظر بگیرید.
:::
